How to Create a User, Group and Policy for Terraform in OCI

By Sunke Nithin · April 11, 2025   CLOUDOCITerraform

Before Terraform can build anything in OCI it needs an identity with the right permissions. A dedicated user in a dedicated group, granted access through a policy, keeps Terraform's rights limited and its actions easy to audit. Then we configure authentication and check a first Terraform configuration.

1Create a Group

  1. OCI Console → Identity & Security → Domains → your identity domain (usually Default or OracleIdentityCloudService) → Groups.
  2. Create group: name terraform-admins, description Group for users managing infrastructure via Terraform.

2Create a User

  1. Same domain → Users → Create user, e.g. terraform-user. An email address is required.
  2. Open the user → Groups → Assign user to groups → terraform-admins.

3Create a Policy

Identity & Security → Policies, choose the compartment, then Create Policy:

  • Name: terraform-policy
  • Compartment: the one Terraform will manage (nithin.sunke here)
  • Statement:
POLICY
Allow group terraform-admins to manage all-resources in compartment nithin.sunke

That's fine for a LAB. For anything shared, grant only the resource families Terraform actually manages:

POLICY
Allow group terraform-admins to manage virtual-network-family in compartment nithin.sunke
Allow group terraform-admins to manage instance-family        in compartment nithin.sunke
Allow group terraform-admins to manage volume-family          in compartment nithin.sunke
Allow group terraform-admins to read   all-resources          in compartment nithin.sunke

4Configure Authentication

Two options:

A. API signing key — for the dedicated user (recommended). Log in as (or administer) terraform-user and add an API key; the provider then uses that profile with no extra settings.

BASH
oci setup config          # creates ~/.oci/config and an API key pair for the user
# upload ~/.oci/oci_api_key_public.pem: Identity → Users → terraform-user → API keys → Add API key

B. Session token — quick tests with your own console login. A browser window opens to sign in; the token lasts one hour.

BASH
oci session authenticate --region me-jeddah-1 --profile-name learn-terraform
oci session refresh --profile learn-terraform     # within the token's 1-hour lifetime
A session token authenticates you, not terraform-user — the policy above only applies if you sign in as a member of terraform-admins.

5Write a First Configuration

Each Terraform configuration lives in its own directory (sample2 here) — create main.tf:

HCL
terraform {
  required_providers {
    oci = {
      source = "oracle/oci"
    }
  }
}

provider "oci" {
  region              = "me-jeddah-1"
  auth                = "SecurityToken"      # only for 'oci session authenticate' profiles
  config_file_profile = "learn-terraform"
}
With a session-token profile the provider needs auth = "SecurityToken" — my screenshot is missing that line, and plan fails to authenticate without it. With an API-key profile (option A), leave auth out.
