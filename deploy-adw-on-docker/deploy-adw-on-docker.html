Run Oracle Autonomous Database Free (ADW/ATP) on Docker

By Sunke Nithin · August 8, 2025   DockerOracleADB

Oracle publishes Autonomous Database Free as a container image: a local ADB 23ai with ORDS, APEX, Database Actions and the MongoDB API, behaving like the cloud service. It's ideal for development and learning without an OCI account. Here I run it as an ADW (data warehouse) instance with Docker.

Prerequisites

  • Docker (or Podman) on Linux x86-64 — or Windows with WSL2
  • At least 4 CPUs, 8 GB RAM and about 30 GB of disk (see moving Docker storage to a bigger disk)
  • Internet access to the GitHub Container Registry

1Pull the Image

BASH
docker pull ghcr.io/oracle/adb-free:latest-23ai
docker image ls ghcr.io/oracle/adb-free
REPOSITORY                TAG           IMAGE ID       CREATED       SIZE
ghcr.io/oracle/adb-free   latest-23ai   73b91e2be6bb   4 weeks ago   4.97GB

2Start the Container — Docker Compose

DOCKER-COMPOSE.YML
services:
  adb-free:
    image: ghcr.io/oracle/adb-free:latest-23ai
    container_name: adb-free
    hostname: adb-free
    ports:
      - "1521:1521"     # TLS
      - "1522:1522"     # mTLS
      - "8443:8443"     # ORDS / APEX / Database Actions
      - "27017:27017"   # MongoDB API
    environment:
      WORKLOAD_TYPE: "ADW"               # or ATP
      ADMIN_PASSWORD: "<admin-password>"
      WALLET_PASSWORD: "<wallet-password>"
    cap_add:
      - SYS_ADMIN
    devices:
      - "/dev/fuse"
    volumes:
      - adb_container_volume:/u01/data
    restart: unless-stopped

volumes:
  adb_container_volume:
BASH
docker compose up -d && docker compose logs -f

Or with plain docker run:

BASH
docker run -d --name adb-free --hostname adb-free \
  -p 1521:1521 -p 1522:1522 -p 8443:8443 -p 27017:27017 \
  -e WORKLOAD_TYPE='ADW' \
  -e ADMIN_PASSWORD='<admin-password>' \
  -e WALLET_PASSWORD='<wallet-password>' \
  --cap-add SYS_ADMIN --device /dev/fuse \
  --volume adb_container_volume:/u01/data \
  ghcr.io/oracle/adb-free:latest-23ai

docker logs -f adb-free        # wait until the database reports it is ready

The container needs SYS_ADMIN and /dev/fuse for its DBFS-based features. Passwords must meet ADB's rules: 12–30 characters with upper case, lower case and a digit.

Troubleshooting: Permission Denied on First Start

LOG
Downloading MY_ATP.pdb..
PermissionError: [Errno 13] Permission denied: '/u01/data/MYATP.pdb.partial'

The volume isn't writable by the container's oracle user (UID 54321). Fix the ownership rather than opening it to everyone with chmod 777:

BASH
docker compose down
VOL=$(docker volume inspect -f '{{.Mountpoint}}' adb_adb_container_volume)
sudo chown -R 54321:54321 "$VOL"      # 54321 = oracle user inside the container
# SELinux hosts: also  sudo chcon -Rt container_file_t "$VOL"
docker compose up -d

Compose prefixes the volume name with the project (folder) name — adb_adb_container_volume here.

3Connect

Copy the TLS wallet out of the container and use one of the predefined service aliases:

BASH
docker cp adb-free:/u01/app/oracle/wallets/tls_wallet ./tls_wallet
export TNS_ADMIN=$PWD/tls_wallet
sqlplus admin@myadw_low_tls       # TLS: no client wallet password needed
