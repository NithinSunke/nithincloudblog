Three Ways to Clone a Linux VM in OCI

By Sunke Nithin · January 9, 2025   CLOUDOCI

OCI has no single "clone VM" button, but there are three good ways to make a copy of a compute instance: clone its volumes, back up and restore them, or create a custom image. To show the copy really is a copy, I first put a small web page on the source VM, demo-vm.

MethodBest forSpeed
Volume (group) cloneA quick copy in the same regionMinutes; the clone is usable almost at once
Backup + restoreA copy from a point in time, kept in Object Storage; can be copied to other regionsSlower; backup must finish first
Custom imageA template for many identical VMs; can be exported or sharedInstance goes offline while the image is taken

The Source VM

On demo-vm (Oracle Linux 8) install Apache, open the port in the OS firewall, and write a page that names the server:

BASH
sudo dnf install -y httpd
sudo systemctl enable --now httpd

sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload

echo '<h1>this server is demo-vm</h1>' | sudo tee /var/www/html/index.html

Allow port 80 in the subnet's security list — only from my own public IP, not the whole internet:

For a clean, consistent copy, stop the instance first (clones of a running VM are crash-consistent, like pulling the power plug):

Method 1: Clone a Volume Group

A volume group bundles the boot volume and any block volumes so they are cloned or backed up at the same instant. Storage → Volume Groups → Create volume group, add the boot volume:

Open the group → Volume group clones → Create volume group clone:

Open the cloned boot volume and click Create instance. The image is the cloned boot volume; pick shape, subnet and SSH key as usual:

Browsing to the new VM shows the page from the source — it's a full copy, hostname included:

BASH
# inside the new VM
sudo hostnamectl set-hostname demo-clone-vm
ip -br addr        # new private IP from the subnet
A boot volume can only be attached to one instance at a time, so a clone is the only way to start a second VM from it. If the source used a reserved public IP, the clone gets a new one.

Method 2: Back Up and Restore

Volume group → Volume group backups → Create (full backup); it is stored in Object Storage:

Open the backup → Restore volume group, then create an instance from the restored boot volume exactly as in method 1:

Method 3: Custom Image

Instance → More actions → Create custom image. The instance goes offline for a few minutes while the image is taken:

When it's Available, create instances from it with Change image → My images → Custom images:

From the CLI

BASH
# clone a boot volume with the OCI CLI
oci bv boot-volume create --source-boot-volume-id <boot-volume-ocid> \
   --availability-domain <AD> --display-name demo-vm-clone-bv

# custom image from an instance
oci compute image create --instance-id <instance-ocid> \
   --compartment-id <compartment-ocid> --display-name web-server

Clean up the clones, backups and images you don't need — they all cost storage. Related: Create an instance with Terraform.
