Step-by-Step Guide to Deploy Oracle Autonomous Data Warehouse (ADW) on OCI

By Sunke Nithin · April 4, 2025   CLOUDOracleOCIADB

Oracle Autonomous Data Warehouse (ADW) is a fully managed database tuned for analytics — reporting, dashboards and BI — that patches, backs up and tunes itself. This post walks through provisioning one in the OCI Console, explaining each choice along the way.

basic info→workload type→configure→backups→admin password→network→license→create

1Start the Create Wizard

In the OCI Console go to Oracle Database → Autonomous Database, pick your compartment and click Create Autonomous Database. Give it a display name and a database name — letters and numbers only, starting with a letter, up to 30 characters.

2Choose the Workload Type

WorkloadBuilt forTypical use
Data WarehouseAnalytics: complex queries, large scans, aggregations and joinsBI tools (Oracle Analytics Cloud, Tableau), data marts, ELT pipelines, data lake queries
Transaction ProcessingOLTP: many short, concurrent reads and writesWeb and mobile apps, ERP/CRM, e-commerce
JSONDocument-centric apps with JSON storage and MongoDB-compatible APIsFlexible-schema apps, mobile back ends
APEXLow-code apps built with Oracle APEXInternal business apps, forms, dashboards

Pick Data Warehouse and the Serverless deployment type (Dedicated runs on your own Exadata infrastructure).

3Configure the Database

  • Database version: 19c here; newer versions are offered as they become available.
  • ECPU count: compute is sized in ECPUs (2 is the minimum).
  • Storage: 1 TB here.
  • Auto scaling: compute auto scaling lets the database use up to 3× the ECPUs when busy; storage auto scaling lets it grow beyond the reserved storage. You pay for what's used. See Scale Your Autonomous Database.
  • Developer: a cheaper, fixed-size option for development and testing.

4Backup Retention

Automatic backups are managed by Oracle and kept for 60 days by default; you can set anything from 1 to 60 days. Backup storage is billed separately from database storage, so a shorter period saves money on non-production databases.

5Set the ADMIN Password

The administrator user is always ADMIN. The password needs 12–30 characters with upper case, lower case and a number, and can't contain the username or a double quote.

6Choose Network Access

OptionWho can connectGood for
Secure access from everywhereAnyone on the internet with valid credentials (and the wallet, if mTLS is on)Quick tests, PoCs, labs
Secure access from allowed IPs and VCNs onlyPublic endpoint, but restricted by an access control list of IP addresses, CIDR ranges and VCNsDevelopers connecting from known locations
Private endpoint access onlyOnly from inside a chosen VCN subnet — no public IP; controlled by NSGs and security listsProduction and compliance-sensitive workloads

Require mutual TLS (mTLS) means clients need the downloaded wallet to connect. Turn it off (with an ACL or private endpoint in place) to allow plain TLS connections without a wallet.

7License and Contacts

Choose License included, or Bring your own license (BYOL) if you have Oracle Database licences to reuse — it's cheaper. Add a contact email to receive maintenance and operational notices.

8Create

Click Create Autonomous Database. Provisioning typically takes just a few minutes, and the badge turns green when it's Available:

From here, use Database connection to download the wallet, Database actions to open SQL worksheet and other tools in the browser, and Manage resource allocation to scale.

Wrapping Up

ADW goes from nothing to a running, backed-up, patched data warehouse in a few minutes, without DBA work on the infrastructure. Next steps: load data from Object Storage and scale it to your workload.
