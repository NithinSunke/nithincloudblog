Multipath Configuration in Linux (OEL8)

By Sunke Nithin · April 8, 2025   LinuxLinux

With SAN storage, multipath I/O lets a server reach the same LUN over several physical paths. If a cable, HBA or switch port fails, I/O carries on over the remaining paths. This post configures device-mapper multipath on Oracle Linux 8 and gives the shared LUNs stable names (ocr, data, fra) for Oracle ASM.

Why Multipath?

  • Redundancy — path failover without an outage
  • Load balancing across paths
  • Stable device names that don't change between reboots (/dev/sdd may become /dev/sdf; /dev/mapper/data won't)

Prerequisites

  • Oracle Linux 8 with root access
  • SAN storage presented over iSCSI or Fibre Channel
  • Ideally two or more paths to each LUN. My lab has only one path per LUN, which is enough to set up multipath and get the aliases, but gives no actual redundancy.

1Install and Enable

BASH
dnf install -y device-mapper-multipath

# create /etc/multipath.conf with sensible defaults and enable the service
mpathconf --enable --with_multipathd y --user_friendly_names y --find_multipaths y
On OL7/8 use mpathconf to create the config file. The old step of copying /usr/share/doc/device-mapper-multipath-0.4.9/multipath.conf only applied to OL6 — that path doesn't exist on OL8.

The WWID is the long identifier after scsi-; for /dev/sdd it's 14f504e46494c450066764448386b2d39584f4b2d6e6d6f69.

3Edit /etc/multipath.conf

Blacklist everything, then allow only the SAN LUNs and give each an alias. Edit the existing sections rather than appending a second defaults block — that's what caused the "duplicate keyword: defaults" warning in my original run:

CONF
defaults {
    user_friendly_names yes
    find_multipaths     yes
    polling_interval    10
    path_selector       "round-robin 0"
    path_grouping_policy multibus
    path_checker        tur
    failback            immediate
    no_path_retry       fail
}

blacklist {
    wwid ".*"
}

blacklist_exceptions {
    wwid "14f504e46494c450036386a5368642d543257722d46525562"
    wwid "14f504e46494c450066764448386b2d39584f4b2d6e6d6f69"
    wwid "14f504e46494c450049774e6875512d326743342d76397558"
}

multipaths {
    multipath {
        wwid  14f504e46494c450036386a5368642d543257722d46525562
        alias ocr
    }
    multipath {
        wwid  14f504e46494c450066764448386b2d39584f4b2d6e6d6f69
        alias data
    }
    multipath {
        wwid  14f504e46494c450049774e6875512d326743342d76397558
        alias fra
    }
}
Updated for OL8. My original config came from OL6 and used udev_dir, getuid_callout and path_checker readsector0. All three are obsolete on OL7/8 (the WWID comes from udev automatically, and tur is the standard checker). For production, check your storage vendor's recommended devices section — many arrays want prio alua and path_grouping_policy group_by_prio.

4Start the Daemon and Load the Maps

BASH
systemctl enable --now multipathd
multipath -r          # reload maps after editing multipath.conf
