Point-in-Time Recovery with RMAN

By Sunke Nithin · July 4, 2019   DatabaseOracle

A DBA drops a tablespace the application needs. The fix is to take the whole database back to a moment just before the mistake — database point-in-time recovery (DBPITR) with RMAN: restore the control file and data files from a backup, roll forward with archived logs to the chosen time, and open with RESETLOGS.

Everything after the recovery time is lost — not just the dropped tablespace but every other change in the database. Look at the alternatives at the end first; one of them may get the data back without rewinding everything.

The Scenario

SQL
SQL> drop tablespace test including contents and datafiles;

Tablespace dropped.

The DBA realises the mistake straight away.

1Find the Exact Time from the Alert Log

ALERT LOG
Sun Feb  4 10:59:43 2007
drop tablespace test including contents and datafiles
Sun Feb  4 10:59:47 2007
Completed: drop tablespace test including contents and datafiles

The drop started at 10:59:43, so we'll recover to 10:58:00 — safely before it. On recent versions, adrci shows the alert log, and with the SCN you can be exact: SET UNTIL SCN.

2Shut Down the Database

SQL
shutdown abort

Stop it as soon as possible so users don't add more changes that will be thrown away.

3Restore and Recover to the Point in Time

BASH
rman target / catalog rman@risl64
RMAN
RUN {
  STARTUP NOMOUNT;
  SET UNTIL TIME "TO_DATE('04-02-07 10:58:00', 'DD-MM-YY HH24:MI:SS')";
  RESTORE CONTROLFILE;
  ALTER DATABASE MOUNT;
  RESTORE DATABASE;
  RECOVER DATABASE;
  ALTER DATABASE OPEN RESETLOGS;
}
StepWhy
SET UNTIL TIMEEvery following command in the block works to this time
RESTORE CONTROLFILEThe current control file no longer knows about the dropped tablespace; an older one from before the drop does. Without a recovery catalog, use RESTORE CONTROLFILE FROM AUTOBACKUP (set the DBID first)
RESTORE DATABASERestores every data file — including test.dbf — from the latest backup before the target time
RECOVER DATABASEApplies archived and online redo up to 10:58:00, then stops
OPEN RESETLOGSOpens the database as a new incarnation

5Take a New Backup

After OPEN RESETLOGS the database is a new incarnation. Backups from before still work for recovering to earlier points, but take a fresh full backup now as the starting point going forward:

RMAN
BACKUP DATABASE PLUS ARCHIVELOG;

Before You Rewind the Whole Database

OptionWhen it fits
Flashback DatabaseIf flashback logging is on, FLASHBACK DATABASE TO TIMESTAMP … rewinds in minutes with no restore. Still loses all later changes.
Tablespace PITR (RECOVER TABLESPACE … UNTIL TIME … AUXILIARY DESTINATION …)Recovers just the tablespace using an auxiliary instance; the rest of the database keeps its changes. From 11.2 it works for a dropped tablespace too.
Table recovery (RECOVER TABLE … UNTIL TIME …, 12c+)When only specific tables were lost; RMAN restores them through an auxiliary instance and imports them.
Restore to another serverRestore the backup elsewhere to the earlier time and export what you need, leaving production untouched.
