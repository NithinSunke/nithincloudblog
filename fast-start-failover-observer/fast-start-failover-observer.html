Configuring the Fast-Start Failover Observer for Oracle Data Guard

By Sunke Nithin · August 8, 2022   DatabaseOracleData Guard

Fast-Start Failover (FSFO) turns a Data Guard standby into an automatic one: if the primary disappears, the standby takes over without a DBA. The decision is made by the observer, a DGMGRL process on a third server. Here I set up the observer with a wallet so it runs unattended in the background, enable FSFO, and test a failover and automatic reinstatement.

LAB Setup

RoleHostDatabase
Primaryorstdbdvl01NPGR (19c)
Physical standbyorstsbdvl01NPGRSB (19c)
Observeroem12.2 client / Oracle home

The observer should be on a separate host — ideally in a third location — so that losing one site doesn't take the observer with it.

Prerequisites

  • A working Data Guard configuration managed by the broker (dg_broker_start=TRUE), with standby redo logs.
  • Flashback Database on both databases — required for the failed primary to be reinstated automatically.
  • Oracle Net connectivity from the observer host to both databases.
SQL
-- on primary and standby
select flashback_on, force_logging, protection_mode from v$database;
show parameter dg_broker_start

-- if needed (primary, and standby with MRP stopped)
alter database flashback on;

1Oracle Net Entries on the Observer

Add both databases to $ORACLE_HOME/network/admin/tnsnames.ora on the observer host:

TNSNAMES.ORA
NPGR =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = orstdbdvl01.snvcloud.com)(PORT = 1521))
    (CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = NPGR))
  )

NPGRSB =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = orstsbdvl01.snvcloud.com)(PORT = 1521))
    (CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = NPGRSB))
  )

2Create a Wallet for Passwordless Login

Since 12.2 the observer can run in the background, which needs credentials it can use on its own — a secure external password store (wallet). As oracle on the observer host, add to sqlnet.ora:

SQLNET.ORA
WALLET_LOCATION =
  (SOURCE =
    (METHOD = FILE)
    (METHOD_DATA = (DIRECTORY = /h01/oracle/admin/fsfo/wallet))
  )
SQLNET.WALLET_OVERRIDE = TRUE
BASH
mkdir -p /h01/oracle/admin/fsfo/wallet
cd /h01/oracle/admin/fsfo/wallet
chmod 700 .

mkstore -wrl . -create                     # prompts for a wallet password
ls
# cwallet.sso  ewallet.p12   (cwallet.sso = auto-login, no password needed at runtime)

Add a SYS credential for each database, using the TNS alias as the key:

BASH
# one entry per database; prompts for the SYS password, then the wallet password
mkstore -wrl . -createCredential npgr   sys
mkstore -wrl . -createCredential npgrsb sys

mkstore -wrl . -listCredential
List credential (index: connect_string username)
2: npgrsb sys
1: npgr sys
The auto-login wallet holds SYS credentials. Keep the directory owned by oracle with mode 700, and the observer host as tightly secured as the database servers.

3Test the Connections

BASH
sqlplus /@npgr as sysdba        # must log in without a password prompt
sqlplus /@npgrsb as sysdba

Both should connect straight away. If a password is asked for, check the alias names in the wallet and WALLET_LOCATION.

4Set FSFO Properties and Enable It

DGMGRL
dgmgrl /@npgr

DGMGRL> show configuration;
DGMGRL> edit database npgr   set property FastStartFailoverTarget='npgrsb';
DGMGRL> edit database npgrsb set property FastStartFailoverTarget='npgr';
DGMGRL> edit configuration set property FastStartFailoverThreshold=60;      -- seconds
DGMGRL> edit configuration set property FastStartFailoverLagLimit=30;       -- MaxPerformance only
DGMGRL> enable fast_start failover;
OUTPUT · SHOW CONFIGURATION
Configuration - my_dg_config

  Protection Mode: MaxPerformance
  Members:
  npgr   - Primary database
    npgrsb - (*) Physical standby database

Fast-Start Failover: ENABLED

Configuration Status:
SUCCESS   (status updated 9 seconds ago)

In MaxPerformance mode FSFO only fails over if the standby is within FastStartFailoverLagLimit seconds of the primary, which bounds data loss. In MaxAvailability it guarantees zero data loss.

5Start the Observer

Enabling FSFO is not enough — nothing fails over until an observer is running:

DGMGRL
DGMGRL> start observer observer1 in background
         file is '/h01/oracle/admin/fsfo/fsfo.dat'
         logfile is '/h01/oracle/admin/fsfo/fsfo.log'
         connect identifier is npgr;
Submitted command "START OBSERVER" using connect identifier "npgr"

DGMGRL> show observer;

Configuration - my_dg_config
  Primary:            npgr
  Target:             npgrsb

Observer "observer1"(12.2.0.1.0) - Master
  Host Name:                    oem.snvcloud.com
  Last Ping to Primary:         0 seconds ago
  Last Ping to Target:          1 second ago

show configuration now shows Fast-Start Failover: Enabled in Potential Data Loss Mode (MaxPerformance) or Zero Data Loss Mode (MaxAvailability), with the observer listed.

6Test: Crash the Primary

SHUTDOWN ABORT on the primary triggers FSFO (a normal or immediate shutdown does not):

SQL
SQL> shutdown abort
ORACLE instance shut down.

Watch the observer log (tail -f /h01/oracle/admin/fsfo/fsfo.log):

FSFO.LOG · ABRIDGED
[W000 08/07 23:11:16.92] Primary database cannot be reached.
[W000 08/07 23:11:16.92] Fast-Start Failover threshold has not exceeded. Retry for the next 60 seconds
[W000 08/07 23:12:16.96] Fast-Start Failover threshold has expired.
[W000 08/07 23:12:16.96] Making a last connection attempt to primary database before proceeding with Fast-Start Failover.
[W000 08/07 23:12:16.97] Check if the standby is ready for failover.
[S002 08/07 23:12:16.99] Fast-Start Failover started...
Initiating Fast-Start Failover to database "npgrsb"...
Performing failover NOW, please wait...
Failover succeeded, new primary is "npgrsb"
[S002 08/07 23:12:34.42] Fast-Start Failover finished...
[W000 08/07 23:12:34.46] Primary database has changed to npgrsb.

After the 60-second threshold the observer fails over to npgrsb — about 18 seconds for the failover itself.

7Automatic Reinstatement

Start the old primary in mount mode. The observer notices, and reinstates it as a standby using Flashback Database:

SQL
-- on the old primary host
SQL> startup mount
Database mounted.
FSFO.LOG · ABRIDGED
[W000 08/07 23:14:09.57] Connection to the new standby restored!
[W000 08/07 23:14:43.84] New primary is now ready to reinstate.
[W000 08/07 23:14:44.84] Issuing REINSTATE command.
Reinstating database "npgr", please wait...
Reinstatement of database "npgr" succeeded
[W000 08/07 23:15:27.50] Successfully reinstated database npgr.
DGMGRL
DGMGRL> show configuration;          -- npgrsb primary, npgr standby, SUCCESS
DGMGRL> switchover to npgr;          -- optional: return to the original roles
