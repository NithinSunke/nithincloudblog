Step by Step: Multiplexing the Control File of an Oracle Database

By Sunke Nithin · September 9, 2019   DatabaseOracle

The control file records the structure of the database — its data files, redo logs and checkpoints — and the database can't mount without it. Keeping two or more identical copies on different disks (multiplexing) means that if one is lost or corrupted, recovery is just copying a surviving copy back. Here's how to add a second control file to a database that has only one.

check→update control_files→shut down→copy→start up→verify

1Check the Database

SQL
select name, open_mode from v$database;

2List the Current Control Files

SQL
show parameter control_files

The database SNVDEV has just one control file. We'll add a second copy on a different file system, /u02.

3Create the New Directory

BASH
mkdir -p /u02/oracle/controlfile/snvdev

In real life, put each copy on a separate physical disk so one disk failure can't take out both.

4Add the New Copy to control_files

If the database uses an spfile (check with show parameter spfile), update the parameter directly — it takes effect at the next startup:

SQL
alter system set control_files=
  '/u01/oracle/oradata/snvdev/control01.ctl',
  '/u02/oracle/controlfile/snvdev/control02.ctl'
  scope=spfile;

5Shut Down and Copy the Control File

Shut down cleanly, so the control file isn't changing while you copy it:

SQL
shutdown immediate
BASH
cp /u01/oracle/oradata/snvdev/control01.ctl /u02/oracle/controlfile/snvdev/control02.ctl

6Start the Database

SQL
startup

7Verify

SQL
show parameter control_files
select name from v$controlfile;

Both copies are now in use. Oracle writes to every file in control_files at the same time.

Using a pfile Instead

If you'd rather edit the parameter by hand — or the database runs from a pfile — do it in this order:

SQL / BASH
SQL> create pfile from spfile;
SQL> shutdown immediate

$ cp /u01/oracle/oradata/snvdev/control01.ctl /u02/oracle/controlfile/snvdev/control02.ctl
$ vi $ORACLE_HOME/dbs/initsnvdev.ora
  *.control_files='/u01/oracle/oradata/snvdev/control01.ctl','/u02/oracle/controlfile/snvdev/control02.ctl'

SQL> create spfile from pfile;
SQL> startup
Don't skip create spfile from pfile. At startup Oracle reads the spfile before the pfile. If you edit only the pfile and start up, the old spfile still lists just control01.ctl, so only that copy is opened and updated. The next time you start with both files listed, their versions no longer match.

Troubleshooting ORA-00214

ERROR
ORA-00214: control file '/u01/oracle/oradata/snvdev/control01.ctl' version 1597
inconsistent with file '/u02/oracle/controlfile/snvdev/control02.ctl' version 1584

The two copies are out of step — usually because the database ran on one copy after the other was taken. To fix it:

  1. shutdown immediate (or shutdown abort if it won't mount).
  2. Copy the newer control file (the higher version, control01.ctl here) over the older one.
  3. Make sure the spfile lists both files (create spfile from pfile if you edited a pfile).
  4. startup.
On ASM, the same idea applies: point control_files at two disk groups (for example +DATA and +FRA) and use RMAN's restore controlfile from to create the second copy — see Convert a Non-ASM Database to ASM.
