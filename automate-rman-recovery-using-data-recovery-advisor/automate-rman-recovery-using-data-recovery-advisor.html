Automating RMAN Recovery with the Data Recovery Advisor

By Sunke Nithin · June 20, 2019   DatabaseOracleRMAN

The Data Recovery Advisor (DRA), introduced in 11g, diagnoses a damaged database, proposes a repair and can run it for you — from RMAN with four commands: LIST FAILURE, ADVISE FAILURE, REPAIR FAILURE PREVIEW and REPAIR FAILURE. Here I lose a data file on purpose and let DRA bring it back (11.2.0.4, single instance).

DRA is deprecated in 19c and desupported from 21c, and it never supported RAC. On current versions use the manual RMAN commands at the end of this post — they're exactly what DRA generates.

1Test Data

SQL
create tablespace nithin_ts datafile '/b01/oradata/sunkdev/nithints.dbf' size 10m;
create user nithin identified by "<password>" default tablespace nithin_ts quota unlimited on nithin_ts;
grant create session, create table to nithin;
grant select on scott.emp to nithin;

conn nithin
create table emp as select * from scott.emp;

2Back Up the Database

RMAN
RMAN> backup incremental level 0 database tag 'firstbackup' plus archivelog;
RMAN> backup current controlfile tag 'control_bkp';

3Lose a Data File

BASH
$ rm /b01/oradata/sunkdev/nithints.dbf      # simulate losing a data file - TEST SYSTEM ONLY

4Diagnose

RMAN
RMAN> list failure;

Failure ID Priority Status    Time Detected Summary
---------- -------- --------- ------------- -------
572        HIGH     OPEN      20-JUN-19     One or more non-system datafiles are missing

RMAN> advise failure;
...
Automated Repair Options
========================
Option Repair Description
------ ------------------
1      Restore and recover datafile 6
  Strategy: The repair includes complete media recovery with no data loss
  Repair script: /a01/oracle/diag/rdbms/sunkdev/sunkdev/hm/reco_1991144589.hm

5Preview the Repair

RMAN
RMAN> repair failure preview;

contents of repair script:
   # restore and recover datafile
   sql 'alter database datafile 6 offline';
   restore datafile 6;
   recover datafile 6;
   sql 'alter database datafile 6 online';

6Repair

RMAN
RMAN> repair failure;
...
Do you really want to execute the above repair (enter YES or NO)? YES
executing repair script
sql statement: alter database datafile 6 offline
channel ORA_DISK_1: restoring datafile 00006 to /b01/oradata/sunkdev/nithints.dbf
media recovery complete, elapsed time: 00:00:01
sql statement: alter database datafile 6 online
repair failure complete

The data file is back on disk and online; the emp table is readable again, with no data loss because all redo since the backup was available.

The Same Without DRA

RMAN
RMAN> sql 'alter database datafile 6 offline';
RMAN> restore datafile 6;
RMAN> recover datafile 6;
RMAN> sql 'alter database datafile 6 online';
