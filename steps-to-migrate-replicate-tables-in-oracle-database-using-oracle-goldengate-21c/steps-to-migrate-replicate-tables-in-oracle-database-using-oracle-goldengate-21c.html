Steps to Migrate / Replicate Tables in Oracle Database Using Oracle GoldenGate 21c

By Sunke Nithin · June 22, 2024   ReplicationOracleGoldengate

This walkthrough replicates the HR.EMPLOYEES table from a source PDB (HRDB in CDB19C) to a target PDB (ORCLPDB1) with Oracle GoldenGate 21c Microservices. We set up change data capture first, then copy the existing rows with an initial load, and finally switch the target over to live replication — the same pattern you'd use for a low-downtime table migration.

source table→trandata→CDC extract→CDC replicat (not started)→initial load→start CDC replicat
ProcessTypeTrailRole
EMP_EXTIntegrated ExtractAACaptures ongoing changes on the source
EMPTParallel Replicat (integrated)AAApplies those changes to the target
EMEILInitial Load ExtractILReads the rows that already exist
EMRILParallel Replicat (nonintegrated)ILLoads those rows into the target

0Assumptions

  • The source and target Oracle databases are already installed.
  • Oracle GoldenGate 21c is installed and a deployment (prodogg) is created, with database credentials for the source (ggadmin_cdb19c) and target (ggadmin_ORCLPDB1).
  • GoldenGate runs on its own server, separate from the database servers. Extract and Replicat are in the same deployment, so no Distribution / Receiver path is needed — the Replicats read the trail files the Extracts write.

2Add Schema Trandata

Supplemental logging lets the Extract capture the key columns of every change. In the Administration Service, open Configuration → TRANDATA Information, choose Schema and enter HRDB.HR, then submit. Search for it again to confirm the schema's tables are prepared for instantiation.

Adding and validating schema trandata for HRDB.HR.

The same from the Admin Client:

ADMIN CLIENT
DBLOGIN USERIDALIAS ggadmin_cdb19c
ADD SCHEMATRANDATA HRDB.HR
INFO SCHEMATRANDATA HRDB.HR

3Create the CDC Extract

On the Overview page click + next to Extracts, choose Integrated Extract, and fill in the options: process name emp_ext, begin Now, trail name AA, register to PDB HRDB, and the source credential alias.

Adding the Integrated Extract.

The generated parameter file:

EMP_EXT.PRM
EXTRACT emp_ext
USERIDALIAS ggadmin_cdb19c DOMAIN OracleGoldenGate
EXTTRAIL AA

SOURCECATALOG HRDB
TABLE HR.EMPLOYEES;

Create and Run — EMP_EXT comes up running.

Test the capture by inserting two more rows on the source. The Extract statistics show both inserts:

4Create the CDC Replicat — but Don't Start It

Add a Replicat of type Parallel Replicat → Integrated, named EMPT, reading trail AA with the target credential and a checkpoint table:

Creating EMPT — click Create, not Create and Run.

EMPT.PRM
REPLICAT EMPT
USERIDALIAS ggadmin_ORCLPDB1 DOMAIN OracleGoldenGate
MAP HRDB.HR.EMPLOYEES, TARGET HR.EMPLOYEES;
Don't start the CDC Replicat yet. So far we only capture new changes; the rows that already exist on the source aren't in the trail. Those come from the initial load, which must finish before EMPT starts.

5Initial Load

There are several ways to copy the existing data:

  • An Initial Load Extract (used here)
  • Oracle Data Pump export / import
  • Oracle Database Migration Service (DMS)

First create the table on the target database:

SQL · TARGET
CREATE TABLE employees (
    id         NUMBER GENERATED BY DEFAULT AS IDENTITY,
    name       VARCHAR2(100) NOT NULL,
    age        NUMBER(3) CHECK (age > 0),
    city       VARCHAR2(100),
    occupation VARCHAR2(100),
    PRIMARY KEY (id)
);

Initial load extract

Add an Extract, choose Initial Load Extract, and name it EMEIL. It writes to trail IL:

EMEIL.PRM
EXTRACT EMEIL
USERIDALIAS ggadmin_cdb19c DOMAIN OracleGoldenGate
EXTFILE IL

SOURCECATALOG HRDB
TABLE HR.EMPLOYEES;

EMEIL reads all 12 rows — the original 10 plus the 2 test inserts.

Initial load replicat

Add a Parallel Replicat → Nonintegrated named EMRIL reading trail IL, and start it:

EMRIL.PRM
REPLICAT EMRIL
USERIDALIAS ggadmin_ORCLPDB1 DOMAIN OracleGoldenGate
MAP HRDB.HR.EMPLOYEES, TARGET HR.EMPLOYEES;

EMRIL applies all 12 rows to the target.

Once every row is applied, stop EMRIL.

6Start the CDC Replicat

When I started EMPT it abended with ORA-00001: unique constraint (HR.SYS_C007769) violated. That's expected: the CDC Extract was started before the initial load, so the 2 test rows are in both trails — EMRIL already inserted them, and EMPT tried to insert them again.

To get past the overlap, add HANDLECOLLISIONS to the Replicat parameters and start it:

EMPT.PRM
REPLICAT EMPT
USERIDALIAS ggadmin_ORCLPDB1 DOMAIN OracleGoldenGate
HANDLECOLLISIONS
MAP HRDB.HR.EMPLOYEES, TARGET HR.EMPLOYEES;

EMPT catches up; EMRIL is stopped.

Once the target is in sync, remove (or comment out) HANDLECOLLISIONS and restart EMPT. Left on, it silently turns duplicate inserts into updates and skips missing-row errors, which hides real data problems.
Avoiding the collision altogether: instead of HANDLECOLLISIONS, start the CDC Replicat from the SCN the initial load was taken at, so it only applies changes made after it — START REPLICAT EMPT, AFTERCSN <scn>. With a Data Pump initial load, the tables prepared for instantiation in step 2 carry that SCN with them, and DBOPTIONS ENABLE_INSTANTIATION_FILTERING in the Replicat skips the overlap automatically.
Identity column: ID is GENERATED BY DEFAULT, so the Replicat can insert the source's values. The target's identity sequence doesn't move, though — if the target ever takes new inserts of its own (after a migration cut-over, say), reset it first: ALTER TABLE hr.employees MODIFY id GENERATED BY DEFAULT AS IDENTITY (START WITH LIMIT VALUE);

7Troubleshooting: OGG-02022

When I first started the Extract, it stopped with:

ERROR
