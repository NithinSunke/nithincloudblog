Steps to Upgrade SQL Server 2016 to SQL Server 2019

By Sunke Nithin · August 8, 2025   DatabaseMSSQLUpgrade

Upgrading Microsoft SQL Server 2016 to SQL Server 2019 is straightforward, but it needs careful planning to avoid downtime or data loss. This is a step-by-step in-place upgrade, as I ran it on a lab instance.

1Pre-Upgrade Checklist

  1. Review the upgrade path. SQL Server 2016 (SP2 or later) upgrades directly to SQL Server 2019.
  2. Check edition compatibility. The 2019 edition you install must support upgrading from your current edition (for example Standard → Standard or Enterprise).
  3. Check the features you use. Review SQL Server 2019's deprecated and discontinued features. Run Data Migration Assistant (DMA) against your databases to catch compatibility issues early.
  4. Run a database consistency check on every database:
    T-SQL
    DBCC CHECKDB;

    CHECKDB reports 0 allocation errors and 0 consistency errors.

  5. Back up everything — full backups of every user database and the system databases master, msdb and model. In SSMS: right-click the database → Tasks → Back Up, choose the destination, and run the backup.
    T-SQL
    BACKUP DATABASE imagedb TO DISK = 'L:\backup\imagedb.bak' WITH CHECKSUM, STATS = 10;
BACKUP DATABASE master  TO DISK = 'L:\backup\master.bak'  WITH CHECKSUM;
BACKUP DATABASE msdb    TO DISK = 'L:\backup\msdb.bak'    WITH CHECKSUM;
BACKUP DATABASE model   TO DISK = 'L:\backup\model.bak'   WITH CHECKSUM;

    Backing up imagedb from SSMS, and all four backups in L:\backup.

    Also script out or back up SQL Server Agent jobs, linked servers, logins and SSIS packages (if any), and take an OS-level snapshot if the server is a VM.
  6. Check disk space — keep at least 6–10 GB free on the drive where SQL Server is installed.
  7. Record the current build, so you know exactly what you're upgrading from:
    T-SQL
    SELECT @@VERSION;
  8. Download SQL Server 2019 setup from Microsoft's SQL Server downloads page.
Reporting Services: since SQL Server 2017, SSRS is a separate installer. If this instance runs SSRS 2016, SQL Server 2019 setup won't upgrade it — plan to install SSRS 2019 separately and migrate the report server databases.

2Upgrade Steps

Step 1: Run SQL Server 2019 setup

Mount or extract the SQL Server 2019 ISO and run setup.exe as Administrator.

Step 2: Choose the upgrade option

In the SQL Server Installation Center, go to Installation → Upgrade from a previous version of SQL Server.

Step 3: Select the instance to upgrade

Accept the license terms and product key screens, then select the existing SQL Server 2016 instance — here SQLDB.

Step 4: Upgrade rules

Let the wizard run its rule checks, and fix any failures it reports (for example a pending reboot or a missing .NET Framework) before continuing.

Step 5: Select features

The features already installed are selected and can't be changed — you can't add features during an upgrade. Add them afterwards with a separate setup run if needed.

Step 6: Instance configuration

Confirm the instance name and ID. The new binaries go into an MSSQL15.<instance> directory.

Step 7: Ready to upgrade

Review the summary and click Upgrade. The duration depends on the instance size, number of databases and features — typically 15–45 minutes.

Setup finished with every feature Succeeded but asked for a computer restart. Restart the server before you continue, so the upgraded files and services are fully in place.

3Post-Upgrade Tasks

  1. Apply the latest cumulative update for SQL Server 2019 — see Microsoft's latest updates for SQL Server page.
  2. Review the database compatibility level. Upgrading the engine doesn't change it: databases keep their existing level (130 for SQL Server 2016). Move to 150 (SQL Server 2019) after testing your workload, and compare query performance before and after — Query Store helps here.
    T-SQL
    SELECT name, compatibility_level FROM sys.databases;

ALTER DATABASE [imagedb] SET COMPATIBILITY_LEVEL = 150;

    imagedb now at compatibility level SQL Server 2019 (150).

  3. Verify services and jobs — SQL Server Agent jobs, linked servers, and any SSIS/SSAS components.
  4. Run DBCC CHECKDB again to validate database integrity after the upgrade.
  5. Check the error log for upgrade-related messages:
    T-SQL
    EXEC xp_readerrorlog;
  6. Update statistics on user databases (for example EXEC sp_updatestats;) so the optimizer works from fresh statistics on the new version.

Summary

An in-place upgrade from SQL Server 2016 to 2019 is mostly a guided wizard. The work that matters happens around it: consistency checks and full backups before, a restart, then the latest CU, a tested compatibility-level change and integrity checks after. Rehearse it on a copy of the server first.
