Two-Node Oracle RAC Installation Steps Using VirtualBox

By Sunke Nithin · June 26, 2019   DatabaseOracleRacVirtualBox

A complete lab build of a two-node Oracle 11g Release 2 RAC cluster on VirtualBox: install Oracle Linux 5 on the first node, configure DNS (including the SCAN name), prepare shared ASM disks with udev, clone the VM to make the second node, then install Grid Infrastructure and the RAC database.

A 2019 lab guide on old releases. Oracle Linux 5 and Database 11g R2 are long out of support, and the old public-yum.oracle.com repository has moved to yum.oracle.com. The overall approach — DNS for SCAN, shared disks, udev rules, cloning, Grid then DB — still applies to newer releases, but commands and package names differ.

2Post-Installation Steps and Packages

On first boot: accept the license, disable the firewall, disable SELinux, disable kdump, set the clock, then finish and reboot. After the restart, log in as root and confirm:

BASH · ROOT
service iptables stop
chkconfig iptables off
chkconfig --list iptables

vi /etc/selinux/config        # SELINUX=disabled

Configure yum and install prerequisites

BASH · ROOT
cd /etc/yum.repos.d
wget http://public-yum.oracle.com/public-yum-el5.repo   # now yum.oracle.com

yum install -y oracle-rdbms-server-11gR2-preinstall
yum install -y man parted unzip xterm lsof bind xorg-x11-twm
yum remove -y ntp
The original post downloaded public-yum-ol6.repo, which is for Oracle Linux 6. On Oracle Linux 5 use the EL5 repo file. Removing ntp lets Oracle's Cluster Time Synchronization Service (CTSS) manage time across the nodes.

3Configure DNS on rac1 (Master)

RAC needs DNS to resolve the SCAN name to three addresses in round-robin. In this lab rac1 is the master DNS server.

rac1Install the BIND packages

Check whether each package is installed with rpm -qa | grep bind, then install any that are missing from the installation media:

BASH · ROOT
rpm -Uvh bind-9*
rpm -Uvh bind-chroot*
rpm -Uvh bind-devel-9.*
rpm -Uvh bind-libbind-*
rpm -Uvh bind-libs-*
rpm -Uvh bind-sdb-9.*
rpm -Uvh system-config-bind-*
rpm -Uvh caching-nameserver-*
rpm -Uvh postgresql-libs-*

rac1Confirm the server's IP address

BASH
ifconfig eth0     # expect inet addr:192.168.1.11  Mask:255.255.255.0

rac1Create and edit named.conf

BASH
cd /var/named/chroot/etc/
cp named.caching-nameserver.conf named.conf
/var/named/chroot/etc/named.conf
options {
    listen-on port 53 { 192.168.1.11; };
    # listen-on-v6 port 53 { ::1; };
    directory           "/var/named";
    dump-file           "/var/named/data/cache_dump.db";
    statistics-file     "/var/named/data/named_stats.txt";
    memstatistics-file  "/var/named/data/named_mem_stats.txt";
    allow-query         { any; };
    allow-query-cache   { localhost; };
};

logging {
    channel default_debug {
        file "data/named.run";
        severity dynamic;
    };
};

view localhost_resolver {
    match-clients      { any; };
    match-destinations { 192.168.1.11; };
    recursion yes;
    include "/etc/named.rfc1912.zones";
};

rac1Define the zones in named.rfc1912.zones

/var/named/chroot/etc/named.rfc1912.zones
zone "." IN {
    type hint;
    file "named.ca";
};

zone "oracle.com" IN {
    type master;
    file "forward.zone";
    allow-update { none; };
};

zone "localhost" IN {
    type master;
    file "localhost.zone";
    allow-update { none; };
};

zone "1.168.192.in-addr.arpa" IN {
    type master;
    file "reverse.zone";
    allow-update { none; };
};
BASH
chgrp named named.conf named.rfc1912.zones

rac1Create the forward and reverse zone files

BASH
cd /var/named/chroot/var/named

cp named.local reverse.zone

rac-scan  IN  A  192.168.1.32
rac-scan  IN  A  192.168.1.33

4Network, PAM and the oracle User

Stop the network service from overwriting /etc/resolv.conf: in /etc/sysconfig/network-scripts/ifcfg-eth1 (and ifcfg-eth0 if present) set PEERDNS=no, then:

BASH · ROOT
service network restart
cat /etc/resolv.conf      # your entries should still be there

Check these lines are present in /etc/pam.d/login:

/etc/pam.d/login
session    required     pam_selinux.so open
session    required     pam_limits.so

Create the groups, the oracle user and the base directory:

BASH · ROOT
groupadd oinstall
groupadd dba
groupadd oper
useradd -g oinstall -G dba,oper oracle
passwd oracle

mkdir -p /u01/app
chown -R oracle:oinstall /u01/app
chmod -R 775 /u01/app
The oracle-rdbms-server-11gR2-preinstall package may already have created the oracle user and groups — check with id oracle first. Use 775 rather than 777 on /u01/app.

5Shared Storage and udev Rules

Shut rac1 down (shutdown -h now) and, in VirtualBox, create the two 8 GB disks as fixed-size, shareable virtual disks attached to rac1. ASM will use them for both Clusterware and database storage.

rac1Partition the shared disks (one node only)

Create a single whole-disk partition on each disk. Starting at sector 2048 gives the recommended 1 MB alignment offset.

BASH · ROOT
fdisk /dev/sdb
  u         # switch units to sectors
  n         # new partition
  p         # primary
  1         # partition number
  2048      # first sector (1 MB offset)
  <Enter>   # last sector: use the default (whole disk)
  w         # write and exit

# Repeat for /dev/sdc

rac1Identify the disks

BASH · ROOT
/sbin/scsi_id -g -u -s /block/sdb
SATA_VBOX_HARDDISK_VBd306dbe0-df3367e3_

/sbin/scsi_id -g -u -s /block/sdc
SATA_VBOX_HARDDISK_VB46dec7e0-192e8000_

Make SCSI devices trusted by adding this line to /etc/scsi_id.config (create the file if it doesn't exist):

/etc/scsi_id.config
options=-g

rac1Create the udev rules file

The PROGRAM value must match the command you used to get the SCSI ID, and RESULT must match the ID returned for each disk.

/etc/udev/rules.d/99-oracle-asmdevices.rules
KERNEL=="sd?1", BUS=="scsi", PROGRAM=="/sbin/scsi_id -g -u -s /block/$parent", RESULT=="SATA_VBOX_HARDDISK_VBd306dbe0-df3367e3_", NAME="asm-disk1", OWNER="oracle", GROUP="dba", MODE="0660"
KERNEL=="sd?1", BUS=="scsi", PROGRAM=="/sbin/scsi_id -g -u -s /block/$parent", RESULT=="SATA_VBOX_HARDDISK_VB46dec7e0-192e8000_", NAME="asm-disk2", OWNER="oracle", GROUP="dba", MODE="0660"

rac1Load the partitions, test the rules and check permissions

BASH · ROOT
/sbin/partprobe /dev/sdb1
/sbin/partprobe /dev/sdc1

udevtest /block/sdb/sdb1      # OL5
udevtest /block/sdc/sdc1

ls -al /dev/asm-disk*
Show expected output
OUTPUT
brw-rw---- 1 oracle dba 8, 17 Apr  8 22:47 /dev/asm-disk1
brw-rw---- 1 oracle dba 8, 33 Apr  8 22:47 /dev/asm-disk2
Detach the shared ASM disks from rac1 before cloning, and attach them to both VMs again afterwards — otherwise the clone gets its own private copies of the disks.

6Clone rac1 to rac2

  1. Shut rac1 down: shutdown -h now.
  2. In VirtualBox, clone the rac1 VM as rac2 (reinitialize the MAC addresses).
  3. Re-attach the two shared disks to both VMs.
  4. Start rac2 and change its IP addresses with system-config-network:
DeviceIPv4 / netmask
eth0192.168.1.12 / 255.255.255.0
eth1192.168.2.12 / 255.255.255.0

Set the hostname to rac2.oracle.com, then clear the cloned NIC identities and reboot:

BASH · ROOT ON RAC2
rm -f /etc/udev/rules.d/70-persistent-net.rules
sed -i -e '/HWADDR/d' -e '/UUID/d' /etc/sysconfig/network-scripts/ifcfg-eth[0-1]
reboot

# After the reboot
ip l                    # check eth0 and eth1 are present
ls -l /dev/asm*         # the shared disks should appear here too
service named stop      # reconfigure DNS as a slave next

7Configure DNS on rac2 (Slave)

rac2 runs a slave copy of the zones so name resolution keeps working if rac1 is down.

rac2named.conf

Same as on rac1, but listening on rac2's address:

/var/named/chroot/etc/named.conf (changes)
listen-on port 53 { 192.168.1.12; };
...
match-destinations { 192.168.1.12; };

rac2named.rfc1912.zones as slave zones

/var/named/chroot/etc/named.rfc1912.zones
zone "." IN {
    type hint;
    file "named.ca";
};

zone "oracle.com" IN {
    type slave;
    file "slaves/forward.zone";
    masters { 192.168.1.11; };
};

zone "localhost" IN {
    type master;
    file "localhost.zone";
    allow-update { none; };
};

zone "1.168.192.in-addr.arpa" IN {
    type slave;
    file "slaves/reverse.zone";
    masters { 192.168.1.11; };
};
Keeping slave zone files under slaves/ (which named can write to) lets rac2 save the transferred zones. Check the transfer worked with ls /var/named/chroot/var/named/slaves/.

rac2Restart and verify

BASH
service named restart
chkconfig named on

dig @192.168.1.12 rac1.oracle.com
dig @192.168.1.12 -x 192.168.1.11
nslookup rac-scan 192.168.1.12

The answers should match rac1's. Now both nodes are ready for the installation.

8Install Grid Infrastructure

rac1 · oracleUnpack the software and set up SSH

BASH
su - oracle
cd /opt                                  # where the software was downloaded
unzip '*.zip'
cd grid

# As root, on both nodes: install cvuqdisk from grid/rpm
rpm -Uvh rpm/cvuqdisk-*.rpm

# Passwordless SSH between the nodes for the oracle user
cd sshsetup
./sshUserSetup.sh -user oracle -hosts "rac1 rac2" -noPromptPassphrase -confirm -advanced

rac1 · oracleRun the pre-installation checks

BASH
cd /opt/grid
./runcluvfy.sh stage -pre crsinst -n rac1,rac2 -fixup -verbose

Fix anything reported as failed (run the generated fixup script as root if offered), then start the installer:

BASH
./runInstaller
  1. Software updates: skip.
  2. Installation option: Install and Configure Grid Infrastructure for a Cluster.
  3. Installation type: Typical.
  4. Cluster configuration:
    • SCAN name: rac-scan
    • Add rac2 to the node list
    • SSH connectivity: enter the oracle password, then Setup and Test
  5. Create ASM disk group:
    • Disk group name: DATA
    • Redundancy: External
    • Candidate disks: /dev/asm-disk1 (set the discovery path to /dev/asm* if it isn't listed)
  6. Create inventory → Next.
  7. Prerequisite checks → Next.
  8. Summary → Install.
  9. Run the root scripts as root when prompted — orainstRoot.sh and root.sh, on rac1 first and then rac2, one node at a time.
  10. Finish.
BASH
# Check the cluster afterwards (as oracle, with the grid home on PATH)
crsctl check cluster -all
crsctl stat res -t

9Install the RAC Database

Run ./runInstaller from the unpacked database directory as oracle and work through the wizard:

  1. Configure security updates: uncheck the box → Next.
  2. Installation option: Create and configure a database.
  3. System class: Server class.
  4. Node selection: Real Application Clusters database installation, with both rac1 and rac2 selected.
  5. Install type: Typical install.
  6. Typical install configuration:
    • Oracle base and software location (defaults under /u01/app)
    • Storage type: Automatic Storage Management
    • Database file location: DATA
    • ASMSNMP password
    • OSDBA group: dba
    • Global database name: racdb
  7. Prerequisite checks → Next.
  8. Run root.sh as root on each node when prompted.
BASH
# Confirm both instances are running
srvctl status database -d racdb
