How to Schedule Automatic VM Backups in Proxmox VE with Proxmox Backup Server

By Sunke Nithin · April 22, 2025   VirtualizationProxmox

Once Proxmox Backup Server is added as storage in Proxmox VE, backup jobs run on a schedule with no manual work. Here's how to create one, set retention, and keep the datastore tidy.

Prerequisites

  • Proxmox VE with VMs or containers
  • PBS added as a storage in Proxmox VE
  • A datastore in PBS

1Create a Backup Job

Datacenter → Backup → Add:

FieldSetting
NodeThe node(s) whose guests to back up (or all)
StorageYour PBS storage
ScheduleCalendar-event syntax, e.g. sun 10:00, daily 02:00, mon..fri 22:30
Selection modeAll, Include selected VMs, Exclude selected VMs, or a Pool
ModeSnapshot — no downtime (recommended, with the QEMU guest agent for consistency); Suspend — brief pause; Stop — shuts the guest down for the backup
NotificationEmail on failure or always

In my lab I backed up VM 102 every Sunday at 10:00 in Stop mode. Compression is fixed to ZSTD for PBS (deduplication happens on the PBS side):

2Set Retention

On the Retention tab, choose how many backups to keep. I kept just the last one for the lab — in real life keep more, e.g. last 3, daily 7, weekly 4, monthly 6:

Click Create. The job appears in the list; Run now tests it immediately:

3Prune, Garbage Collection and Verify on PBS

Retention can also live on the PBS side — Datastore → Prune & GC → add a prune job with keep rules, and a garbage-collection schedule. Pruning removes backup snapshots; garbage collection is what actually frees the disk space. Add a Verify job (e.g. weekly) to check backup integrity.

Set retention in one place — either the Proxmox VE job or a PBS prune job — so the two don't fight.

Tips

  • Install the QEMU guest agent in VMs so snapshot-mode backups are filesystem-consistent.
  • Keep an off-site copy with a sync job to a second PBS.
  • Test restores regularly — a backup you've never restored is a hope, not a backup.
