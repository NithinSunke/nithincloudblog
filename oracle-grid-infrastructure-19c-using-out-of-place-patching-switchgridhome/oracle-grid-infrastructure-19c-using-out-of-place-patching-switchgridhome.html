Oracle Grid Infrastructure 19c Out-of-Place Patching with switchGridHome

By Sunke Nithin · June 12, 2024   DatabaseOraclePatching

Out-of-place patching installs a fresh, already-patched Grid home next to the running one and then switches the cluster to it, node by node. Downtime per node is only the time it takes to restart the stack, rollback is just switching back, and you never touch the binaries the cluster is running from. Here I patch a freshly built two-node 19c RAC to the 19.23 RU (patch 36233126) using gridSetup.sh -switchGridHome.

Why a fresh install instead of a clone? opatchauto -outofplace clones the existing home and patches the copy (see the related post below). With -switchGridHome you unzip the gold image yourself and apply the RU during setup with -applyRU, so the new home has no leftovers from the old one.

Preparation

  1. The Oracle Grid Infrastructure 19c base image (LINUX.X64_193000_grid_home.zip).
  2. The latest RU — here 36233126 (GI 19.23).
  3. The latest OPatch (patch 6880880).
  4. Enough free space on every node for a second Grid home (about 15 GB).

1Create the New Grid Home Directory

On all nodes, as root:

BASH
[oracle@rac1 ~]$ su - root
[root@rac1 ~]# mkdir -p /u01/app/19.23.0/grid
[root@rac1 ~]# chown -R oracle:oinstall /u01/app/19.23.0
[root@rac1 ~]# chmod -R 775 /u01/app/19.23.0
[root@rac1 ~]# su - oracle
[oracle@rac1 ~]$ ssh rac1    # quick check that user equivalence works
[oracle@rac1 ~]$ exit

2Unzip the Software and the Latest OPatch

On node 1 only — the installer copies the home to the other nodes:

BASH
[oracle@rac1 ~]$ export NEWGRIDHOME=/u01/app/19.23.0/grid
[oracle@rac1 ~]$ cd $NEWGRIDHOME
[oracle@rac1 grid]$ unzip -oq /nfsshare/vagrant-scripts/si/ol7_19/software/LINUX.X64_193000_grid_home.zip

# replace the bundled OPatch with the latest one
[oracle@rac1 grid]$ rm -rf OPatch
[oracle@rac1 grid]$ unzip -oq /u01/patch/p6880880_122010_Linux-x86-64.zip

3Run the Prerequisite Checks

BASH
[oracle@rac1 grid]$ export ORACLE_HOME=$NEWGRIDHOME
[oracle@rac1 grid]$ $ORACLE_HOME/gridSetup.sh -executePrereqs -silent
Launching Oracle Grid Infrastructure Setup Wizard...

[WARNING] [INS-13014] Target environment does not meet some optional requirements.
   CAUSE: Some of the optional prerequisites are not met. See logs for details. /u01/app/oraInventory/logs/GridSetupActions2024-06-12_00-56-28AM/gridSetupActions2024-06-12_00-56-28AM.log

In my lab the warning was only insufficient swap space, which is fine to ignore on a test cluster. In production, read the log and fix anything else it lists.

4Install the New Home with the RU Applied

A software-only install (CRS_SWONLY) of the new home, applying the RU first with -applyRU:

BASH
# olsnodes comes from the CURRENT (old) grid home, so run these before changing PATH
[oracle@rac1 grid]$ export CLUSTER_NAME=$(/u01/app/19.0.0/grid/bin/olsnodes -c)
[oracle@rac1 grid]$ export CLUSTER_NODES=$(/u01/app/19.0.0/grid/bin/olsnodes | tr '\n' ',' | sed 's/,\s*$//')
[oracle@rac1 grid]$ export ORACLE_BASE=/u01/app/grid
[oracle@rac1 grid]$ export ORA_INVENTORY=/u01/app/oraInventory
[oracle@rac1 grid]$ cd $ORACLE_HOME
[oracle@rac1 grid]$ ./gridSetup.sh -ignorePrereq -waitforcompletion -silent \
   -applyRU /u01/patch/36233126 \
   -responseFile $ORACLE_HOME/install/response/gridsetup.rsp \
   INVENTORY_LOCATION=$ORA_INVENTORY \
   ORACLE_BASE=$ORACLE_BASE \
   SELECTED_LANGUAGES=en \
   oracle.install.option=CRS_SWONLY \
   oracle.install.asm.OSDBA=asmdba \
   oracle.install.asm.OSOPER=asmoper \
   oracle.install.asm.OSASM=asmadmin \
   oracle.install.crs.config.ClusterConfiguration=STANDALONE \
   oracle.install.crs.config.configureAsExtendedCluster=false \
   oracle.install.crs.config.clusterName=$CLUSTER_NAME \
   oracle.install.crs.config.gpnp.configureGNS=false \
   oracle.install.crs.config.autoConfigureClusterNodeVIP=false \
   oracle.install.crs.config.clusterNodes=$CLUSTER_NODES

Don't run root.sh yet. The installer asks for it, but on a software-only install it is run after the switch (step 6).

5Switch to the New Grid Home

Run -switchGridHome on each node, with clusterNodes set to that node. First on rac1:

BASH
[oracle@rac1 grid]$ export ORACLE_HOME=/u01/app/19.23.0/grid
[oracle@rac1 grid]$ export CURRENT_NODE=$(hostname)
[oracle@rac1 grid]$ $ORACLE_HOME/gridSetup.sh \
   -silent -switchGridHome \
   oracle.install.option=CRS_SWONLY \
   ORACLE_HOME=$ORACLE_HOME \
   oracle.install.crs.config.clusterNodes=$CURRENT_NODE \
   oracle.install.crs.rootconfig.executeRootScript=false
Launching Oracle Grid Infrastructure Setup Wizard...
As a root user, execute the following script(s):
        1. /u01/app/19.23.0/grid/root.sh

Execute /u01/app/19.23.0/grid/root.sh on the following nodes:
[rac1]
...
Successfully Setup Software.

Then on rac2:

BASH
[oracle@rac2 ~]$ export ORACLE_HOME=/u01/app/19.23.0/grid
[oracle@rac2 ~]$ export CURRENT_NODE=$(hostname)
[oracle@rac2 ~]$ $ORACLE_HOME/gridSetup.sh \
   -silent -switchGridHome \
   oracle.install.option=CRS_SWONLY \
   ORACLE_HOME=$ORACLE_HOME \
   oracle.install.crs.config.clusterNodes=$CURRENT_NODE \
   oracle.install.crs.rootconfig.executeRootScript=false
...
Execute /u01/app/19.23.0/grid/root.sh on the following nodes:
[rac2]
Correction: in my original post the second run was on rac1 again — it must run on rac2 (the output should then list [rac2]).

6Run root.sh — One Node at a Time

This is the moment the clusterware on that node restarts from the new home. Do it in a rolling fashion so the other node keeps the databases available:

BASH
[root@rac1 ~]# /u01/app/19.23.0/grid/root.sh
Check /u01/app/19.23.0/grid/install/root_rac1.scslabs.com_2024-06-12_02-06-44-081548068.log for the output of root script

# wait until the stack is fully up on rac1, then on rac2:
[root@rac2 ~]# /u01/app/19.23.0/grid/root.sh

7Verify

BASH
$ crsctl query crs activeversion -f
$ crsctl query crs softwarepatch rac1
$ crsctl query crs softwarepatch rac2
$ crsctl check cluster -all
$ $ORACLE_HOME/OPatch/opatch lspatches
$ cat /etc/oratab | grep ASM

Both nodes should report the 19.23 patch level and the same software patch number. Then update the grid user's profile (ORACLE_HOME, PATH) on every node to point to /u01/app/19.23.0/grid; /etc/oratab is updated for +ASM by the switch.

8Remove the Old Grid Home — Later

The old home is your rollback path, so keep it for a week or so. When you're confident, deinstall it on each node, one at a time — no downtime is needed:

BASH
$ export ORACLE_HOME=/u01/app/19.0.0/grid
$ $ORACLE_HOME/deinstall/deinstall -local
The old home in this lab is /u01/app/19.0.0/grid — check the path before you run deinstall; pointing it at the active home would be a very bad day.
