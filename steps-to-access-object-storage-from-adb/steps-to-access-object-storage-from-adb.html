Steps to Access OCI Object Storage from Autonomous Database

By Sunke Nithin · April 4, 2025   DatabaseCLOUDOracleADBOCI

Oracle Autonomous Database (ADB) works directly with OCI Object Storage: you can list, load and export files in a bucket from SQL. In this post we create an auth token, store it as a credential in ADB with DBMS_CLOUD, list a bucket's contents and load a CSV file into a table.

bucket + file→auth token→CREATE_CREDENTIAL→LIST_OBJECTS→COPY_DATA

0Prerequisites

  • An OCI account with an Autonomous Database provisioned.
  • A user allowed to manage buckets and create auth tokens.
  • Access to ADB as ADMIN (or a user with EXECUTE on DBMS_CLOUD) through Database Actions or SQL Developer.

1Create a Bucket and Upload a File

  1. In the OCI Console, go to Storage → Object Storage & Archive Storage → Buckets.
  2. Pick your compartment, click Create Bucket, give it a name (ociob here) and keep the defaults.
  3. Open the bucket, click Upload and upload your file — channels.txt, a small comma-separated file.

2Generate an Auth Token

ADB authenticates to Object Storage as an OCI user, using an auth token as the password. Open your profile (top-right avatar → My profile), choose Auth tokens under Resources, and click Generate token:

Copy the token straight away — it's shown only once. Treat it like a password: don't paste it into scripts you share, and never publish it. Each user can have at most two auth tokens; delete ones you no longer use.

3Store the Credential in ADB

In ADB, create a credential with your OCI username and the auth token:

SQL · ADB
SET DEFINE OFF
BEGIN
  DBMS_CLOUD.CREATE_CREDENTIAL(
    credential_name => 'ADBP_OBS',
    username        => 'oracleidentitycloudservice/<your-user@example.com>',
    password        => '<auth-token>'
  );
END;
/
  • username is your OCI username exactly as shown in your profile. Federated (IDCS) users have the oracleidentitycloudservice/ prefix; users in an identity domain's default domain use just the username or email. Watch for stray spaces.
  • SET DEFINE OFF stops SQL*Plus-style tools treating an & in the token as a substitution variable.

Check it:

SQL · ADB
SELECT credential_name, username, enabled FROM user_credentials;
No-token alternative: ADB can use a resource principal instead. Run EXEC DBMS_CLOUD_ADMIN.ENABLE_RESOURCE_PRINCIPAL(); as ADMIN, add an IAM dynamic group and policy that let the database read the bucket, then use credential_name => 'OCI$RESOURCE_PRINCIPAL'. Nothing to rotate or leak.

4Test: List the Bucket

The bucket URI is https://objectstorage.<region>.oraclecloud.com/n/<namespace>/b/<bucket>/o/. Your namespace is shown on the bucket's details page and in Tenancy details.

SQL · ADB
SELECT object_name, bytes
  FROM DBMS_CLOUD.LIST_OBJECTS('ADBP_OBS', 'https://objectstorage.eu-frankfurt-1.oraclecloud.com/n/<namespace>/b/ociob/o/');

ADB can see channels.txt in the bucket — the credential works.

5Load the File into a Table

Create the target table:

SQL · ADB
CREATE TABLE channels (
  channel_id     CHAR(1),
  channel_desc   VARCHAR2(20),
  channel_class  VARCHAR2(20)
);

Load it with DBMS_CLOUD.COPY_DATA:

SQL · ADB
BEGIN
  DBMS_CLOUD.COPY_DATA(
    table_name      => 'CHANNELS',
    credential_name => 'ADBP_OBS',
    file_uri_list   => 'https://objectstorage.eu-frankfurt-1.oraclecloud.com/n/<namespace>/b/ociob/o/channels.txt',
    format          => json_object('delimiter' value ',')
  );
END;
/
SQL · ADB
SELECT * FROM channels;

The rows from channels.txt are now in the CHANNELS table.

If a load fails, COPY_DATA writes log and bad-file tables: SELECT * FROM user_load_operations ORDER BY id DESC; shows their names. The format parameter also takes options like 'skipheaders' value '1' for files with a header row.

Going the Other Way

To write data to the bucket, use DBMS_CLOUD.EXPORT_DATA with the same credential and a file_uri_list in the bucket, for example to export a query as CSV or Parquet.
