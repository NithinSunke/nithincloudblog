Setup for Oracle Databases Involved in a GoldenGate Configuration

By Sunke Nithin · June 22, 2024   ReplicationGoldengate

Before GoldenGate 21c can capture from or apply to an Oracle database, the database needs a few changes: archive logging, force and supplemental logging, the GoldenGate replication parameter, enough streams pool, and a GoldenGate admin user. This post prepares the source and target databases and then adds their credentials to GoldenGate.

archivelog→force + supplemental logging→enable_goldengate_replication→streams_pool_size→c##ggadmin→credential alias

1Prepare the Database

Run as SYSDBA in CDB$ROOT on both the source and target databases (the source is the one that really needs the logging settings):

SQL · CDB$ROOT
-- Integrated Extract needs ARCHIVELOG mode
SELECT log_mode FROM v$database;

-- Force logging and minimal supplemental logging
ALTER DATABASE FORCE LOGGING;
ALTER DATABASE ADD SUPPLEMENTAL LOG DATA;
SELECT force_logging, supplemental_log_data_min FROM v$database;

-- Allow GoldenGate replication
ALTER SYSTEM SET enable_goldengate_replication = TRUE SCOPE = BOTH;

-- Memory for Integrated Extract / Replicat
ALTER SYSTEM SET streams_pool_size = 1G SCOPE = BOTH;
Supplemental logging levels: the database-level minimal logging above is required. Table-level key logging is then added from GoldenGate with ADD SCHEMATRANDATA / ADD TRANDATA, which is more targeted than turning on all-column logging for the whole database.
Streams pool sizing: each Integrated Extract uses about 1 GB by default, so allow roughly 1 GB × number of Extracts, plus 25% headroom.

2Create the GoldenGate Admin User

Create a common user that exists in every container:

SQL · CDB$ROOT
CREATE USER c##ggadmin IDENTIFIED BY "<password>" CONTAINER = ALL;
GRANT CREATE SESSION, CONNECT, RESOURCE TO c##ggadmin CONTAINER = ALL;
GRANT SELECT ANY DICTIONARY TO c##ggadmin CONTAINER = ALL;
ALTER USER c##ggadmin QUOTA UNLIMITED ON users CONTAINER = ALL;

EXEC DBMS_GOLDENGATE_AUTH.GRANT_ADMIN_PRIVILEGE('C##GGADMIN', container => 'ALL');

GRANT_ADMIN_PRIVILEGE with container => 'ALL' gives the capture and apply privileges in every PDB.

On the target, the Replicat applies changes as this user, so it also needs DML and DDL rights on the tables it maintains:

SQL · TARGET
GRANT INSERT ANY TABLE, UPDATE ANY TABLE, DELETE ANY TABLE TO c##ggadmin CONTAINER = ALL;
GRANT CREATE ANY TABLE, ALTER ANY TABLE, DROP ANY TABLE, LOCK ANY TABLE TO c##ggadmin CONTAINER = ALL;
Show the full grant list I used in my lab
SQL
EXEC DBMS_GOLDENGATE_AUTH.GRANT_ADMIN_PRIVILEGE(grantee => 'C##GGADMIN', container => 'ALL');
EXEC DBMS_GOLDENGATE_AUTH.GRANT_ADMIN_PRIVILEGE('C##GGADMIN', '*', grant_optional_privileges => '*');

GRANT INSERT ON system.logmnr_restart_ckpt$ TO c##ggadmin CONTAINER = ALL;
GRANT UPDATE ON streams$_capture_process TO c##ggadmin CONTAINER = ALL;
GRANT BECOME USER TO c##ggadmin CONTAINER = ALL;
GRANT CONNECT, RESOURCE TO c##ggadmin CONTAINER = ALL;
GRANT SELECT ANY DICTIONARY, SELECT ANY TABLE, SELECT ANY TRANSACTION TO c##ggadmin CONTAINER = ALL;
GRANT CREATE TABLE, CREATE ANY TABLE, ALTER ANY TABLE, DROP ANY TABLE TO c##ggadmin CONTAINER = ALL;
GRANT INSERT ANY TABLE, UPDATE ANY TABLE, DELETE ANY TABLE, LOCK ANY TABLE TO c##ggadmin CONTAINER = ALL;
GRANT FLASHBACK ANY TABLE TO c##ggadmin CONTAINER = ALL;
GRANT EXECUTE ON dbms_flashback TO c##ggadmin CONTAINER = ALL;
GRANT EXECUTE ON utl_file TO c##ggadmin CONTAINER = ALL;
GRANT ALTER SYSTEM TO c##ggadmin CONTAINER = ALL;

-- and in each PDB involved
EXEC DBMS_GOLDENGATE_AUTH.GRANT_ADMIN_PRIVILEGE('C##GGADMIN');

This is far more than GoldenGate needs — fine in a lab, but in production grant only what's required for your Extract and Replicat. DBMS_STREAMS_AUTH, used in older guides, belongs to the desupported Oracle Streams and isn't needed.

3Add the Credential Alias in GoldenGate

In the GoldenGate 21c Administration Service, open the menu and go to Configuration, then click + next to Credentials:

Without a tnsnames.ora entry, give the user ID with a full connect descriptor (or an EZConnect string like c##ggadmin@ol8doct01.scslabs.com:1522/CDB19C):

USER ID
C##GGADMIN@(DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=ol8doct01.scslabs.com)(PORT=1522))(CONNECT_DATA=(SERVER=DEDICATED)(SERVICE_NAME=CDB19C)))
