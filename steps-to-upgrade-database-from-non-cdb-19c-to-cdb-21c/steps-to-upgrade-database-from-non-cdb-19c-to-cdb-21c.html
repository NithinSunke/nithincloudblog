Steps to Upgrade a Non-CDB 19c Database to a CDB 21c PDB

By Sunke Nithin · May 25, 2024   DatabaseOracleUpgradeMigration

In this post we upgrade a 19c non-container database (ncdb19c) to Oracle 21c and, in the same run, plug it into an existing 21c container database (cdb21c) as a new PDB. AutoUpgrade does both jobs — the upgrade and the non-CDB-to-PDB conversion — from one config file.

download autoupgrade.jar→config file→analyze→deploy→verify PDB

0Assumptions

  1. A non-CDB database ncdb19c is already running on 19c.
  2. A fresh 21c Oracle home is installed (/u01/app/oracle/product/21c/dbhome_1).
  3. A container database cdb21c has already been created in the 21c home. It's the target the non-CDB will be plugged into.
Take a full backup first. Once the non-CDB is converted into a PDB it can't be opened as a 19c non-CDB again. AutoUpgrade creates a guaranteed restore point during the run, but after the plug-in step the reliable way back is your RMAN backup.
21c is an innovation release with a short support window. For production, Oracle's long-term releases are 19c and 23ai (now Oracle AI Database 26ai). The steps below are the same for those targets: point target_home at the new home and set target_version to match.

1Get the Latest autoupgrade.jar

Download the latest autoupgrade.jar from MOS note 2485457.1 and replace the copy in the 21c home. If you don't have MOS access, skip this step and use the version that ships with the home.

BASH
cd /u01/app/oracle/product/21c/dbhome_1/rdbms/admin
mv autoupgrade.jar autoupgrade.jar_25052024
mv /nfsshare/oracle/soft/autoupgrade.jar .

2Create the Config File

Generate a sample config file:

BASH
/u01/app/oracle/product/21c/dbhome_1/jdk/bin/java -jar \
  /u01/app/oracle/product/21c/dbhome_1/rdbms/admin/autoupgrade.jar \
  -create_sample_file config /nfsshare/oracle/pre_upgrade/config.txt full

Created sample configuration file /nfsshare/oracle/pre_upgrade/config.txt

Edit the entries you need and save the result as /nfsshare/oracle/upgrade/ncdb19c.cfg, the file used in the next steps:

NCDB19C.CFG
global.autoupg_log_dir=/u01/app/oracle/cfgtoollogs/autoupgrade
upg1.log_dir=/nfsshare/oracle/upgrade/ncdb19c
upg1.sid=ncdb19c
upg1.source_home=/u01/app/oracle/product/19.0.0/dbhome_1
upg1.target_home=/u01/app/oracle/product/21c/dbhome_1
upg1.target_cdb=cdb21c
upg1.target_pdb_name=ncdb19c
upg1.start_time=NOW
upg1.upgrade_node=ol7_19_vagrant.scslabs.com
#upg1.run_utlrp=yes
upg1.timezone_upg=yes
upg1.target_version=21
ParameterWhat it does
target_cdbThe 21c CDB to plug the upgraded database into. Setting it is what triggers the non-CDB-to-PDB conversion.
target_pdb_nameThe name the new PDB gets in the CDB.
upgrade_nodeThe host to run on. Default is localhost.
timezone_upgAlso upgrades the time zone file.
start_timeNOW starts the job straight away.
By default AutoUpgrade plugs the database in using its existing datafiles (no copy), so the conversion is fast but the original files now belong to the PDB. To keep the source files untouched, set upg1.target_pdb_copy_option=file_name_convert=NONE (OMF) or a file_name_convert pair. That copies the datafiles, so you need the extra space.

3Run AutoUpgrade in Analyze Mode

Analyze mode only checks the database. It changes nothing and needs no downtime.

BASH
/u01/app/oracle/product/21c/dbhome_1/jdk/bin/java -jar \

4Run AutoUpgrade in Deploy Mode

Downtime starts here. Deploy mode shuts the source database down, upgrades it and converts it to a PDB.
BASH
/u01/app/oracle/product/21c/dbhome_1/jdk/bin/java -jar \
  /u01/app/oracle/product/21c/dbhome_1/rdbms/admin/autoupgrade.jar \
  -config /nfsshare/oracle/upgrade/ncdb19c.cfg -mode deploy

5Validate the New PDB

Connect to the 21c CDB as SYSDBA (ss here is a shell alias for sqlplus / as sysdba) and check the PDBs:

SQL
SQL*Plus: Release 21.0.0.0.0 - Production on Sat May 25 00:26:56 2024
Version 21.3.0.0.0

Connected to:
Oracle Database 21c Enterprise Edition Release 21.0.0.0.0 - Production

SQL> show pdbs

    CON_ID CON_NAME                       OPEN MODE  RESTRICTED
---------- ------------------------------ ---------- ----------
         2 PDB$SEED                       READ ONLY  NO
         3 PDB1                           READ WRITE NO
         4 NCDB19C                        READ WRITE NO

NCDB19C is now a PDB in cdb21c, open READ WRITE and not restricted. A few more checks are worth running inside the PDB:

SQL
ALTER SESSION SET CONTAINER = NCDB19C;

-- components should all be VALID
SELECT comp_id, version, status FROM dba_registry;

-- no invalid objects left behind
SELECT COUNT(*) FROM dba_objects WHERE status = 'INVALID';

-- any plug-in issues still open
SELECT type, message FROM pdb_plug_in_violations
 WHERE name = 'NCDB19C' AND status <> 'RESOLVED';

-- keep the PDB open after a CDB restart
ALTER PLUGGABLE DATABASE NCDB19C SAVE STATE;
After the upgrade, update your tnsnames.ora entries and application connection strings to use the PDB's service name (ncdb19c) on the 21c listener. Once you're happy with the result, back up the CDB.
