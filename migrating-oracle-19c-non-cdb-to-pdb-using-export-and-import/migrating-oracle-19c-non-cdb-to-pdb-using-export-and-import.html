Migrating Oracle 19c Non-CDB to PDB Using Export and Import

By Sunke Nithin · August 18, 2025   DatabaseOracleMigration

The most flexible way to move a non-CDB into a PDB is a logical copy with Data Pump: export from the non-CDB, import into a new PDB. It works across versions, platforms and character sets, lets you pick schemas and transform data — at the cost of the longest downtime of all the methods, since the whole database is unloaded and reloaded.

1Create Directory Objects

SQL
-- in the source non-CDB
CREATE OR REPLACE DIRECTORY dpump_dir AS '/u01/app/oracle/dpump';

-- in the target PDB (not the CDB root)
ALTER SESSION SET CONTAINER = ONCDB;
CREATE OR REPLACE DIRECTORY dpump_dir AS '/u01/app/oracle/dpump';

Data Pump's SYSTEM user has access to all directory objects; grant READ, WRITE if you use another DBA account.

2Export the Non-CDB

PARFILE
# export.par
DIRECTORY=dpump_dir
DUMPFILE=noncdb_export_%U.dmp
LOGFILE=noncdb_export.log
FULL=Y
FLASHBACK_TIME=SYSTIMESTAMP
PARALLEL=4
METRICS=YES
BASH
expdp system parfile=export.par      # prompts for the password

FLASHBACK_TIME=SYSTIMESTAMP makes the export consistent to one point in time — without it, tables are exported at different moments. Stop application changes before you start if you need everything up to cutover. Check noncdb_export.log for errors.

3Move the Dump Files

BASH
scp /u01/app/oracle/dpump/noncdb_export_*.dmp oracle@targethost:/u01/app/oracle/dpump/
# check sizes / checksums on both sides
sha256sum /u01/app/oracle/dpump/noncdb_export_*.dmp

4Create the Target PDB

SQL
CREATE PLUGGABLE DATABASE ONCDB ADMIN USER pdb_admin IDENTIFIED BY "<password>";
ALTER PLUGGABLE DATABASE ONCDB OPEN;
ALTER PLUGGABLE DATABASE ONCDB SAVE STATE;

Create the tablespaces the source uses (or let the import create them, if the data file paths make sense on the target — use REMAP_DATAFILE otherwise).

5Import into the PDB

PARFILE
# import.par
DIRECTORY=dpump_dir
DUMPFILE=noncdb_export_%U.dmp
LOGFILE=noncdb_import.log
FULL=Y
PARALLEL=4
METRICS=YES
BASH
impdp system@ONCDB parfile=import.par

Connect to the PDB's service, not the CDB root. A full import reports errors for objects that already exist in any database (e.g. ORA-31684 for TEMP, system users, some Oracle-maintained objects) — those are expected; review everything else.

6Validate and Clean Up

SQL
@?/rdbms/admin/utlrp.sql
SQL
-- compare with the same query on the source
SELECT owner, object_type, COUNT(*)
  FROM dba_objects
 WHERE oracle_maintained = 'N'
 GROUP BY owner, object_type
 ORDER BY owner, object_type;

SELECT owner, object_name, object_type
  FROM dba_objects
 WHERE status = 'INVALID' AND oracle_maintained = 'N';

Add a TNS entry for the PDB's service:

TNS
ONCDB =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = targethost)(PORT = 1521))
    (CONNECT_DATA =
      (SERVER = DEDICATED)
      (SERVICE_NAME = ONCDB)
    )
  )

Gather statistics, back up the CDB, and drop the old non-CDB only after the applications have been running on the PDB for a while.

When to Choose Export/Import

  • Small or medium databases where a few hours' outage is acceptable
  • Changing platform, character set or version at the same time
  • Moving only some schemas, or reorganising storage on the way

For large databases or short outages, look at refreshable clones or M5 below.
