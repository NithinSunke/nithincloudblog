Migrating Oracle Non-CDB to PDB with AutoUpgrade Using Refreshable Clones

By Sunke Nithin · August 18, 2025   DatabaseOracleMigration

The non-CDB architecture is desupported from Oracle Database 21c, so every non-CDB eventually has to become a PDB. AutoUpgrade can do this with a refreshable clone PDB: it clones the non-CDB over a database link while the source stays online, keeps the clone in sync, and at a time you choose does a final refresh and converts it. Downtime is only that final refresh and the conversion.

This follows Daniel Overby Hansen's OUGN 2023 presentation, Migrate to Multitenant with Refreshable Clones Using AutoUpgrade. My lab: 19c non-CDB ONCDB → 19c CDB O19TC on the same server.

1Get the Latest AutoUpgrade

Download the newest autoupgrade.jar from My Oracle Support (Doc ID 2485457.1) — refreshable-clone support improves with each release. I used 25.4.

2Prepare the Source and the Database Link

The source must be in ARCHIVELOG mode (the clone is refreshed from redo). Create a user for the link:

SQL
-- on the source non-CDB
CREATE USER dblinkuser IDENTIFIED BY "<password>";
GRANT CREATE SESSION, CREATE PLUGGABLE DATABASE, SELECT_CATALOG_ROLE TO dblinkuser;
GRANT READ ON sys.enc$ TO dblinkuser;
SQL
-- on the target CDB (root)
CREATE DATABASE LINK CLONEPDB
  CONNECT TO dblinkuser IDENTIFIED BY "<password>"
  USING 'noncdb-alias';

SELECT sysdate FROM dual@CLONEPDB;
Give dblinkuser a profile without IDLE_TIME — if the session is killed for being idle, the refresh fails.

3Create the AutoUpgrade Config File

CFG
global.autoupg_log_dir=/home/oracle/mig/logs
upg1.log_dir=/home/oracle/mig/logs/upg1
upg1.source_home=/u01/app/oracle/product/19.0.0/dbhome_2
upg1.target_home=/u01/app/oracle/product/19.0.0/dbhome_1
upg1.sid=ONCDB
upg1.target_cdb=O19TC
upg1.source_dblink.ONCDB=CLONEPDB
upg1.target_pdb_name.ONCDB=ONCDB
upg1.refreshable_pdb=yes
upg1.start_time=18/08/2025 07:45:00
upg1.run_utlrp=yes
upg1.target_pdb_copy_option.ONCDB=file_name_convert=('/u02/oradata/ONCDB/', '/u02/oradata/O19TC/ONCDB/')
ParameterMeaning
source_dblink.ONCDBClone over this database link instead of plugging in the files
refreshable_pdb=yesCreate the clone as a refreshable PDB and keep refreshing it
start_timeThe cutover: when AutoUpgrade stops refreshing, does a final refresh and converts the PDB. Until then the source stays in use
target_pdb_copy_optionWhere the clone's data files go
Correction: my original file had target_pdb_name.ONCDB=O19TC — the CDB's name. The PDB name should be ONCDB (as the result below shows).

4Analyze

BASH
$ORACLE_HOME/jdk/bin/java -jar /home/oracle/mig/autoupgrade.jar -config /home/oracle/mig/autoupgrade_refresh.cfg -mode analyze

Review /home/oracle/mig/logs/cfgtoollogs/upgrade/auto/status/status.html and fix anything it flags.

5Deploy

BASH
$ORACLE_HOME/jdk/bin/java -jar /home/oracle/mig/autoupgrade.jar -config /home/oracle/mig/autoupgrade_refresh.cfg -mode deploy

AutoUpgrade creates the clone (CLONEPDB) and refreshes it (REFRESHPDB) until start_time. Leave the AutoUpgrade session running. To move the cutover, use proceed -job <n> -newdate <time> at the upg> prompt. At cutover — stop the applications first — it does the final refresh, runs noncdb_to_pdb.sql, and opens the PDB:

6Validate

Then point the applications at the new PDB's service, take a full backup of the CDB, and keep the source non-CDB (untouched by this method) until you're sure you won't fall back.

Pros and Cons

ProsCons
Minimal downtime — the source stays online while the clone syncsNeeds space for a full copy and network bandwidth for the clone
AutoUpgrade automates clone, refresh and conversionMissing archive logs or a killed idle link session interrupt the refresh
The source remains intact for fallbackSource and target must be the same endian format

Best Practices

  • Keep recent backups of both databases, and run analyze first.
  • Large databases: throttle the clone so it doesn't saturate the network.
  • Data Guard: decide how the target CDB's standbys handle the new PDB (manage_standbys_clause, e.g. standbys=none and re-create it on the standby later).
  • Leave COMPATIBLE at the default (19.0.0).
  • If you hit an ORA-600 [4293] during refresh, raise it with Oracle Support.
