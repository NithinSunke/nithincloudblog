Steps to Add New Tables to Ongoing GoldenGate Replication

By Sunke Nithin · June 25, 2024   ReplicationOracleGoldengate

Replication is already running for HR.EMPLOYEES, and now HR.CUSTOMERS needs to join it — without rebuilding anything. The pattern is the same as the original setup, just for one table: start capturing it, copy the existing rows with an initial load, then add it to the running Replicat.

add to Extract→initial load Extract→create target table→initial load Replicat→add to Replicat→validate
ProcessTypeTrailRole
EMP_EXTIntegrated Extract (existing)AAOngoing capture — CUSTOMERS added
EMPTParallel Replicat, integrated (existing)AAOngoing apply — CUSTOMERS added
CUSTILInitial Load Extract (new)ILReads the existing CUSTOMERS rows
CUTILParallel Replicat, nonintegrated (new)ILLoads them into the target

0Assumptions

  • GoldenGate 21c is running, with replication already set up — see Replicate tables with GoldenGate 21c.
  • Schema-level trandata is on for HRDB.HR, so new tables in the schema are already supplementally logged. If you only added trandata per table, run ADD TRANDATA HRDB.HR.CUSTOMERS first.

The source table has 10 rows to start with:

1Add the Table to the Extract

Open the running Extract EMP_EXT, go to Parameters, click the pencil icon and add the table:

EMP_EXT.PRM
EXTRACT emp_ext
USERIDALIAS ggadmin_cdb19c DOMAIN OracleGoldenGate
EXTTRAIL AA

SOURCECATALOG HRDB
TABLE HR.EMPLOYEES;
TABLE HR.CUSTOMERS;

Apply and restart the Extract so it picks up the change. From now on, every change to CUSTOMERS goes into trail AA. To test, I inserted 10 more rows on the source — the Extract statistics show them:

2Create the Initial Load Extract

Add an Extract of type Initial Load Extract, named CUSTIL, writing to trail IL:

CUSTIL.PRM
EXTRACT CUSTIL
USERIDALIAS ggadmin_cdb19c DOMAIN OracleGoldenGate
EXTFILE IL

SOURCECATALOG HRDB
TABLE HR.CUSTOMERS;

Start it. It reads all 20 rows now in the table:

3Create the Target Table

SQL · TARGET
CREATE TABLE customers (
    customer_id   NUMBER GENERATED BY DEFAULT AS IDENTITY,
    first_name    VARCHAR2(50),
    last_name     VARCHAR2(50) NOT NULL,
    email         VARCHAR2(100) UNIQUE NOT NULL,
    phone_number  VARCHAR2(15),
    address       VARCHAR2(200),
    city          VARCHAR2(100),
    state         VARCHAR2(50),
    zip_code      VARCHAR2(20),
    created_at    DATE DEFAULT SYSDATE,
    PRIMARY KEY (customer_id)
);

4Create and Run the Initial Load Replicat

Add a Parallel Replicat → Nonintegrated named CUTIL, reading trail IL with the target credential:

CUTIL.PRM
REPLICAT CUTIL
USERIDALIAS ggadmin_ORCLPDB1 DOMAIN OracleGoldenGate
MAP HRDB.HR.CUSTOMERS, TARGET HR.CUSTOMERS;

Start CUTIL. When its statistics show all 20 rows applied, stop it:

5Add the Table to the Ongoing Replicat

Edit the parameters of the CDC Replicat EMPT and add a MAP for CUSTOMERS, then restart it:

EMPT.PRM
REPLICAT EMPT
USERIDALIAS ggadmin_ORCLPDB1 DOMAIN OracleGoldenGate
--HANDLECOLLISIONS
MAP HRDB.HR.EMPLOYEES, TARGET HR.EMPLOYEES;
MAP HRDB.HR.CUSTOMERS, TARGET HR.CUSTOMERS;
Watch the overlap. The 10 rows inserted in step 1 are in both trails: the CDC trail AA and the initial load. When EMPT reaches them it may hit ORA-00001 unique-constraint errors. Either uncomment HANDLECOLLISIONS until EMPT is past that point (then comment it out and restart), or avoid the overlap by noting the SCN the initial load ran at and filtering older changes for this table: MAP HRDB.HR.CUSTOMERS, TARGET HR.CUSTOMERS, FILTER (@GETENV('TRANSACTION','CSN') > <scn>);
In a busy system, stop EMPT before step 4 so it doesn't apply CUSTOMERS changes before the target table exists — or create the target table before adding the table to the Extract.

6Validate

Compare row counts on both sides:

30 rows on the source and 30 on the target — the table is in sync and part of ongoing replication.

For more than a row count, Oracle GoldenGate Veridata compares the data itself.
