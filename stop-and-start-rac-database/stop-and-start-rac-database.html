Stop and Start an Oracle RAC Database

By Sunke Nithin · July 4, 2019   DatabaseRacOracle

A quick reference for shutting down and starting up a two-node Oracle RAC (11g Release 2) cleanly — database first and clusterware last on the way down, and the reverse on the way up. Replace dbname, nodename1 and nodename2 with your own names.

Stop order
  1. Database
  2. ASM
  3. Node apps
  4. Clusterware (as root)
Start order
  1. Clusterware (as root)
  2. Database
  3. Check resources

Stop the RAC Database

0Set the environment oracle

Source the Grid profile, or use oraenv and point it at the local ASM instance:

BASH
. ./grid_env

# or
. oraenv
ORACLE_SID = [grid] ? +ASM1

1Stop the database oracle

BASH
srvctl stop database -d dbname -o immediate
srvctl status database -d dbname

This shuts down the instances on all nodes at once.

2Stop ASM oracle

BASH
srvctl stop asm -n nodename1 -f
srvctl stop asm -n nodename2 -f

srvctl status asm -n nodename1
srvctl status asm -n nodename2

3Stop node apps oracle

BASH
srvctl stop nodeapps -n nodename1 -f
srvctl stop nodeapps -n nodename2 -f

srvctl status nodeapps -n nodename1
srvctl status nodeapps -n nodename2

4Stop the clusterware root

Log in as root, source the Grid profile, then:

BASH · ROOT
crsctl stop cluster -all
crsctl check cluster -all
crsctl stop cluster -all stops the remaining cluster resources (ASM, listeners, VIPs and so on) on every node itself, so steps 2–3 are optional — doing them one by one just lets you see each layer go down. If the OCR and voting disks live in ASM, srvctl stop asm may refuse while the clusterware still needs it; in that case go straight to step 4.

Start the RAC Database

1Start the clusterware root

Log in as root and source the Grid profile:

BASH · ROOT
. /home/grid/grid_env

# or
. oraenv
ORACLE_SID = [root] ? +ASM1

crsctl start cluster -all     # starts cluster services on both nodes

This brings up ASM, the listeners and node apps on both nodes as well.

2Start the database oracle

Log in as oracle and source the profile (. ./grid_env):

BASH
srvctl start database -d dbname     # starts the instances on both nodes
srvctl status database -d dbname

3Check the cluster resources oracle

BASH
crsctl stat res -t

Every resource should show ONLINE on both nodes. (The older crs_stat -t -v does the same job but is deprecated in 11g R2.)

On 12c and later the same commands accept long-form options too — for example srvctl stop database -db dbname -stopoption immediate and srvctl stop asm -node nodename1. The short forms above still work.
