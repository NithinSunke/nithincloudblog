Clone an Oracle 19c PDB Using Refreshable Clones

By Sunke Nithin · June 9, 2024   DatabaseOracle

A refreshable PDB clone copies a pluggable database over a database link and can then be kept up to date by pulling in the source's redo — on demand or on a schedule. It's an easy way to keep a test copy current, or to prepare a migration copy and cut over with only a final refresh.

Source CDB / PDBCDB1 / O122V
Target CDB / new PDBcrac1d (RAC, ASM) / O122T

1Source: a Common User for Cloning

SQL
-- source CDB (CDB1), in CDB$ROOT
create user c##cloneuser identified by "<password>" container=all;
grant create session, create pluggable database, select_catalog_role
      to c##cloneuser container=all;

-- the source must be in archivelog mode with local undo
select log_mode from v$database;
select property_value from database_properties where property_name='LOCAL_UNDO_ENABLED';

The grants need container=all so they apply in the PDBs too. Hot cloning needs archivelog mode and local undo.

2Target: Net Entry and Database Link

TNSNAMES.ORA
CDB1 =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = ol7_19c_vagrant.scslabs.com)(PORT = 1521))
    (CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = cdb1))
  )
SQL
-- target CDB (crac1d), in CDB$ROOT
create database link cloneo122v
  connect to c##cloneuser identified by "<password>" using 'cdb1';
select * from dual@cloneo122v;

3Create the Refreshable Clone

Give it the final name straight away:

SQL
create pluggable database O122T from O122V@cloneo122v
  file_name_convert=('/u02/oradata/CDB1/18ED0CF355963BE9E0631901A8C07D5D','+DATA')
  parallel 3
  refresh mode manual;            -- or: refresh mode every 60 minutes

On ASM, file_name_convert to the disk group (or set db_create_file_dest and leave it out) and Oracle-managed names are used.

4Refresh When Needed

SQL
-- the PDB must be closed (mounted) to refresh
alter pluggable database O122T close immediate;
alter pluggable database O122T refresh;

-- look at the data between refreshes: open READ ONLY only
alter pluggable database O122T open read only;

A refreshable PDB can never be opened read write — that would break the chain of redo.

5Finish: Stop Refreshing and Open

SQL
-- final refresh, then make it an ordinary PDB (one-way)
alter pluggable database O122T close immediate;
alter pluggable database O122T refresh;
alter pluggable database O122T refresh mode none;
alter pluggable database O122T open;
alter pluggable database O122T save state;
show pdbs
OUTPUT
    CON_ID CON_NAME     OPEN MODE  RESTRICTED
---------- ------------ ---------- ----------
         2 PDB$SEED     READ ONLY  NO
         3 P19C1D       READ WRITE NO
         5 O122T        READ WRITE NO
Renaming a PDB (if you cloned it under the source name)
SQL
-- only if you created it under the source name and must rename it
alter pluggable database O122V close immediate;
alter pluggable database O122V open restricted;
alter session set container=O122V;
alter pluggable database rename global_name to O122T;
alter pluggable database close immediate;
alter pluggable database open;
