Implementation Steps for My Windows Server Homelab

By Sunke Nithin · May 6, 2025   LABLAB

The plan for my Windows Server homelab project: build a small company network from scratch — a domain controller, DNS, DHCP, Group Policy, file shares, Remote Desktop, a web server, backups and monitoring — the core of day-to-day Windows Server administration.

1Install Windows Server

  • Install on a physical machine or a VM (VMware, Hyper-V or Proxmox) — see Installing Windows Server 2016.
  • Patch it fully, give it a static IP and a proper name.

2Active Directory Domain Services

  • Add the AD DS role and promote the server to a domain controller, creating a new forest (e.g. corp.local, or better a subdomain of a domain you own such as ad.example.com), with DNS.
  • Create Organizational Units for departments (HR, IT, Sales), and users and groups in them — e.g. HR_Users, IT_Admins.
POWERSHELL
# Server 2012 and later: dcpromo is gone — use PowerShell (or Server Manager)
Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
Install-ADDSForest -DomainName "corp.local" -InstallDns

3DNS

  • Check the AD-integrated forward zone created by the promotion; add a reverse lookup zone.
  • Add forwarders for internet names and test with nslookup / Resolve-DnsName — see DNS Server on Windows Server.

4DHCP

  • Install the DHCP role (same server or another) and authorize it in AD.
  • Create a scope (e.g. 192.168.1.100–200) with router and DNS options; add reservations for printers and servers.
  • Turn off DHCP on the home router for that network so there's only one DHCP server.

5Group Policy

  • Create GPOs for password and lockout policy (in the Default Domain Policy or a fine-grained password policy), screen lock timeouts and drive mappings.
  • Link them to the right OUs and test on client machines with gpresult /r.

6File Server and Permissions

  • Create shares per department (HR_Shared, IT_Shared).
  • Grant access through groups: share permissions broad, NTFS permissions specific (Read, Modify).
  • Optionally set up folder redirection or roaming profiles.

7Remote Desktop Services

  • Enable Remote Desktop for admins; for user sessions install the RDS roles and configure RDS licensing (120-day grace period in a lab).

8Web Server (IIS)

  • Install IIS, host a simple site, and secure it with a certificate (from an internal CA such as AD CS, or Let's Encrypt for a public name).

9Backup and Disaster Recovery

  • Use Windows Server Backup (including System State for AD) on a schedule.
  • Test restores — including an authoritative restore of a deleted OU or user.

10Security and Monitoring

  • Microsoft Defender Antivirus, Windows Firewall rules, and separate admin accounts.
  • Event Viewer, Performance Monitor, and central event forwarding for health checks.
