Step-by-Step Guide: Chat with Your PDF Articles Using DeepSeek-R1 and Ollama on Windows 11

By Sunke Nithin · April 8, 2025   AILAB

This post builds a local "chat with your documents" app on Windows 11: point it at a folder of PDFs, ask questions, and the DeepSeek-R1 model running in Ollama answers from your own content. Everything runs on your machine — no cloud API, no data leaving the PC.

Training vs RAG: this doesn't actually train or fine-tune the model — that needs far more data, GPU time and tooling. It uses retrieval-augmented generation (RAG): the PDFs are split into chunks and indexed, the chunks most relevant to each question are found, and they're handed to the model along with the question. The model itself never changes, which is why adding a new PDF takes seconds rather than hours.
PDFs→chunk→embed (FAISS)→retrieve top-k→DeepSeek-R1 via Ollama→answer

2Install Ollama and Pull DeepSeek-R1

Download and install Ollama for Windows from ollama.com/download. It runs as a background service. Then pull the model:

POWERSHELL
ollama pull deepseek-r1:8b
ollama run deepseek-r1:8b "Say hello in one line"

The 8B model is a good fit for 16–32 GB of RAM. deepseek-r1:1.5b is lighter if your machine struggles; 14b and up give better answers if you have the hardware.

6Create the App

POWERSHELL
mkdir rag-system
cd rag-system

Save this as app.py. It loads every PDF in a folder, builds the index once (cached), and answers questions from the most relevant passages:

APP.PY
import os
import streamlit as st
from langchain_community.document_loaders import PDFPlumberLoader
from langchain_community.vectorstores import FAISS
from langchain_experimental.text_splitter import SemanticChunker
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_ollama import OllamaLLM

st.title("📄 Chatbot with homelab knowledge base")

# ===== Sidebar =====
with st.sidebar:
    st.header("Configuration")
    pdf_folder = st.text_input("PDF folder path", value=r"D:\Nithin\aitraning")
    top_k = st.slider("Number of passages to use", 1, 5, 3)
    model = st.text_input("Ollama model", value="deepseek-r1:8b")

# ===== Build the index once per folder (cached) =====
@st.cache_resource(show_spinner="Reading and indexing PDFs...")
def build_index(folder):
    docs = []
    for name in os.listdir(folder):
        if name.lower().endswith(".pdf"):
            docs.extend(PDFPlumberLoader(os.path.join(folder, name)).load())
    embeddings = HuggingFaceEmbeddings()          # all-mpnet-base-v2, runs locally
    chunks = SemanticChunker(embeddings).split_documents(docs)
    return FAISS.from_documents(chunks, embeddings)

index = build_index(pdf_folder)
llm = OllamaLLM(model=model)

# ===== Chat =====
question = st.text_input("Ask about your PDFs:", placeholder="Type your question here...")
if st.button("Submit") and question:
    with st.spinner("Searching your documents..."):
        passages = index.similarity_search(question, k=top_k)
        context = "\n\n".join(p.page_content for p in passages)
        prompt = (
            "Answer the question using only the context below. "
            "If the answer is not in the context, say you don't know.\n\n"
            f"Context:\n{context}\n\nQuestion: {question}"
        )
        answer = llm.invoke(prompt)

    st.subheader("Answer")
    st.write(answer)
    with st.expander("See relevant passages"):
        for i, p in enumerate(passages, 1):
            src = os.path.basename(p.metadata.get("source", ""))
            st.markdown(f"**{i}. {src}** (page {p.metadata.get('page', 'N/A')})")
            st.write(p.page_content[:500] + "...")
How it works
  • Load: PDFPlumberLoader reads each PDF page by page.
  • Chunk: SemanticChunker splits the text into passages at natural topic boundaries.
  • Index: each chunk is turned into an embedding vector and stored in FAISS. @st.cache_resource keeps the index in memory, so it's only built once per folder.
  • Answer: the top-k most similar passages are put into the prompt, and DeepSeek-R1 answers from them.

7Run It

POWERSHELL
conda activate rag
streamlit run app.py --server.fileWatcherType none
The torch.classes RuntimeError in that output comes from Streamlit's file watcher inspecting PyTorch. It's harmless, and --server.fileWatcherType none stops it appearing. The Chain.__call__ deprecation warning came from the older version of the script; the version above doesn't use chains.

Your browser opens http://localhost:8501. The first run takes a while as it downloads the embedding model and indexes the PDFs; after that, questions come back in seconds (or a minute or so on CPU):

DeepSeek-R1 answering from my homelab notes.

DeepSeek-R1 is a reasoning model, so its answer starts with its thinking inside <think>…</think>. To hide that, strip it before displaying: answer = answer.split("</think>")[-1].strip().

Tips

  • Added new PDFs? Restart the app, or clear the cache from Streamlit's menu, so the index is rebuilt.
  • Scanned PDFs (images of pages) have no text to extract — run them through OCR first.
  • Better answers: try a bigger model, raise top-k to give it more context, or swap in a stronger embedding model, e.g. HuggingFaceEmbeddings(model_name="BAAI/bge-base-en-v1.5").
