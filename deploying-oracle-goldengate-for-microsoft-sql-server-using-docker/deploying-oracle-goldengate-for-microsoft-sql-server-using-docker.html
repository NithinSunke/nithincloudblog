Deploying Oracle GoldenGate for Microsoft SQL Server Using Docker

By Sunke Nithin · August 11, 2025   ReplicationGoldengateDockerMSSQL

Oracle publishes a ready-made container of GoldenGate for SQL Server (Free edition) on the Oracle Container Registry. With Docker Compose you get a full GoldenGate Microservices deployment — Service Manager, Administration Server, web UI behind Nginx — in a few minutes, ideal for a POC or LAB of SQL Server replication.

Prerequisites

  • Docker Engine with the Compose v2 plugin (see Install Docker on OEL 8)
  • An Oracle account for container-registry.oracle.com
  • A SQL Server instance to replicate from or to

1Create a Registry Auth Token

Since mid-2025 the Oracle Container Registry accepts only auth tokens, not account passwords, for docker login / podman login:

  1. Sign in at container-registry.oracle.com, open your profile menu → Auth Token.
  2. Generate Secret Key and copy it — it's shown only once. If lost, delete it and generate a new one.
  3. Find GoldenGate → goldengate-sqlserver-free and accept the licence terms if asked.

2Log In and Pull

BASH
# Oracle account e-mail as user name, the auth token as password
docker login container-registry.oracle.com
Username: <your-oracle-account-email>
Password: <auth-token>
Login Succeeded
BASH
docker pull container-registry.oracle.com/goldengate/goldengate-sqlserver-free:latest

3Docker Compose File

DOCKER-COMPOSE.YML
services:
  ogg-mssqlsrv:
    image: container-registry.oracle.com/goldengate/goldengate-sqlserver-free:latest
    container_name: ogg-mssqlsrv
    ports:
      - "8081:80"     # HTTP  (host:container)
      - "5443:443"    # HTTPS
    environment:
      OGG_ADMIN: oggadmin
      OGG_ADMIN_PWD: "<admin-password>"
      OGG_DEPLOYMENT: mssqlsrv
    volumes:
      - u02_data:/u02
      - u03_data:/u03
      - certs:/etc/nginx/cert
    restart: unless-stopped

volumes:
  u02_data:
  u03_data:
  certs:

/u02 holds the deployment configuration and /u03 the trail files — both on named volumes so they survive container rebuilds. Put your own certificate and key in the certs volume to replace the self-signed one.

4Start It

BASH
docker compose up -d
[+] Running 5/5
 ✔ Network mssqlsrv_default    Created
 ✔ Volume "mssqlsrv_u03_data"  Created
 ✔ Volume "mssqlsrv_certs"     Created
 ✔ Volume "mssqlsrv_u02_data"  Created
 ✔ Container ogg-mssqlsrv      Started

docker compose logs -f        # wait until the deployment reports it is ready

5Open the Web UI

Browse to https://<host-ip>:5443 (or http://<host-ip>:8081) and log in with OGG_ADMIN / OGG_ADMIN_PWD. The Service Manager shows the mssqlsrv deployment; open its Administration Server to add database connections, Extracts and Replicats.

6Prepare SQL Server

GoldenGate captures from SQL Server through Change Data Capture:

SQL
-- on SQL Server, for the database you capture from
EXEC sys.sp_cdc_enable_db;
-- then add trandata / heartbeat from the GoldenGate UI or adminclient

The SQL Server Agent must be running for CDC. Then add a connection in the Administration Server and enable supplemental logging (TRANDATA) for the tables to replicate.

Useful Commands

BASH
docker compose ps             # status
docker compose logs -f        # follow logs
docker compose restart        # restart
docker compose down           # stop and remove the container (volumes are kept)
docker volume ls              # the persistent volumes

Before Using It Seriously

  • Use HTTPS only, with a proper certificate, and restrict ports 8081/5443 to admin networks with firewall rules.
  • Use a strong admin password, and don't keep it in a compose file under version control — use an .env file or Docker secrets.
  • The Free edition is for development and smaller workloads and has usage limits; check Oracle's licence terms before production use.
