Setting Up an Oracle 19c Physical Standby (Data Guard) with RMAN Active Duplicate

By Sunke Nithin · August 8, 2022   DatabaseOracleData Guard

This builds a physical standby database NPGRSB for the primary NPGR (Oracle 19.14 on RHEL 7) by copying it over the network with DUPLICATE ... FROM ACTIVE DATABASE — no backup files to move around.

Starting Point

  • Two servers with the OS and Oracle software installed: orstdbdvl01 (primary, database running) and orstsbdvl01 (software only).
  • DB_NAME = NPGR on both; DB_UNIQUE_NAME = NPGR on the primary and NPGRSB on the standby.

1Primary: Archive Log Mode and Force Logging

SQL
select log_mode, force_logging from v$database;
-- LOG_MODE must be ARCHIVELOG

alter database force logging;

2Primary: Initialization Parameters

SQL
alter system set log_archive_config='DG_CONFIG=(NPGR,NPGRSB)';
alter system set log_archive_dest_2='SERVICE=NPGRSB ASYNC NOAFFIRM VALID_FOR=(ONLINE_LOGFILES,PRIMARY_ROLE) DB_UNIQUE_NAME=NPGRSB';
alter system set log_archive_dest_state_2=ENABLE;
alter system set log_archive_format='%t_%s_%r.arc' scope=spfile;
alter system set remote_login_passwordfile=EXCLUSIVE scope=spfile;

-- for switchover / failover later
alter system set fal_server=NPGRSB;
alter system set standby_file_management=AUTO;
-- only if paths differ between the servers:
-- alter system set db_file_name_convert='/NPGRSB/','/NPGR/' scope=spfile;
-- alter system set log_file_name_convert='/NPGRSB/','/NPGR/' scope=spfile;

Parameters set with scope=spfile take effect after a restart. LOG_ARCHIVE_DEST_1 can stay at its default (the fast recovery area).

3Oracle Net on Both Servers

Same entries in $ORACLE_HOME/network/admin/tnsnames.ora on both:

TNSNAMES.ORA
NPGR =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = orstdbdvl01.snvcloud.com)(PORT = 1521))
    (CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = NPGR))
  )

NPGRSB =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = orstsbdvl01.snvcloud.com)(PORT = 1521))
    (CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = NPGRSB))
  )

4Primary: Standby Redo Logs

DUPLICATE creates standby redo logs on the standby; add them on the primary too, so it can become a standby after a switchover:

SQL
-- one more group than the online logs, same size as them (check v$log)
alter database add standby logfile thread 1 ('/u01/app/oracle/oradata/NPGR/standby_redo01.log') size 50M;
alter database add standby logfile thread 1 ('/u01/app/oracle/oradata/NPGR/standby_redo02.log') size 50M;
alter database add standby logfile thread 1 ('/u01/app/oracle/oradata/NPGR/standby_redo03.log') size 50M;
alter database add standby logfile thread 1 ('/u01/app/oracle/oradata/NPGR/standby_redo04.log') size 50M;

5Standby: Directories, Password File and Listener

BASH
mkdir -p /u01/app/oracle/oradata/NPGR
mkdir -p /u01/app/oracle/fast_recovery_area/NPGR
mkdir -p /u01/app/oracle/admin/NPGRSB/adump

# password file: copy from the primary and rename
scp orstdbdvl01:$ORACLE_HOME/dbs/orapwNPGR $ORACLE_HOME/dbs/orapwNPGRSB

The auxiliary instance only runs in NOMOUNT during the duplicate, so it can't register with the listener by itself — it needs a static entry in listener.ora. Add the matching NPGR_DGMGRL entry on the primary if you'll use the broker.

LISTENER.ORA
LISTENER =
  (DESCRIPTION_LIST =
    (DESCRIPTION =
      (ADDRESS = (PROTOCOL = TCP)(HOST = orstsbdvl01.snvcloud.com)(PORT = 1521))
      (ADDRESS = (PROTOCOL = IPC)(KEY = EXTPROC1521))
    )
  )

SID_LIST_LISTENER =
  (SID_LIST =
    (SID_DESC =
      (GLOBAL_DBNAME = NPGRSB)          # for RMAN duplicate (instance in NOMOUNT)
      (ORACLE_HOME = /h01/oracle/19cr3)
      (SID_NAME = NPGRSB)
    )
    (SID_DESC =
      (GLOBAL_DBNAME = NPGRSB_DGMGRL)   # for the Data Guard broker
      (ORACLE_HOME = /h01/oracle/19cr3)
      (SID_NAME = NPGRSB)
    )
  )

ADR_BASE_LISTENER = /h01/oracle

6Standby: Start the Auxiliary Instance

A one-line parameter file is enough; DUPLICATE replaces it with the primary's spfile.

BASH
export ORACLE_SID=NPGRSB
echo "DB_NAME=NPGR" > $ORACLE_HOME/dbs/initNPGRSB.ora
lsnrctl reload
sqlplus / as sysdba <<'EOF'
startup nomount
EOF

7Run the Duplicate

Connect with full connect strings for both instances (not OS authentication), and let RMAN prompt for the SYS password rather than putting it on the command line:

RMAN
rman target sys@npgr auxiliary sys@npgrsb      # prompts for the passwords

DUPLICATE TARGET DATABASE
  FOR STANDBY
  FROM ACTIVE DATABASE
  DORECOVER
  SPFILE
    SET db_unique_name='NPGRSB' COMMENT 'Is standby'
    SET log_archive_dest_2='SERVICE=NPGR ASYNC VALID_FOR=(ONLINE_LOGFILES,PRIMARY_ROLE) DB_UNIQUE_NAME=NPGR'
    SET fal_server='NPGR' COMMENT 'Is primary'
    SET audit_file_dest='/u01/app/oracle/admin/NPGRSB/adump'
  NOFILENAMECHECK;

8Start Redo Apply

SQL
alter database recover managed standby database disconnect from session;
-- to stop it:
-- alter database recover managed standby database cancel;

9Test Redo Transport

SQL
-- primary
alter session set nls_date_format='DD-MON-YYYY HH24:MI:SS';
select max(sequence#) from v$archived_log;
alter system switch logfile;
SQL
-- standby
select sequence#, first_time, next_time, applied
from   v$archived_log order by sequence#;

select process, status, sequence# from v$managed_standby;   -- MRP0 APPLYING_LOG
select name, value from v$dataguard_stats where name like '%lag%';

The new sequence should arrive on the standby and show APPLIED = YES within moments.
