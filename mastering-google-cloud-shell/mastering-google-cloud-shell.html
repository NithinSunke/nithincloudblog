Mastering Google Cloud Shell

By Sunke Nithin · August 9, 2025   CLOUDGCP

Google Cloud Shell is a free, browser-based terminal for Google Cloud. It runs on a temporary virtual machine with the Google Cloud CLI and common tools already installed and already signed in as you — nothing to install locally. Here's what it offers, how to start, and its limits.

Key Features

FeatureDetails
Pre-installed toolsgcloud, gsutil, bq, kubectl, terraform, plus git, vim, nano, Python, Node.js, Docker and more
Persistent home5 GB of persistent storage mounted as $HOME, kept between sessions
Built-in editorCloud Shell Editor, based on Code OSS (the open-source core of VS Code) — Open Editor or cloudshell edit <file>
Your identityRuns as your Google account, with your IAM permissions
Any projectSwitch with gcloud config set project <PROJECT_ID>
Web PreviewPreview a web app running on ports 8080 and others in the browser

Getting Started

  1. Sign in to the Google Cloud console.
  2. Click the Activate Cloud Shell icon at the top right.

Example Uses

Create a VM

BASH
gcloud compute instances create my-vm \
  --zone=us-central1-a \
  --machine-type=e2-micro \
  --image-family=debian-12 \
  --image-project=debian-cloud

Build infrastructure with Terraform

BASH
terraform init
terraform plan
terraform apply

Script routine tasks

Use gcloud, gsutil / gcloud storage and bq scripts for backups, exports and IAM changes — kept in $HOME so they're there next time.

Deploy a web app

BASH
git clone https://github.com/<you>/<app>.git && cd <app>
gcloud app deploy
gcloud app logs tail -s default

Use Web Preview to test the app locally before deploying.

Limits

From Google's Cloud Shell quotas and limits page:

LimitValue
Weekly usage50 hours per week (check under Session information → Usage quota)
Session length12 hours maximum; then start a new one
InactivityThe VM ends after 40 minutes of inactivity; anything outside $HOME is lost
Home directory5 GB; deleted if you don't use Cloud Shell for 120 days (you get an email first)
UseInteractive use only — no mining, scanning or long-running services
EditorCustom extensions can't be installed
Corrections: my original post said sessions end after 20 minutes idle and that Cloud Shell runs on an f1-micro VM. Google's documentation says 40 minutes, and doesn't specify the machine type. The weekly 50-hour quota is the limit people most often hit.

Cost

Cloud Shell itself is free. You pay only for the resources you create from it — VMs, databases, storage and so on.

Tips

TipWhy
Keep everything in $HOMEThe rest of the VM is reset when the session ends
Use ~/.customize_environmentA script that runs as root at every start — install extra packages there
Use aliasesSave frequently used commands and projects in ~/.bashrc (keep its Cloud Shell lines)
Don't store secretsAvoid service-account keys and API keys in your home directory; use your own identity or Secret Manager
SSH keys for GitSet up ~/.ssh for GitHub or GitLab
Several tabsOpen more terminal tabs with +
Move filescloudshell download <file>, or Upload/Download in the ⋮ menu

Conclusion

Cloud Shell is the quickest way to work with Google Cloud from anywhere — authenticated, tooled up and free. Keep its limits in mind, and it's ideal for learning, administration and quick deployments.
