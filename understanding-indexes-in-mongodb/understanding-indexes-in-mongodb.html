Understanding Indexes in MongoDB

By Sunke Nithin · August 25, 2025   DatabaseMongoDB

Indexes are critical for query performance in MongoDB. By creating efficient pathways to locate and retrieve data, they significantly reduce the time it takes to execute queries, especially on large datasets. This post explores what indexes are, how they work in MongoDB, the main types, and best practices for using them effectively.

1What is an Index in MongoDB?

An index is a data structure that speeds up data retrieval on a collection. It works much like the index in a book: MongoDB can jump straight to matching documents instead of scanning the whole collection. Indexes are stored separately from the data and map field values to document locations.

For example, if you frequently query a users collection by email, an index on email makes those queries much faster.

2Why Use Indexes?

Improved Query PerformanceFewer documents to scan means faster queries.
Efficient SortingSorts on indexed fields can use the index order directly.
Optimized FilteringFilters such as find({ age: 30 }) benefit from an index on the filtered field.
Reduced Resource UsageFaster queries mean less CPU and memory.

However, indexes come with trade-offs:

Storage OverheadIndexes consume additional disk space and memory.
Write PerformanceEvery insert, update or delete must also update the indexes, which slows writes.

3Types of Indexes in MongoDB

MongoDB supports several index types for different use cases. The most popular ones:

Single Field Index

Indexes one field in a collection:

MONGOSH
db.users.createIndex({ age: 1 })   // 1 for ascending, -1 for descending

Useful for queries that filter or sort on one field.

Compound Index

Indexes multiple fields in a specific order:

MONGOSH
db.users.createIndex({ city: 1, age: -1 })

Supports queries that filter on city, on city and age, or sort by these fields. A query on age alone cannot use it efficiently, because age is not the leading field.

Multikey Index

Indexes arrays, allowing efficient queries on array elements:

MONGOSH
db.products.createIndex({ tags: 1 })

Useful when documents contain arrays, like tags: ["electronics", "gadgets"]. MongoDB creates a multikey index automatically when the indexed field holds an array.

Text Index

Enables text search on string fields:

MONGOSH
db.articles.createIndex({ content: "text" })

Supports full-text search queries like:

MONGOSH
db.articles.find({ $text: { $search: "MongoDB tutorial" } })

Hashed Index

Indexes hashed values of a field — useful for sharding or equality-based queries:

MONGOSH
db.users.createIndex({ userId: "hashed" })

4Creating and Managing Indexes

TaskCommand
Create an index on emaildb.users.createIndex({ email: 1 })
List all indexes on a collectiondb.users.getIndexes()
Drop a specific indexdb.users.dropIndex({ email: 1 })
Drop all indexes (except the default _id index)db.users.dropIndexes()
MONGOSH
// Create an index
db.users.createIndex({ email: 1 })

// View indexes
db.users.getIndexes()

// Drop one index
db.users.dropIndex({ email: 1 })

// Drop all indexes except _id
db.users.dropIndexes()

5Best Practices for Indexes

  1. Index selectively: only index fields that are frequently queried or sorted, to minimize storage and write overhead.
  2. Use compound indexes wisely: order fields to match query patterns — fields used for equality filters first, then sort fields, then range filters.
  3. Monitor performance: use explain() to confirm queries use your indexes.
    MONGOSH
    db.users.find({ age: 30 }).explain("executionStats")
    Look for IXSCAN (index scan) rather than COLLSCAN (full collection scan), and compare totalDocsExamined with nReturned.
  4. Prefer selective fields: an index works best on fields with many distinct values. Indexing low-cardinality fields (for example a boolean status) on its own rarely helps, because each value still matches a large share of the collection.
  5. Consider the workload: balance read-heavy against write-heavy workloads. For write-heavy applications, keep the number of indexes small.
  6. Use covered queries: design indexes so a query can be answered entirely from the index, without reading the documents.

6Common Pitfalls

PitfallWhy it hurts
Over-indexingToo many indexes degrade write performance and increase storage.
Unused indexesThey waste resources. Review them regularly (for example with $indexStats) and remove the ones nothing uses.
Improper index orderIn compound indexes, field order matters. Make sure it matches your query patterns.
Text index limitationsText indexes are resource-intensive and don't support partial-word matches or complex regex queries.

7Use Cases for Indexes

  • E-commerce: index product fields like category or price for fast filtering and sorting.
  • Social media: index user IDs or post timestamps to quickly retrieve a user's posts or the most recent ones.
  • Analytics: use TTL indexes to expire temporary event data, or geospatial indexes for location-based analytics.
  • Search applications: text indexes for full-text search in blogs or articles.

Conclusion

Indexes are a powerful tool for optimizing MongoDB query performance, but they need careful planning to balance speed, storage and write overhead. Choose the right index types, follow the best practices above, use explain() to analyze your queries, and refer to the MongoDB indexes documentation for deeper insights.
