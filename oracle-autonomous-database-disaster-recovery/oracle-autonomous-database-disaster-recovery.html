Oracle Autonomous Database: Disaster Recovery

By Sunke Nithin · April 4, 2025   DatabaseOracleOCIADB

For critical applications, downtime isn't an option. Oracle Autonomous Database (ADB) gives you two disaster recovery (DR) designs — backup-based DR and Autonomous Data Guard — each available in the same region or another region. Here's how they compare, and how I added a cross-region peer and upgraded a local peer to Autonomous Data Guard from the OCI Console.

What Disaster Recovery Protects Against

  • Hardware or availability-domain failure
  • A region-wide outage
  • Cyberattacks and logical corruption (with point-in-time restore)
  • Natural disasters

The goal is to keep two numbers low: RTO (how long until you're running again) and RPO (how much data you can lose).

Correction: I originally wrote that Autonomous Data Guard can use synchronous or asynchronous redo transport — you don't choose. Oracle manages it; the RPO figures above are what you get. A local Autonomous Data Guard standby can fail over automatically (optionally with a data loss limit you set); cross-region switchover and failover are started by you.

Automatic Backups

Every ADB is backed up automatically to Object Storage. Retention is configurable from 1 to 60 days, and you can restore or clone to any point in time within the retention window. These backups are what backup-based DR uses.

Backup-Based DR in Practice

Use caseAction
Accidental table dropPoint-in-time clone, copy the table back
Region-level DR testCross-region clone or switchover to the backup copy
Monthly DR drillCreate a temporary clone and drop it afterwards
Cost-optimised DRBackup-based peer instead of a standby

Pros: the local copy is built in at no extra cost, flexible point-in-time restore, no standby database to pay for. Cons: a much higher RTO (restore time grows with database size), and a cross-region copy adds storage cost.

1How Backup-Based DR Works

Locally, the peer is a backup copy in the same region; cross-region, backups are replicated to the remote region and the database is restored there when you fail over:

2Add a Cross-Region Peer

Open the database, go to Disaster recovery. My primary is in India South (Hyderabad) and already has its local backup copy. Click Add peer database and choose the peer region — India West (Mumbai):

Choose the DR type. The console shows the RTO/RPO for each and the cost note for a cross-region backup copy; I chose backup-based:

This creates a cross-region backup-based peer in Mumbai.

3Upgrade the Local Peer to Autonomous Data Guard

For a lower RTO/RPO, change the local peer's DR type: select Autonomous Data Guard (RTO 2 minutes, RPO 10 seconds) — optionally with automatic failover and a data loss limit — and click Submit:

Follow the Enable Autonomous Data Guard work request until it succeeds:

The local peer's role changes from backup copy to Standby:

Final Thoughts

Every ADB already has local backup-based DR. Add a cross-region backup copy for cheap regional protection, and use Autonomous Data Guard — local, cross-region or both — when the application needs recovery in minutes. Test switchover regularly; it's one click and tells you whether your applications reconnect cleanly.
