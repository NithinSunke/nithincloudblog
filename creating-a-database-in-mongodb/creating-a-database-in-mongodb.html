Creating a Database in MongoDB

By Sunke Nithin · August 25, 2025   DatabaseMongoDB

In earlier posts we installed MongoDB on Oracle Enterprise Linux 8 (OEL 8) and connected to it using the shell and GUI. Now we'll walk through creating a database in MongoDB 8.0 Community Edition on OEL 8, adding a collection, and performing basic operations in the mongosh shell. We'll authenticate as the admin user (mongoadmin) created earlier.

1Prerequisites

  • MongoDB 8.0 Community Edition installed.
  • An admin user (mongoadmin) with a secure password and the readWriteAnyDatabase role.
  • The MongoDB service running (sudo systemctl status mongod).
  • mongosh installed (included with the mongodb-org package).
  • MongoDB Compass installed (optional, for a GUI).
  • For remote access: bindIp set in /etc/mongod.conf (e.g. 0.0.0.0) and port 27017 open in the firewall.
  • Basic familiarity with MongoDB concepts (databases, collections, documents).

2Creating a Database Using mongosh

MongoDB creates databases implicitly — there is no CREATE DATABASE command. A database comes into existence the first time you store data in it.

Step 1Connect to MongoDB

Connect as the mongoadmin user:

BASH
mongosh -u mongoadmin -p --authenticationDatabase admin

Enter the password when prompted. You'll see the admin> prompt.

Step 2Switch to the New Database

Switch to a new database (e.g. testdb). MongoDB creates it when data is first inserted:

MONGOSH
use testdb
show dbs

The use command switches to testdb. If it doesn't exist yet, it is only staged for creation.

Notice that testdb does not appear in show dbs yet. A database is only listed once it holds at least one collection with data.

Step 3Create a Collection and Insert Data

MongoDB stores data in collections (like tables in a relational database). Create a users collection simply by inserting a document into it:

MONGOSH
db.users.insertOne({
  name: "John Doe",
  email: "john.doe@example.com",
  role: "Developer",
  createdAt: new Date()
})
PartMeaning
db.usersThe users collection in the current database (testdb).
insertOne()Adds a single document (a JSON-like object).
ResultThe database and collection are created automatically on insertion.

Step 4Verify the Insertion

MONGOSH
db.users.find().pretty()

3Additional Operations

Insert Multiple Documents

You can insert several documents at once:

MONGOSH
db.users.insertMany([
  { name: "Alice Brown", email: "alice.brown@example.com", role: "Analyst" },
  { name: "Bob Wilson",  email: "bob.wilson@example.com",  role: "Designer" }
])

Query Data

MONGOSH
db.users.find()                              // all documents
db.users.find({ role: "Developer" })         // only developers
db.users.find({ role: "Developer" }).pretty()

Update Data

MONGOSH
db.users.updateOne(
  { email: "john.doe@example.com" },       // Query (filter)
  { $set: { role: "Senior Developer" } }   // Update action
)

updateOne() updates a single document that matches the filter:

  • If multiple documents match, only the first match is updated.
  • If no document matches, nothing happens.

Delete Data

MONGOSH
db.users.deleteOne({ email: "john.doe@example.com" })
PartMeaning
db.usersThe users collection in the current database.
deleteOne()Deletes a single document that matches the filter. If several match, only the first is deleted; if none match, nothing happens.
{ email: "john.doe@example.com" }The filter: delete the document whose email equals "john.doe@example.com".

4Best Practices

  • Use meaningful database and collection names (e.g. inventory, orders).
  • Index fields for faster queries, e.g. db.users.createIndex({ email: 1 }).
  • Back up data regularly using mongodump.
  • For production, enable TLS/SSL and restrict bindIp to trusted IPs.
bindIp: 0.0.0.0 makes MongoDB listen on every network interface. That's handy in a lab, but in production always pair it with authentication, a firewall and TLS — or bind only to specific addresses.

Conclusion

We created a MongoDB database (testdb) and a collection (users) on OEL 8 using mongosh, then inserted, queried, updated and deleted documents. The shell is well suited to automation. For advanced topics like indexing or backups, see the MongoDB documentation.
