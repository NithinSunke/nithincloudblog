Don't Allow Direct Root Login over SSH on Linux

By Sunke Nithin · April 16, 2025   LinuxLinuxSecurity

root exists on every Linux server, so it's the first account attackers try over SSH. Turn off direct root login: people log in with their own accounts and use sudo — that adds a second name an attacker has to guess, and every admin action is traceable to a person.

Before changing anything, make sure a normal user can log in and use sudo, and keep your current session open until you have tested a new one. Otherwise you can lock yourself out.

1Become Root and Back Up the Config

BASH
# log in as a normal user that has sudo, then
sudo -i
cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak

2Set PermitRootLogin no

Find the PermitRootLogin line in /etc/ssh/sshd_config (it may be commented out with #) and change it to:

SSHD_CONFIG
# /etc/ssh/sshd_config
PermitRootLogin no

Want root reachable only with an SSH key, e.g. for automation? Use PermitRootLogin prohibit-password instead.

3Check for Overrides and Syntax

BASH
# drop-in files override the main file on OL9 / RHEL9 / Ubuntu 22.04+
grep -ri permitrootlogin /etc/ssh/sshd_config /etc/ssh/sshd_config.d/ 2>/dev/null

sshd -t                          # syntax check - no output means OK
sshd -T | grep -i permitrootlogin
permitrootlogin no

sshd uses the first value it reads, and files in /etc/ssh/sshd_config.d/ are read first on newer distributions — a PermitRootLogin yes there wins. sshd -T shows the setting actually in effect.

4Restart sshd

BASH
systemctl restart sshd           # OL / RHEL / Rocky
systemctl restart ssh            # Ubuntu / Debian

5Test from Another Machine

OUTPUT
$ ssh root@server01
root@server01's password:
Permission denied, please try again.

Root is refused whether it uses a password or a key; your normal account still works.

Limit Who Can Log In At All

SSHD_CONFIG
# /etc/ssh/sshd_config - only these users / groups may log in over SSH
AllowUsers nsunke oracle
AllowGroups sshusers wheel
# DenyUsers / DenyGroups work the other way round

Only the listed users or members of the listed groups get in; everyone else is refused even with the right password. Test carefully — forgetting your own account here locks you out too.

Narrow sudo Rights

sudo doesn't have to mean full root. The value in brackets is the user the command runs as:

SUDOERS
# /etc/sudoers.d/nsunke   (edit with: visudo -f /etc/sudoers.d/nsunke)
# nsunke may run chown as the oracle user, and nothing else
nsunke  ALL=(oracle)  /usr/bin/chown nsunke *

# usage
sudo -u oracle /usr/bin/chown nsunke /home/oracle/oraclefile
