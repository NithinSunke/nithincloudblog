Mastering CRUD Operations in MongoDB

By Sunke Nithin · August 25, 2025   DatabaseMongoDB

MongoDB, a popular NoSQL database, is known for its flexibility in handling unstructured or semi-structured data. At the heart of working with MongoDB collections are CRUD operations: Create, Read, Update and Delete. This post walks through each operation with examples and best practices to help you master data manipulation in MongoDB.

What are CRUD Operations?

CCreateAdd new documents — insertOne(), insertMany()
RReadRetrieve documents — findOne(), find()
UUpdateModify documents — updateOne(), updateMany(), replaceOne()
DDeleteRemove documents — deleteOne(), deleteMany()

These operations are fundamental to any database system, and MongoDB provides a straightforward, powerful syntax for them. Let's explore each one with examples in the MongoDB shell.

Setting Up a Sample Collection

For the demonstration we'll use a users collection in a database named mydb. If you're following along, create the sample collection with a few documents:

MONGOSH
use mydb
db.users.insertMany([
  { _id: 1, name: "Alice",   age: 30, city: "New York" },
  { _id: 2, name: "Bob",     age: 25, city: "London" },
  { _id: 3, name: "Charlie", age: 35, city: "Paris" }
])

1Create Operations

Create operations add new documents to a collection, using insertOne() and insertMany().

Inserting a Single Document

MONGOSH
db.users.insertOne({
  _id: 4,
  name: "Diana",
  age: 28,
  city: "Tokyo"
})

Output: confirms the insertion with the document's _id.

Inserting Multiple Documents

MONGOSH
db.users.insertMany([
  { _id: 5, name: "Eve",   age: 22, city: "Sydney" },
  { _id: 6, name: "Frank", age: 40, city: "Berlin" }
])

Output: returns the inserted _id values.

Notes
  • If you don't specify an _id, MongoDB generates a unique ObjectId automatically.
  • Use insertOne() for single insertions and insertMany() for bulk operations to optimize performance.

2Read Operations

Read operations retrieve documents with findOne() and find().

The screenshots in this section also show an extra document — { _id: 7, name: "Alice", age: 33, city: "London" } — that was added in my test collection. If you only ran the inserts above, you won't see it in your results.

Finding a Single Document

MONGOSH
db.users.findOne({ name: "Alice" })

Output: the first matching document, e.g. { _id: 1, name: "Alice", age: 30, city: "New York" }.

Finding Multiple Documents

MONGOSH
db.users.find({ city: "London" })

Output: a cursor over all matching documents.

To make the output more readable, use pretty():

MONGOSH
db.users.find().pretty()
In the modern mongosh shell, results are already formatted, so pretty() makes no visible difference. It mattered in the legacy mongo shell.

Query Operators

MongoDB supports operators for more complex queries.

Comparison: $eq, $gt, $gte, $lt, $lte, $ne, $in

MONGOSH
db.users.find({ age: { $gt: 30 } })   // Users older than 30

Logical: $and, $or, $not, $nor

MONGOSH
db.users.find({ $or: [{ city: "Tokyo" }, { city: "Sydney" }] })
Notes
  • Use findOne() for single-document retrieval and find() for multiple documents.
  • Indexes on frequently queried fields (e.g. name or city) improve read performance.

3Update Operations

Update operations modify existing documents using updateOne(), updateMany() or replaceOne().

Updating a Single Document

MONGOSH
db.users.updateOne(
  { name: "Bob" },
  { $set: { age: 26, city: "Manchester" } }
)

Output: the number of documents matched and modified.

Updating Multiple Documents

MONGOSH
db.users.updateMany(
  { city: "New York" },
  { $set: { country: "USA" } }
)

Replacing a Document

To replace an entire document (everything except _id):

MONGOSH
db.users.replaceOne(
  { name: "Diana" },
  { name: "Diana", age: 29, city: "Osaka", country: "Japan" }
)
With replaceOne(), any field you leave out of the new document is removed. Use $set when you only want to change some fields.

Update Operators

OperatorWhat it doesExample
$setSets specific fields{ $set: { city: "Leeds" } }
$incIncrements a numeric field{ $inc: { age: 1 } }
$pushAdds an element to an array{ $push: { hobbies: "reading" } }
Notes
  • Use $set to avoid overwriting fields unintentionally.
  • Make sure indexes exist for the fields used in update filters, to optimize performance.

4Delete Operations

Delete operations remove documents using deleteOne() or deleteMany().

Deleting a Single Document

MONGOSH
db.users.deleteOne({ name: "Frank" })

Output: the number of documents deleted.

Deleting Multiple Documents

MONGOSH
db.users.deleteMany({ city: "Paris" })
Be careful
  • deleteMany() can remove large numbers of documents — and deleteMany({}) removes every document in the collection.
  • Deleted documents cannot be recovered unless you have a backup, or the delete ran inside a transaction that you abort before committing.
Tip: run the same filter with find() first to see exactly what will be deleted.

Best Practices for CRUD Operations

  • Use indexes: create indexes on fields used in queries to speed up finds, updates and deletes.
    MONGOSH
    db.users.createIndex({ name: 1 })
  • Validate data: use MongoDB's schema validation to enforce data integrity on inserts and updates.
  • Batch operations: for bulk inserts or updates, use insertMany() or updateMany() to reduce network overhead.
  • Check results: inspect the output of each operation (e.g. matchedCount, modifiedCount) to confirm it did what you expected.
  • Use transactions: for multi-document operations that must stay consistent, use transactions.
  • Test queries: use explain() to analyze query performance and confirm indexes are used:
    MONGOSH
    db.users.find({ city: "Tokyo" }).explain("executionStats")

Conclusion

CRUD operations are the backbone of working with MongoDB, letting you create, read, update and delete data efficiently. Master them and follow the best practices above, and you can build robust, performant applications. Try the examples in a MongoDB shell or an Atlas cluster, and see the MongoDB CRUD documentation for advanced features like aggregation pipelines and change streams.
