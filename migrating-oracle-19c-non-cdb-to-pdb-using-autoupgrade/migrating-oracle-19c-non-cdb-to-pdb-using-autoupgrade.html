Migrating Oracle 19c Non-CDB to PDB Using AutoUpgrade

By Sunke Nithin · August 18, 2025   DatabaseOracleMigration

AutoUpgrade can convert a non-CDB into a PDB of an existing CDB in one job: it checks the database, creates the manifest, plugs it in, runs noncdb_to_pdb.sql, and recompiles. Here a 19c non-CDB ONCDB becomes a PDB in the 19c CDB O19TC on the same server.

1Get AutoUpgrade

Download the latest autoupgrade.jar from My Oracle Support (Doc ID 2485457.1). It runs with the JDK in any 19c home.

2Create the Config File

BASH
$ORACLE_HOME/jdk/bin/java -jar /home/oracle/mig/autoupgrade.jar -create_sample_file settings noncdbtopdb.cfg

Edit it:

CFG
global.autoupg_log_dir=/home/oracle/mig/logs
upg1.log_dir=/home/oracle/mig/logs/upg1
upg1.source_home=/u01/app/oracle/product/19.0.0/dbhome_2
upg1.target_home=/u01/app/oracle/product/19.0.0/dbhome_1
upg1.sid=ONCDB
upg1.target_cdb=O19TC
upg1.target_pdb_name=ONCDB
upg1.start_time=NOW
upg1.run_utlrp=yes
upg1.target_pdb_copy_option=file_name_convert=('/u02/oradata/ONCDB/', '/u02/oradata/O19TC/ONCDB/')
ParameterMeaning
source_home / target_homeThe non-CDB's home and the CDB's home (both 19c here — a conversion without an upgrade)
sidThe non-CDB to convert
target_cdb / target_pdb_nameWhere it goes and what the PDB is called
target_pdb_copy_optionCopy the data files to a new location. Without it, the PDB reuses the source files in place (NOCOPY) — faster, but the non-CDB can't be used again

3Analyze

BASH
$ORACLE_HOME/jdk/bin/java -jar /home/oracle/mig/autoupgrade.jar -config noncdbtopdb.cfg -mode analyze

Review /home/oracle/mig/logs/cfgtoollogs/upgrade/auto/status/status.html.

4Deploy

This is the outage: AutoUpgrade shuts the non-CDB down, plugs it in and converts it. Stop the applications first.

BASH
$ORACLE_HOME/jdk/bin/java -jar /home/oracle/mig/autoupgrade.jar -config noncdbtopdb.cfg -mode deploy

At the upg> prompt, lsj lists jobs and status -job 101 shows the stages. In my lab the NONCDBTOPDB stage took about 8 minutes.

5Verify

6Post-Migration Tasks

Back up the CDB right away — the old non-CDB backups can't be used to restore the new PDB:

RMAN
rman target /
BACKUP DATABASE PLUS ARCHIVELOG;

Update tnsnames.ora — the PDB's service has the PDB name:

TNS
ONCDB =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = localhost)(PORT = 1521))
    (CONNECT_DATA =
      (SERVER = DEDICATED)
      (SERVICE_NAME = ONCDB)
    )
  )

When you no longer need the old non-CDB (with the copy option its files are still there), drop it:

SQL
-- connected to the old non-CDB instance
SHUTDOWN IMMEDIATE;
STARTUP MOUNT RESTRICT;
DROP DATABASE;
DROP DATABASE requires the database mounted in restricted mode — a plain STARTUP MOUNT, as I originally wrote, gives ORA-12719. Make sure you're connected to the right instance.
