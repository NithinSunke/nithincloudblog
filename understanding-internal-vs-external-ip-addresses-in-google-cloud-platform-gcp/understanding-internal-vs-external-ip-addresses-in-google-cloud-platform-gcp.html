Understanding Internal vs External IP Addresses in Google Cloud Platform (GCP)

By Sunke Nithin · August 9, 2025   CLOUDGCPNetwork

When you deploy resources in Google Cloud Platform (GCP), understanding how internal and external IP addresses work is crucial for designing secure, scalable architectures. Whether you're launching a VM, setting up a load balancer or deploying a Kubernetes cluster, knowing how GCP handles IP addressing helps you:

Control accessManage costsSecure your workloads

Let's look at the differences, use cases, how to assign each type, and the key best practices.

2Internal IP Address (Private)

An internal IP is a private address assigned to a VM instance, internal load balancer or GKE node within a VPC network. It's used for private communication between GCP resources without exposing them to the internet.

Use cases

  • Backend services (database servers, APIs)
  • GKE nodes communicating internally
  • VM-to-VM or VM-to-database traffic
  • Connections over VPC peering, Cloud VPN or Interconnect

How internal IPs are assigned

  • Automatically by GCP from the subnet's range (e.g. 10.0.0.0/24), or
  • As a static reservation, so the VM keeps the same address even if it's stopped or recreated.

Reserve a static internal IP — Console

  1. Go to VPC network → IP addresses.
  2. Click Reserve internal static IP address.
  3. Select the network, region and subnet, and optionally choose the exact address.
  4. Click Reserve, then select it as the primary internal IP when you create the VM.

Reserve a static internal IP — gcloud

GCLOUD
gcloud compute addresses create my-internal-ip \
  --region=us-central1 \
  --subnet=custom-subnet \
  --addresses=10.0.0.100 \
  --purpose=GCE_ENDPOINT

Passing --subnet makes it an internal address. Omit --addresses to let GCP pick a free IP from the subnet.

3External IP Address (Public)

An external IP is a public IP address assigned to a VM, load balancer or other resource that needs to communicate with — or be reached from — the public internet.

Use cases

  • Web servers and APIs accessed over the internet
  • Remote SSH/RDP access to VMs (though IAP is a safer option — see below)
  • Inbound and outbound communication with external systems
Security warning: a public IP exposes the resource to the internet. Always protect it with:
  • Firewall rules that allow only the ports and sources you need
  • Identity-Aware Proxy (IAP) for admin access
  • A secure VPN or bastion host

Types of external IP

TypeDescription
EphemeralAssigned automatically. Released when the VM is stopped or deleted (it survives a reboot/reset), so it may change the next time the VM starts.
StaticReserved and fixed until you release it — ideal for DNS records and long-lived services.
You can promote an ephemeral external IP to static without changing it: VPC network → IP addresses, select the address, then Promote to static IP address.

Reserve a static external IP — Console

  1. Go to VPC network → IP addresses.
  2. Click Reserve external static IP address.
  3. Choose the Type: Regional or Global (global addresses are for global external load balancers).
  4. Use the address during VM or load-balancer setup.

Reserve a static external IP — gcloud

GCLOUD
# Regional — for VMs and regional load balancers
gcloud compute addresses create my-external-ip \
  --region=us-central1

# Global — for global external load balancers
gcloud compute addresses create my-global-ip \
  --global

4Best Practices

Internal IPs

  • Use internal IPs by default for all internal communication.
  • Enable Private Google Access to reach Google APIs without public IPs.
  • Use Cloud NAT for outbound internet access without public IPs.

External IPs

  • Avoid exposing VMs directly — put an HTTPS load balancer with Cloud Armor in front.
  • Use static IPs for DNS mapping and consistency.
  • Restrict access with firewall rules, service accounts and IAP.

Final Thoughts

IP address management in GCP isn't just about connectivity — it's about security, availability and cost efficiency. Default to internal IPs, use external IPs only when needed, and always follow GCP's network security best practices.
