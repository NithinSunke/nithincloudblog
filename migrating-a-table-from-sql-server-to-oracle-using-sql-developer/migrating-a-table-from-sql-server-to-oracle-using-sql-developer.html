Migrating a Table from SQL Server to Oracle Using SQL Developer

By Sunke Nithin · April 11, 2025   DatabaseOracleMigration

Oracle SQL Developer can connect to Microsoft SQL Server and copy tables — structure and data — straight into an Oracle schema. Here I copy a table of images (binary data) from SQL Server 2016 into Oracle Database 19c with Copy To Oracle.

Prerequisites

  • Oracle SQL Developer (I used 23.1 on Windows)
  • SQL Server with the source database, reachable over TCP/IP
  • An Oracle database and a target schema
  • The jTDS JDBC driver — SQL Developer's SQL Server connection type uses jTDS, not Microsoft's sqljdbc.jar

1The Source and Target

Source: SQL Server 2016, database imagedb, table dbo.ImageStore. Target: Oracle 19c PDB NCDB, schema IMADM:

On SQL Server I created a table holding images as binary data and loaded 11 files:

2Add the jTDS Driver to SQL Developer

  1. Download jTDS (jtds-1.3.1-dist.zip) from SourceForge and unzip it.
  2. In SQL Developer: Tools → Preferences → Database → Third Party JDBC Drivers.
  3. Click Add Entry, select jtds-1.3.1.jar, click OK, and restart SQL Developer.

After the restart, SQLServer appears as a database type in the connection dialog:

3Enable TCP/IP on SQL Server

In SQL Server Configuration Manager → SQL Server Network Configuration → Protocols for <instance>, enable TCP/IP and note the port (TCP/IP Properties → IP Addresses → IPAll; 1433 by default). Restart the SQL Server service after enabling it, and allow the port through Windows Firewall:

4Create the SQL Server Connection

Hostname, port 1433, a SQL Server login, then Retrieve database and pick imagedb. Test, then Save:

5Create a Migration Repository

SQL Developer keeps migration metadata in a repository schema in Oracle:

SQL
-- in the target PDB (NCDB), as a DBA
CREATE USER mig_repo_schema IDENTIFIED BY "<password>"
  DEFAULT TABLESPACE users QUOTA UNLIMITED ON users;
GRANT CONNECT, RESOURCE, CREATE SESSION, CREATE VIEW, CREATE MATERIALIZED VIEW
   TO mig_repo_schema;
Since 12c, RESOURCE no longer includes UNLIMITED TABLESPACE, so give the repository user a quota — otherwise creating the repository fails with ORA-01950.

Create an SQL Developer connection for mig_repo_schema, then Tools → Migration → Repository Management → Create Repository and select it:

6Copy the Table to Oracle

In the SQL Server connection, expand the database, right-click the table and choose Copy To Oracle. Pick the destination connection (the target schema) and the options — copy DDL, copy data, and what to do if the table already exists:

For a whole database (tables, views, procedures converted to PL/SQL), use Tools → Migration → Migrate instead — the full migration wizard.

7Validate

The table is in the Oracle schema with all 11 rows, VARBINARY(MAX) mapped to BLOB:

SQL
-- Oracle
SELECT COUNT(*), SUM(DBMS_LOB.GETLENGTH(imagedata)) FROM imadm.imagestore;

-- SQL Server
SELECT COUNT(*), SUM(DATALENGTH(ImageData)) FROM imagedb.dbo.ImageStore;

Comparing total byte length as well as row counts confirms the binary data came across intact.

Tips

  • Back up both sides before migrating.
  • Start with small tables to validate data type mappings (dates, NVARCHAR, identity columns).
  • Copy into a staging schema first in production projects.
  • For ongoing replication rather than a one-off copy, GoldenGate is the tool.
