Installing and Configuring a DNS Server in Windows Server

By Sunke Nithin · May 20, 2024   WindowsInstallation

DNS turns names like web01.scslabs.com into IP addresses, and back again. Windows Server includes a DNS Server role; here I install it, create forward and reverse lookup zones, add records, and test them — in Server Manager and with PowerShell.

Before You Start

  • Windows Server 2016, 2019, 2022 or 2025, with a static IP address
  • An account with local administrator rights (Domain Admin on a domain controller)
  • Your zone name (e.g. scslabs.com) and the hosts and network ranges it will cover

1Install the DNS Server Role

Server Manager: Manage → Add Roles and Features → Role-based or feature-based installation → select the server → tick DNS Server → Add Features → Next through to Install → Close when it finishes.

PowerShell (as administrator):

POWERSHELL
# install the role and the management tools
Install-WindowsFeature -Name DNS -IncludeManagementTools
Get-WindowsFeature -Name DNS
If you're building a domain, you normally don't install DNS separately — promoting the server to a domain controller installs DNS and creates an Active Directory–integrated zone for the domain automatically.

2Create a Forward Lookup Zone

A forward lookup zone maps names to IP addresses. Open Server Manager → Tools → DNS, expand the server, right-click Forward Lookup Zones → New Zone:

  1. Primary zone (on a domain controller, keep Store the zone in Active Directory ticked).
  2. Zone name: scslabs.com.
  3. Zone file: Create a new file with this file name (non-AD zones only).
  4. Dynamic updates: Secure only for AD-integrated zones; Do not allow for a static, manually maintained zone.
  5. Finish. The zone is created with its SOA and NS records.

3Create a Reverse Lookup Zone

A reverse lookup zone maps IP addresses back to names (PTR records). Right-click Reverse Lookup Zones → New Zone: Primary zone → IPv4 Reverse Lookup Zone → Network ID 192.168.1 → zone file → dynamic update choice → Finish. The zone is named 1.168.192.in-addr.arpa.

4Add Records

Right-click the forward zone → New Host (A or AAAA), enter the name and IP address, tick Create associated pointer (PTR) record, and click Add Host. The same with PowerShell:

POWERSHELL
# forward zone (file-backed, as in a standalone DNS server)
Add-DnsServerPrimaryZone -Name "scslabs.com" -ZoneFile "scslabs.com.dns"

# reverse zone for 192.168.1.0/24
Add-DnsServerPrimaryZone -NetworkId "192.168.1.0/24" -ZoneFile "1.168.192.in-addr.arpa.dns"

# an A record with its PTR
Add-DnsServerResourceRecordA -ZoneName "scslabs.com" -Name "web01" -IPv4Address 192.168.1.20 -CreatePtr

# on a domain controller, use AD-integrated zones instead:
# Add-DnsServerPrimaryZone -Name "scslabs.com" -ReplicationScope Domain -DynamicUpdate Secure

5Test Name Resolution

CMD
C:\> nslookup web01.scslabs.com 192.168.1.10
Server:  dc01.scslabs.com
Address:  192.168.1.10

Name:    web01.scslabs.com
Address:  192.168.1.20

C:\> nslookup 192.168.1.20 192.168.1.10
Name:    web01.scslabs.com
Address:  192.168.1.20

PS> Resolve-DnsName web01.scslabs.com -Server 192.168.1.10

A forward lookup returning the IP and a reverse lookup returning the name confirm both zones work. Finally, add forwarders (server properties → Forwarders, e.g. your router or 8.8.8.8) so the server can resolve internet names too, and point your clients' DNS settings at it.
