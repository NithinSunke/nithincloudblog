Streamlining Oracle Database Patching with AutoUpgrade.jar

By Sunke Nithin · December 12, 2024   DatabasePatchingAutoupgradeOracle

Keeping Oracle databases up to date is critical for performance, security and compliance. I recently used autoupgrade.jar in patching mode to move a 19c database to Release Update 19.25 — it downloaded the patches, built a new Oracle home, patched the database and left a restore point behind, all from one config file. Here's the whole run.

AutomationLess manual work and fewer errors across the whole patching process.

Before you start: download the latest autoupgrade.jar from My Oracle Support (it's updated often), test the whole process in a non-production environment first, and make sure your backups are in place.

1The Configuration File

One small config file describes the database to patch and where everything goes:

PATCH.CFG
global.global_log_dir=/u01/software/log
global.keystore=/home/oracle/autoupgrade/keys
upg1.sid=cdb1
upg1.source_home=/u01/app/oracle/product/19.0.0/dbhome_1
upg1.target_home=/u01/app/oracle/product/19.0.0/dbhome_2
upg1.folder=/u01/software/patch
upg1.download=YES
upg1.patch=RECOMMENDED
Show screenshot
ParameterMeaning
keystoreSecure directory that holds the AutoUpgrade keystore (your My Oracle Support credentials)
source_homeORACLE_HOME the database runs from now
target_homeDirectory where AutoUpgrade creates the new, patched ORACLE_HOME
sidORACLE_SID of the database to patch
folderDirectory holding the patch zip files and the base image
downloadYES lets AutoUpgrade fetch missing patches from My Oracle Support
patchComma-separated list of what to install (default RECOMMENDED)

Values for patch

ValueInstalls
RECOMMENDEDAlias for RU,OPATCH,OJVM,DPBP (the default)
RULatest Release Update
RU:x.yA specific Release Update, e.g. RU:19.24
OPATCHLatest OPatch
OJVMOracle Java VM patch matching the RU
OJVM:x.yA specific OJVM patch, e.g. OJVM:19.24
DPBPData Pump bundle patch matching the RU
<number>A specific one-off patch
With method=OUTOFPLACE (out-of-place patching into a new home, as here), the list must include RU,OPATCH.

2Patching Modes and Stages

AutoUpgrade patching has three job modes, plus a download mode that only fetches patches. Each runs a different set of stages:

ModeStages
analyzePRECHECKS
fixupsPRECHECKS, PREFIXUPS
deployGRP, PREACTIONS, PRECHECKS, PREFIXUPS, EXTRACT, INSTALL, ROOTSH, DBTOOLS, OPATCH, PATCHING, POSTCHECKS, POSTFIXUPS, POSTACTIONS

Every command below runs from the AutoUpgrade directory, using the Java that ships with the database home:

BASH
$ORACLE_HOME/jdk/jre/bin/java -jar autoupgrade.jar -patch -config patch.cfg -mode <mode>

3Load My Oracle Support Credentials

For AutoUpgrade to download patches, store your MOS credentials in its keystore with -load_password. The first run creates the keystore and asks you to set a password for it:

BASH
$ORACLE_HOME/jdk/jre/bin/java -jar autoupgrade.jar -patch -config patch.cfg -load_password

# Inside the MOS> prompt:
MOS> add -user <your-mos-username>    # then enter your MOS password twice
MOS> save
MOS> list                            # "MOS Credentials Loaded - Connection Successful"
MOS> exit

4Download the Patches

BASH
$ORACLE_HOME/jdk/jre/bin/java -jar autoupgrade.jar -patch -config patch.cfg -mode download
ls /u01/software/patch/

AutoUpgrade connected to MOS, worked out what RECOMMENDED means today, and downloaded and validated each file:

PatchFile
Database Release Update 19.25.0.0.0p36912597_190000_Linux-x86-64.zip
Data Pump Bundle Patch 19.25.0.0.0p37056207_1925000DBRU_Generic.zip

The folder also contains LINUX.X64_193000_db_home.zip — the 19.3 base image AutoUpgrade unzips to build the new home.

5Analyze: Run the Pre-Checks

BASH
$ORACLE_HOME/jdk/jre/bin/java -jar autoupgrade.jar -patch -config patch.cfg -mode analyze

The files are already there, so each one is reported as LOCATED. The job runs in the background and you get a patch> console. Useful commands there:

CONSOLE
lsj               # list jobs and their current stage
status -job 100   # details for one job: logs, stages, per-container progress
/                 # repeat the last command
help              # all console commands
Show output

Job 100 finished with no failures. Read the pre-check report under /u01/software/log/cdb1/100/prechecks, and the summary at /u01/software/log/cfgtoollogs/patch/auto/status/status.html, before deploying.

6Deploy: Apply the Patches

BASH
$ORACLE_HOME/jdk/jre/bin/java -jar autoupgrade.jar -patch -config patch.cfg -mode deploy

Deploy mode created a guaranteed restore point (GRP), built and patched the new home, moved cdb1 into it and ran datapatch. Job 101 took about 2 hours 20 minutes in this lab:

StageTimeRelative time
GRP, PREACTIONS<1 min
PRECHECKS4 min
PREFIXUPS9 min
EXTRACT3 min
INSTALL2 min
ROOTSH, DBTOOLS<1 min
OPATCH25 min
PATCHING~90 min
Show output
Because this is out-of-place patching, the database now runs from dbhome_2. Update /etc/oratab if needed and any scripts or profiles that set ORACLE_HOME, and keep dbhome_1 until you're sure you won't need to fall back.

Also confirm datapatch ran inside the database:

SQL
SELECT patch_id, action, status, description
FROM   dba_registry_sqlpatch
ORDER  BY action_time;

Drop the guaranteed restore point

AutoUpgrade keeps the GRP so you can roll back. A guaranteed restore point keeps flashback logs growing in the recovery area, so drop it once you're happy with the patched database:

SQL
DROP RESTORE POINT AU_PATCHING_9212_CDB1193000;

Summary

AutoUpgrade turned a multi-step manual job — downloading the right RU, OJVM, Data Pump and OPatch patches, building a new home, patching and running datapatch — into four commands driven by one config file. It's a must-have for any Oracle DBA who wants to reduce manual work and patch more consistently. If you haven't tried it yet, start with -mode analyze on a test system.
