Migrate a Non-CDB from Windows to a Linux CDB Using Remote Clone over a Database Link

By Sunke Nithin · April 4, 2025   DatabaseOracleMigration

A 19c non-CDB on Windows can be cloned straight into a PDB of a CDB on Linux over a database link. Windows x86-64 and Linux x86-64 are both little-endian, so the data files can be copied as they are. Using a refreshable clone keeps the PDB in sync until cutover, so the outage is only the final refresh and the conversion.

Prerequisites

  • Source: 19c non-CDB on Windows (NCDB), in ARCHIVELOG mode
  • Target: 19c CDB on Linux (O19TC on OL8) with local undo (the default)
  • Network access from the target to the source listener
  • Enough storage on the target for the whole database

1Check Plug-In Compatibility

On the source, describe the database to an XML file:

SQL
-- on the source (Windows), creates the XML description of the non-CDB
SQL> exec DBMS_PDB.DESCRIBE('F:\NCDB.xml');

Copy NCDB.xml to the target and check it:

SQL
set serveroutput on
DECLARE
compatible CONSTANT VARCHAR2(3) := CASE DBMS_PDB.CHECK_PLUG_COMPATIBILITY( pdb_descr_file => '/home/oracle/NCDB.xml', pdb_name => 'NCDB') WHEN TRUE THEN 'YES' ELSE 'NO'
END;
BEGIN
DBMS_OUTPUT.PUT_LINE('Is the future PDB compatible?  ==>  ' || compatible);
END;
/

The answer is NO, but the violations are all fixable: the PDB needs noncdb_to_pdb.sql, two memory parameters differ (warnings), and the source is on RU 19.3 while the CDB is on 19.25 — datapatch fixes that after the clone.

2TNS Entry and Database Link

On the Linux server, add a TNS entry for the Windows database and test it:

TNS
ncdb =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = wo19cdb01.scslabs.com)(PORT = 1521))
    (CONNECT_DATA =
      (SERVER = DEDICATED)
      (SERVICE_NAME = NCDB)
    )
  )

Create a user on the source for the clone, and the database link on the target:

SQL
-- on the source non-CDB
SQL> create user migusr identified by "<password>";
SQL> grant create session, create pluggable database to migusr;
My original post also granted SYSOPER; it isn't needed — CREATE PLUGGABLE DATABASE and CREATE SESSION are enough.
SQL
-- on the target CDB root
SQL> create database link MIGDBLINK connect to migusr identified by "<password>" using 'NCDB';
SQL> select * from dual@MIGDBLINK;

3Create a Refreshable Clone

The clone is refreshed from the source's redo every minute:

SQL
SQL> create pluggable database NCDB from NCDB@MIGDBLINK refresh mode every 1 minutes parallel 2;
Pluggable database created.

SQL> show pdbs
    CON_ID CON_NAME                       OPEN MODE  RESTRICTED
---------- ------------------------------ ---------- ----------
         2 PDB$SEED                       READ ONLY  NO
         3 PRD_PDB1                       READ WRITE NO
         5 NCDB                           MOUNTED

SQL> set lines 300
col pdb_name for a15
col open_mode for a15
col restricted for a15
col status for a15
col refresh_mode for a15
col refresh_interval for 999
select p.pdb_name, v.open_mode, v.restricted, p.status, p.refresh_mode, p.refresh_interval
from v$pdbs v join dba_pdbs p on (v.con_id =p.pdb_id)
where p.pdb_name='NCDB' order by v.con_id
;

PDB_NAME        OPEN_MODE       RESTRICTED      STATUS          REFRESH_MODE    REFRESH_INTERVAL
--------------- --------------- --------------- --------------- --------------- ----------------
NCDB            MOUNTED                         REFRESHING      AUTO                           1
SQL> exit
Oracle's documented syntax for cloning a non-CDB is FROM NON$CDB@MIGDBLINK; naming the database (NCDB@MIGDBLINK) also worked in my lab.

4Cutover: Final Refresh

Stop the applications and make sure nothing is still connected to the source:

SQL
select sid,username,status, MACHINE from v$session where username is not null;

Then refresh one last time, stop refreshing, and open the PDB in upgrade mode:

SQL
SQL> alter pluggable database NCDB refresh;
SQL> alter pluggable database NCDB refresh mode none;
SQL> alter pluggable database NCDB open upgrade;

SQL> select name, open_mode, restricted from v$pdbs where name='NCDB';

NAME       OPEN_MODE       RESTRICTED
---------- --------------- ---------------
NCDB       MIGRATE         YES

The PDB's Java classes were still at 19.3 while the CDB binaries were at 19.25:

update_javavm_db.sql is the fix from MOS Doc ID 2905337.1 (ORA-29548: Java system class reported). Without it, datapatch fails — see "The datapatch failure" below.

7Run noncdb_to_pdb.sql

This converts the non-CDB's data dictionary into a PDB's:

SQL
SQL> alter session set container=NCDB;
SQL> @?/rdbms/admin/noncdb_to_pdb.sql

8Open the PDB Normally

SQL
SQL> show pdbs
    CON_ID CON_NAME                       OPEN MODE  RESTRICTED
---------- ------------------------------ ---------- ----------
         4 NCDB                           MIGRATE    YES
SQL> alter pluggable database NCDB close immediate;
SQL> alter pluggable database NCDB open;
SQL> alter pluggable database NCDB save state;
SQL> show pdbs
    CON_ID CON_NAME                       OPEN MODE  RESTRICTED
---------- ------------------------------ ---------- ----------
         4 NCDB                           READ WRITE NO

9Enable TDE in the PDB

The CDB uses TDE, so the new PDB needs its own master key, and then its tablespaces can be encrypted online:

SQL
-- TEMP can't be encrypted in place: create an encrypted one and switch
SQL> create temporary tablespace temp_enc tempfile size 1g autoextend on encryption encrypt;
SQL> alter database default temporary tablespace temp_enc;
SQL> drop tablespace temp including contents and datafiles;

10Post-Migration

  • Verify objects, schemas and users; run utlrp.sql.
  • Create the application services and update connection strings.
  • Gather statistics: EXEC DBMS_STATS.GATHER_DATABASE_STATS;
  • Back up the CDB and drop the database link.
