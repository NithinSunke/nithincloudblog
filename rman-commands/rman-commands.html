RMAN Commands: ALLOCATE CHANNEL, BACKUP and Format Options

By Sunke Nithin · June 13, 2019   DatabaseOracle

A reference for RMAN's core backup commands — channels, the BACKUP command and its options, file-name format variables — with worked examples for common jobs. For listing, crosschecking and deleting backups, see RMAN Useful Commands.

ALLOCATE CHANNEL

A channel is a connection from RMAN to the database instance; each one starts a server session that reads and writes the backup. Channels allocated inside a RUN block are released automatically when the block ends. With a configured default device and parallelism, RMAN allocates channels for you, so you only need ALLOCATE CHANNEL to override them.

Example 1: Back up to tape

Allocate a tape (SBT) channel for a whole-database backup — this needs a media manager such as Oracle Secure Backup or a vendor library.

RMAN
RUN {
  ALLOCATE CHANNEL dev1 DEVICE TYPE sbt;
  BACKUP DATABASE;
}

Example 2: Multiple copies of a backup

SET BACKUP COPIES makes RMAN write identical copies of each piece to several locations — here four copies of data file 1:

RMAN
RUN {
  ALLOCATE CHANNEL dev1 DEVICE TYPE DISK MAXPIECESIZE 2G;
  SET BACKUP COPIES = 4;
  BACKUP DATAFILE 1 FORMAT '/dsk1/bp/%U', '/dsk2/bp/%U', '/dsk3/bp/%U', '/dsk4/bp/%U';
}

BACKUP

Backs up the database, tablespaces, data files (current or copies), the control file, the spfile, archived logs or existing backup sets — on a primary or a standby. Output goes to backup sets (RMAN's own format; one or more backup pieces, which are the physical files) or image copies (BACKUP AS COPY). Only backups that complete successfully are recorded.

What to back up

OptionBacks up
DATABASEAll data files (plus the control file and spfile when autobackup is on, or with INCLUDE CURRENT CONTROLFILE)
TABLESPACE name, …All data files of one or more tablespaces
DATAFILE n, …Specific data files, by number or name
DATAFILECOPY 'file'Existing image copies of data files
CURRENT CONTROLFILEThe current control file
SPFILEThe server parameter file
ARCHIVELOG …Archived logs: ALL, SEQUENCE …, FROM/UNTIL TIME, LIKE 'pattern'
BACKUPSET …Existing backup sets — e.g. move disk backups to tape (disk→disk or disk→tape only)
PLUGGABLE DATABASE pdbAll data files of a PDB (12c and later)

Full and incremental

OptionMeaning
FULLEvery used block. The default when neither FULL nor INCREMENTAL is given. A full backup can't be the base for incrementals.
INCREMENTAL LEVEL 0Also every used block, but it is the base for later incrementals
INCREMENTAL LEVEL 1Differential (default): blocks changed since the most recent level 1 or level 0
INCREMENTAL LEVEL 1 CUMULATIVEBlocks changed since the most recent level 0 — larger, but restores need fewer pieces
Old documentation mentions incremental levels 2–4. Since 10g, Oracle supports only levels 0 and 1. Enable block change tracking (ALTER DATABASE ENABLE BLOCK CHANGE TRACKING;) so level 1 backups don't have to read every block.

Examples

Example 1: Database, then the control file

Back up the database, then the control file that records that backup (or just turn on CONFIGURE CONTROLFILE AUTOBACKUP ON):

RMAN
BACKUP DATABASE;
BACKUP CURRENT CONTROLFILE;

Example 2: Tablespaces and data files in parallel

Two channels writing to two file systems; RMAN spreads the work between them:

RMAN
RUN {
  ALLOCATE CHANNEL dev1 DEVICE TYPE DISK FORMAT '/fs1/%U';
  ALLOCATE CHANNEL dev2 DEVICE TYPE DISK FORMAT '/fs2/%U';
  BACKUP
    (TABLESPACE system, sales1, sales2, sales3 FILESPERSET 20)
    (DATAFILE 12, 14, 15);
}

Example 3: Archived logs, then delete them

Back up archived logs matching a pattern and delete every copy of them once the backup succeeds:

RMAN
BACKUP ARCHIVELOG LIKE '/arch/dest%' DELETE ALL INPUT;

Example 4: Move old backups to tape

Copy disk backup sets older than two weeks to tape and delete them from disk:

RMAN
BACKUP DEVICE TYPE sbt BACKUPSET COMPLETED BEFORE 'SYSDATE-14' DELETE INPUT;

Example 5: Default to disk, archived logs to tape

RMAN
CONFIGURE DEFAULT DEVICE TYPE TO DISK;
BACKUP DEVICE TYPE sbt ARCHIVELOG ALL;

Example 6: Cumulative incremental

Back up every block changed since the last level 0, skipping files that can't be read:

RMAN
BACKUP INCREMENTAL LEVEL 1 CUMULATIVE SKIP INACCESSIBLE DATABASE;

Example 7: Check for corruption

Back up data file 3, checking for logical corruption and tolerating at most two corrupt blocks:

RMAN
RUN {
  SET MAXCORRUPT FOR DATAFILE 3 TO 2;
  BACKUP CHECK LOGICAL DATAFILE 3;
}

To check without writing a backup at all: BACKUP VALIDATE CHECK LOGICAL DATABASE;

Example 8: Long-term archival backup

A consistent backup exempt from the retention policy and kept for a year. RMAN backs up the archived logs needed to make it consistent and keeps them with it:

RMAN
SHUTDOWN IMMEDIATE;
STARTUP MOUNT;
BACKUP DATABASE KEEP UNTIL TIME 'SYSDATE+365';
ALTER DATABASE OPEN;
Old versions used BACKUP DATABASE UNTIL 'SYSDATE+365' NOLOGS. From 11g the syntax is KEEP UNTIL TIME; an online archival backup also works (RMAN includes the logs it needs). KEEP backups can't go to the fast recovery area — give them a FORMAT outside it.

Example 9: Files with no recent backup

Back up all data files and archived logs that haven't been backed up in the last month:

RMAN
BACKUP DATABASE, ARCHIVELOG ALL NOT BACKED UP SINCE TIME 'SYSDATE-31';

Example 10: Consistent backup while mounted

Mount the database, take a whole-database backup, then open it:

RMAN
STARTUP MOUNT;
BACKUP DATABASE;
ALTER DATABASE OPEN;

Example 11: Restore the control file

Restore the control file to its default locations from the autobackup:

RMAN
STARTUP NOMOUNT;
RESTORE CONTROLFILE FROM AUTOBACKUP;
ALTER DATABASE MOUNT;

Example 12: Restore archived logs by SCN

Restore backed-up archived logs within an SCN range:

RMAN
RESTORE ARCHIVELOG SCN BETWEEN 500 AND 700;

Example 13: One archived log

Back up archived log sequence 1372 and delete it:

RMAN
BACKUP ARCHIVELOG SEQUENCE 1372 DELETE INPUT;

Example 14: A range of archived logs to tape

Back up logs 288–301 of thread 1 to tape and delete them afterwards. If the backup fails, nothing is deleted:

RMAN
RUN {
  ALLOCATE CHANNEL dev1 DEVICE TYPE sbt;
  BACKUP ARCHIVELOG SEQUENCE BETWEEN 288 AND 301 THREAD 1
    DELETE INPUT;   # delete the logs after the backup completes
}
