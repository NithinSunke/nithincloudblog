Steps to Upgrade vCenter Server 7 to vCenter Server 8

By Sunke Nithin · May 4, 2025   VirtualizationVmware

vCenter Server 8 brings performance improvements, security enhancements and support for modern infrastructure. If you're still on vCenter 7, here's the whole upgrade in my homelab, using the vCenter Server Appliance (VCSA) GUI installer. The installer deploys a new 8.0 appliance, copies your configuration across, then shuts the old one down and takes over its identity.

1Pre-Upgrade Checklist

  • Take a file-based backup of the existing VCSA (VAMI → Backup), and/or a snapshot of the appliance VM.
  • Check that your ESXi hosts, hardware and other VMware products (backup tools, NSX, vSAN and so on) are compatible with vCenter 8, using the Broadcom Compatibility Guide and Interoperability Matrix.
  • Check the supported upgrade path from your exact vCenter 7 build: a recent 7.0 Update 3 build can need a matching 8.0 update rather than an older 8.0 release.
  • Download the vCenter Server 8 ISO from the Broadcom Support Portal (formerly VMware Customer Connect).
  • Reserve a temporary static IP on the same network for the new appliance. It's only used during the upgrade; at the end the new appliance takes over the old one's name and IP.
  • Have a vCenter 8 license key ready — vCenter 7 keys don't license vCenter 8, which runs in evaluation mode until you add one.

2Mount the ISO and Start the Installer

Mount the vCenter 8 ISO on your workstation and open the installer folder for your operating system:

PATH
vcsa-ui-installer\win32\installer.exe     # Windows
vcsa-ui-installer/lin64/installer        # Linux
vcsa-ui-installer/mac/Installer.app      # macOS

Launch the installer and choose Upgrade.

3Stage 1: Deploy the New vCenter Appliance

Introduction and license agreement

Review the introduction, click Next, and accept the EULA.

Connect to the source appliance

Enter the source vCenter 7 address and click Connect to Source. Then provide its SSO administrator and root credentials, plus the ESXi host or vCenter that manages the source appliance, and accept the certificate thumbprints.

Choose where to deploy the new appliance

Enter the target ESXi host (or vCenter) for the new VCSA 8 — here the same host, 192.168.1.100. Then set the new VM name and root password, pick the deployment size, and choose a datastore.

Configure the temporary network

Give the new appliance its temporary settings: network, static IPv4 address, prefix, gateway and DNS servers.

Finish and deploy

Review the summary and click Finish. The installer deploys the new appliance; when it reports success, click Continue to go to Stage 2.

4Stage 2: Transfer the Configuration

Stage 2 reconnects to the source vCenter and runs the pre-upgrade checks.

Select the data to copy

Choose what to bring across. Copying only configuration and inventory is fastest; adding tasks, events and performance metrics keeps history but lengthens the downtime. Here, 1.98 GB with an estimated 37 minutes of downtime.

CEIP, review and start

Choose whether to join the Customer Experience Improvement Program, review the summary and click Finish. Confirm the warning: the source vCenter is shut down once the new appliance takes over its network identity.

Data transfer and cutover

The wizard copies the data, sets up the target vCenter and starts its services, then imports the copied data. A message that there are no licenses to add is expected — see the licensing note above.

5Post-Upgrade Steps

  • Log in to https://<vcenter-FQDN> (here https://vcenter.scslabs.com) as administrator@vsphere.local or your SSO domain administrator.
  • Verify the inventory (datacenters, clusters, hosts, VMs), vDS and storage configuration.
  • Add your vCenter 8 license under Administration → Licensing.
  • Reconnect and test backup tools, monitoring agents and other integrations.
  • Take a fresh file-based backup of the new appliance.
  • When everything checks out, delete the old VCSA 7 VM — it's powered off but not removed automatically.

The upgraded vcenter.scslabs.com in the vSphere Client, with the same datacenter, cluster, host and VMs.

Tips and Notes

  • The old appliance is not deleted automatically — clean it up manually once you're confident.
  • Don't power off hosts or the source appliance while the upgrade is running.
  • Keep both appliances on the same subnet for a smoother migration, and make sure forward and reverse DNS for the vCenter FQDN are correct beforehand.

Conclusion

The two-stage installer makes upgrading from vCenter 7 to 8 a safe, structured process: Stage 1 builds the new appliance next to the old one, and Stage 2 moves your data across and switches identity. Always rehearse in a lab before upgrading production.
