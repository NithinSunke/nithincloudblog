Relocate a Pluggable Database's Data Files Using RMAN

By Sunke Nithin · September 5, 2019   DatabaseOracleMigration

Moving a PDB's data files to a new location — a new mount point or disk — can be done with RMAN image copies: copy the files while the PDB is open, then switch to the copies and recover. The PDB is only closed for the switch and recovery, which takes seconds. Example: PDB pdbsnv in CDB snvtst (12.2), moving from …/snvtst/pdbsnv/ to …/snvtst/psnv/.

backup as copy (PDB open)→close PDB→switch to copy→recover→open

Prerequisite

The CDB must be in ARCHIVELOG mode — the copies are taken while the PDB is open and are brought up to date with the archived logs.

1Copy the PDB's Data Files to the New Location

RMAN
RMAN> backup as copy pluggable database pdbsnv format '/u01/oracle/oradata/snvtst/psnv/%U';
OUTPUT

output file name=/u01/oracle/oradata/snvtst/psnv/data_D-SNVTST_I-2798789440_TS-SYSTEM_FNO-9_02ub1u09
input datafile file number=00011 name=/u01/oracle/oradata/snvtst/pdbsnv/undotbs01.dbf

Finished backup at 06-SEP-19

The PDB stays open and in use while this runs. Use a format like '/new/path/%N_%f.dbf' (tablespace name and file number) if you'd like readable file names instead of %U.

2Close the PDB

RMAN
RMAN> alter pluggable database pdbsnv close;

3Switch to the Copies

RMAN
RMAN> switch pluggable database pdbsnv to copy;
OUTPUT
datafile 9 switched to datafile copy "/u01/oracle/oradata/snvtst/psnv/data_D-SNVTST_I-2798789440_TS-SYSTEM_FNO-9_02ub1u09"
datafile 10 switched to datafile copy "/u01/oracle/oradata/snvtst/psnv/data_D-SNVTST_I-2798789440_TS-SYSAUX_FNO-10_01ub1tvq"
datafile 11 switched to datafile copy "/u01/oracle/oradata/snvtst/psnv/data_D-SNVTST_I-2798789440_TS-UNDOTBS1_FNO-11_03ub1u0o"
datafile 12 switched to datafile copy "/u01/oracle/oradata/snvtst/psnv/data_D-SNVTST_I-2798789440_TS-USERS_FNO-12_05ub1u0t"
datafile 13 switched to datafile copy "/u01/oracle/oradata/snvtst/psnv/data_D-SNVTST_I-2798789440_TS-NITHINTS_FNO-13_04ub1u0s"

The control file now points at the new files.

4Recover the PDB

Apply the redo generated while the copies were being made:

RMAN
RMAN> recover pluggable database pdbsnv;
OUTPUT
starting media recovery
archived log file name=/u01/oracle/12.2.0/db/dbs/arch/1_4_1018226114.dbf thread=1 sequence=4
...
archived log file name=/u01/oracle/12.2.0/db/dbs/arch/1_7_1018226114.dbf thread=1 sequence=7
media recovery complete, elapsed time: 00:00:01
Finished recover at 06-SEP-19

5Open the PDB

RMAN
RMAN> alter pluggable database pdbsnv open;
SQL
alter session set container = pdbsnv;
select file#, name from v$datafile;

Clean Up

  • Old files: after the switch, RMAN records the old files as data file copies. Once you've verified the PDB, remove them with RMAN> delete datafilecopy all; (check with list copy of pluggable database pdbsnv; first).
  • Temp files aren't moved by RMAN. Add a new temp file in the new location and drop the old one: alter tablespace temp add tempfile '/u01/oracle/oradata/snvtst/psnv/temp02.dbf' size 1g; then alter tablespace temp drop tempfile '/u01/oracle/oradata/snvtst/pdbsnv/temp01.dbf';
  • Take a fresh backup.

The Truly Online Alternative

From 12c you can move data files with no close at all, one file at a time, while the PDB stays open:

SQL
alter session set container = pdbsnv;
alter database move datafile '/u01/oracle/oradata/snvtst/pdbsnv/users01.dbf'
  to '/u01/oracle/oradata/snvtst/psnv/users01.dbf';

That avoids any downtime and needs no archived logs, but it moves files one by one and needs space for both copies of each file during the move. The RMAN method is handy when there are many files, or to prepare the copies well ahead of a short maintenance window.
