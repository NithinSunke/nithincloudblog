Why NetworkManager Reports ip-config-unavailable

By Sunke Nithin · May 20, 2024   LinuxNetwork

While deploying an Oracle Linux 7 VM with Terraform in my lab, I hit an issue that stopped the network device eth0 from coming up. NetworkManager kept failing the device with the reason ip-config-unavailable. The steps below, from Red Hat's guidance, were the fix.

1Environment

  • Red Hat Enterprise Linux 7 and above (and compatible distributions such as Oracle Linux)
  • NetworkManager

2Issue

The interface won't come up, and adding an IP address to it fails. The NetworkManager log (journalctl -u NetworkManager or /var/log/messages) shows messages like these:

LOG
May 14 09:11:14 servera NetworkManager[675]: <info>  (ens8): device state change: ip-config -> secondaries (reason 'ip-config-unavailable') [70 90 5]

May 14 09:03:27 serverb NetworkManager[695]: <info>  [1684047807.5263] device (ens9): state change: ip-config -> failed (reason 'ip-config-unavailable', sys-iface-state: 'managed')

3Root Cause

The connection's ipv4.method is set to disabled, so no IPv4 configuration is available for the interface. NetworkManager therefore can't complete the ip-config stage, and it won't let you add an IP address. Once ipv4.method is changed to auto or manual, you can configure the address again.

To confirm, find the connection name and check its method:

BASH
# List connections and the devices they use
nmcli connection show

# Show the IPv4 method for one connection
nmcli -g ipv4.method connection show <con-name>     # prints "disabled" when affected

4Resolution

Change ipv4.method to auto (DHCP) or give the NIC a static IP address with manual, then bring the connection back up. Replace <con-name> with the name from nmcli connection show.

Method 1 — DHCP (auto)

BASH
nmcli connection modify <con-name> ipv4.method auto
nmcli connection up <con-name>

Method 2 — Static IP (manual)

BASH
nmcli connection modify <con-name> \
  ipv4.method manual \
  ipv4.addresses <IP>/<prefix>
nmcli connection up <con-name>
Static IP tip: with manual you'll usually also want a gateway and DNS, for example: nmcli connection modify <con-name> ipv4.gateway 192.168.1.1 ipv4.dns 192.168.1.1. With manual, NetworkManager requires at least one address in ipv4.addresses, so set it in the same command as the method (as above).

Verify

BASH
nmcli device status          # the device should show "connected"
ip addr show <device>        # the IPv4 address should now be present
If the VM is built by Terraform or cloud-init, the disabled IPv4 method may come from the image or the provisioning config. Fix it there too, or the next VM you deploy will hit the same problem.
