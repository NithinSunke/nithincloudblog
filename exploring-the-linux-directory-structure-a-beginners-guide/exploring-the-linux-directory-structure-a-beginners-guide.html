Exploring the Linux Directory Structure: A Beginner's Guide

By Sunke Nithin · April 22, 2025   LinuxLinux

Windows has a drive letter per disk. Linux has a single tree starting at the root directory /, and every disk, USB stick or network share is mounted somewhere inside it. Knowing what lives where makes administration and troubleshooting much easier.

The Top Level

TEXT
/
├── bin  -> usr/bin     (symlink on modern distributions)
├── boot
├── dev
├── etc
├── home
├── lib  -> usr/lib
├── media
├── mnt
├── opt
├── proc
├── root
├── run
├── sbin -> usr/sbin
├── srv
├── sys
├── tmp
├── usr
└── var

The layout follows the Filesystem Hierarchy Standard (FHS), so it's almost identical on Oracle Linux, RHEL, Ubuntu and Debian.

What Each Directory Is For

DirectoryPurpose
/The root of the whole tree
/binEssential commands for all users (ls, cp, mv). On current distributions a link to /usr/bin
/bootKernel, initramfs and boot loader (GRUB) files
/devDevice files — disks (/dev/sda, /dev/nvme0n1), terminals, /dev/null
/etcSystem-wide configuration files (/etc/fstab, /etc/hosts, /etc/ssh/)
/homeHome directories of normal users, e.g. /home/nithin
/lib, /lib64Shared libraries and kernel modules; links into /usr on current distributions
/mediaAutomatic mount points for removable media (USB, DVD)
/mntA place for temporary, manual mounts
/optAdd-on software from third parties (often where vendors install, e.g. /opt/oracle)
/procVirtual filesystem with process and kernel information (/proc/cpuinfo, /proc/meminfo)
/sysVirtual filesystem describing devices and drivers; also used to tune the kernel
/rootHome directory of the root user (not to be confused with /)
/runRuntime data since the last boot — PID files, sockets; kept in memory
/sbinSystem administration commands (fdisk, fsck, reboot); a link to /usr/sbin on current distributions
/srvData served by this system, e.g. web or FTP content
/tmpTemporary files for everyone. Often cleared at boot or after a set age, depending on the distribution
/usrInstalled software: programs (/usr/bin), libraries (/usr/lib), documentation (/usr/share), locally built software (/usr/local)
/varData that changes while the system runs: logs (/var/log), caches, spool files, databases
The "usr merge": RHEL/Oracle Linux 7 and later, Ubuntu 20.04+ and Debian 12 keep all programs and libraries under /usr; /bin, /sbin and /lib are just symbolic links to it. Old scripts using either path keep working.

Commands for Exploring

BASH
ls -l /                 # top-level directories (note the -> symlinks)
cd /etc && pwd
tree -L 1 /             # dnf install tree  /  apt install tree
df -h                   # mounted filesystems and free space
du -sh /var/* 2>/dev/null | sort -h    # what is using space under /var
findmnt                 # which filesystem is mounted where
man hier                # the reference for this layout

Why It Matters

  • Separation — configuration in /etc, user data in /home, growing data in /var, so each can be backed up or sized on its own.
  • Partitioning — putting /var, /home or /tmp on separate filesystems stops runaway logs or uploads from filling /.
  • Security — permissions differ per area, and options like noexec can be set on /tmp.
  • Consistency — once you know the layout, you know it on every distribution.
