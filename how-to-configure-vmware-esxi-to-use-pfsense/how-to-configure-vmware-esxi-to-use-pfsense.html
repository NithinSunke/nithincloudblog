How to Configure VMware ESXi to Use pfSense

By Sunke Nithin · April 16, 2025   VirtualizationVmwareNetwork

In a Home LAB, a pfSense firewall can act as the router for isolated networks inside VMware ESXi — giving test VMs their own subnets, internet access through pfSense, and firewall rules between them. Here I connect an ESXi host (nested in VMware Workstation) to two pfSense-routed networks.

LAB Layout

Windows VM (192.168.10.21) → port group VLAN10-PG → vSwitch VLanSwitch10 → vmnic1 → Workstation VMnet1 → pfSense LAN (192.168.10.1) → internet
  • ESXi runs as a VM in VMware Workstation with three network adapters (vmnic0 for management, vmnic1, vmnic2).
  • Adapters 2 and 3 are attached to the Workstation host-only networks VMnet1 and VMnet2.
  • The pfSense VM (see pfSense installation guide) has an interface on each of those networks — 192.168.10.1 and 192.168.20.1 — acting as their gateway, with NAT to its WAN.
These are separate networks, not 802.1Q VLANs. The names say "VLAN 10/20", but each port group uses VLAN ID 0 and its own vSwitch and uplink, so isolation comes from separate segments. With real VLANs you'd use one vSwitch and uplink, set VLAN IDs 10 and 20 on the port groups, and give pfSense VLAN interfaces on a trunk.

1Log In and Check the Physical NICs

Open the ESXi Host Client (https://<esxi-ip>/ui) — see Install VMware ESXi 7 if you're starting from scratch. Networking → Physical NICs shows three adapters.

2Create a Virtual Switch per Network

Networking → Virtual switches → Add standard virtual switch. Create VLanSwitch10 with uplink vmnic1, and VLANSwitch20 with uplink vmnic2.

3Create the Port Groups

Port groups → Add port group: VLAN10-PG on VLanSwitch10 and VLAN20-PG on VLANSwitch20.

4Connect a VM

Edit a VM (a Windows Server VM here) and set Network Adapter 1 to VLAN10-PG.

5Configure the Guest and Test

If DHCP is enabled on that pfSense interface the VM gets an address automatically; otherwise set one by hand — 192.168.10.21/24, gateway 192.168.10.1 (pfSense), and your DNS servers.

Pinging the pfSense gateway and google.com both work, so traffic is routed and NATed through pfSense.

Promiscuous mode: because ESXi is itself a VM here, Workstation's virtual NICs must pass frames for MAC addresses other than ESXi's own. If guests can't reach the gateway, set Security → Promiscuous mode / MAC address changes / Forged transmits to Accept on the vSwitch (on ESXi 7+ MAC learning is the cleaner alternative).

Where to Go Next

Add more isolated vSwitches for test VMs, a DMZ or VPN-only networks, and let pfSense firewall rules control traffic between them. To manage several hosts, add vCenter Server.
