Scale Up or Down Your Oracle Autonomous Database: CPU & Storage Made Simple

By Sunke Nithin · April 4, 2025   DatabaseOCIOracleADB

Workloads aren't flat — month-end reports, year-end analytics and test cycles all need more horsepower for a while. Oracle Autonomous Database (ADW, ATP, JSON or APEX) lets you change compute and storage online, without downtime, so you can size for today instead of the busiest day of the year.

What You Can Scale

ResourceUnitOnline?Auto scaling
ComputeECPUs (older databases: OCPUs)Yes — no restartUp to 3× the base ECPU count, billed for what's used
StorageTB for Data Warehouse, GB or TB for Transaction ProcessingYes — no restartUp to 3× the reserved storage
New Autonomous Databases are sized in ECPUs. Databases created with the older OCPU model show OCPUs instead and can be switched to ECPU from the console.

1Open Manage Resource Allocation

In the OCI Console, open your Autonomous Database and click Manage resource allocation:

2Change ECPUs and/or Storage

Set the new ECPU count and/or Storage, tick the auto scaling options if you want them, and click Apply.

3Watch It Scale

The status shows Scaling In Progress; the database stays open throughout.

Running sessions keep working while scaling happens; the new capacity is available as soon as the status returns to Available. Scaling down storage only works if the data fits the smaller size.

From the Command Line

The same change with the OCI CLI — handy for scheduling:

OCI CLI
oci db autonomous-database update \
  --autonomous-database-id <adb-ocid> \
  --compute-count 4 \
  --is-auto-scaling-enabled true

Permissions

The user needs IAM permission to manage the database, for example:

IAM POLICY
Allow group DBAdmins to manage autonomous-database-family in compartment MyCompartment

When to Scale What

ScenarioAction
Quarter-end or year-end reportingScale up ECPUs (or let auto scaling handle peaks)
Nights, weekends, holidaysScale down ECPUs
Large data loadScale up storage first
Test environment not in useScale down — or stop the database, which stops compute billing

Best Practices

  • Watch usage in OCI Monitoring metrics and Performance Hub before choosing a size.
  • Turn on compute auto scaling for spiky workloads: you set a base, and the database bursts up to 3× when it needs to.
  • Automate predictable changes with the OCI CLI or scheduled jobs — e.g. scale down every Friday evening and back up on Monday morning.
