How to Configure Duo MFA on Linux (SSH) – Step by Step

By Sunke Nithin · April 8, 2025   LinuxLinuxSecurity

Adding multi-factor authentication to SSH is one of the best security upgrades for a Linux server. With Duo Unix (pam_duo), a correct password is no longer enough: the user must also approve a push on their phone. This guide sets it up on Oracle Linux / RHEL.

Prerequisites

  • A Linux server (Oracle Linux, RHEL, Rocky, Alma; Ubuntu/Debian work too with Duo's apt repository)
  • Root access — and a second root session kept open while you change PAM, so a mistake can't lock you out
  • A Duo account (the free plan covers up to 10 users) and the Duo Mobile app

1Create the Duo Application

  1. Log in to the Duo Admin Panel.
  2. Applications → Protect an Application, search for UNIX Application, click Protect.
  3. Note the Integration key, Secret key and API hostname.
Treat the secret key like a password. Anyone who has it together with the integration key can talk to Duo as your application. Never put it in a screenshot, script or blog post; if it leaks, reset it in the Admin Panel.

2Install Duo Unix

INI
# /etc/yum.repos.d/duosecurity.repo
[duosecurity]
name=Duo Security Repository
baseurl=https://pkg.duosecurity.com/RedHat/$releasever/$basearch
enabled=1
gpgcheck=1
BASH
rpm --import https://duo.com/DUO-GPG-PUBLIC-KEY.asc
dnf install -y duo_unix          # yum on OL7/RHEL7

No compilers or -devel packages are needed for the packaged install — those are only for building from source. If $releasever doesn't resolve to a plain major version on your distribution, replace it with 8 or 9.

3Configure pam_duo.conf

Edit /etc/duo/pam_duo.conf:

/ETC/DUO/PAM_DUO.CONF
[duo]
; values from the Duo Admin Panel (UNIX Application)
ikey = <integration key>
skey = <secret key>
host = api-xxxxxxxx.duosecurity.com
; secure = deny login if Duo can't be reached; safe = allow login without MFA
failmode = secure
pushinfo = yes
autopush = yes
BASH
chown root:root /etc/duo/pam_duo.conf
chmod 600 /etc/duo/pam_duo.conf

failmode = secure is the safe default for production: if Duo is unreachable, nobody logs in. safe lets people in without MFA in that case — convenient in a LAB, but an attacker who can block the Duo API bypasses MFA. Keep console access available either way.

4Add Duo to PAM

Put pam_duo right after pam_unix, so the password is checked first and Duo second:

PAM
# /etc/pam.d/password-auth  (and system-auth for su/console logins)
auth        required      pam_env.so
auth        requisite     pam_unix.so nullok try_first_pass
auth        sufficient    /lib64/security/pam_duo.so
auth        required      pam_deny.so

password-auth is used by sshd; system-auth by local logins and su.

On OL8/OL9 these files are generated by authselect and are overwritten when the profile changes. For a permanent setup, create a custom profile (authselect create-profile duo -b sssd), add the line there and select it.

5Configure sshd

BASH
# /etc/ssh/sshd_config
UsePAM yes
ChallengeResponseAuthentication yes     # KbdInteractiveAuthentication yes on OL9/RHEL9
UseDNS no

systemctl restart sshd

With key-based SSH the password stack is skipped, so Duo never runs. To require key and Duo, add pam_duo to /etc/pam.d/sshd instead and set AuthenticationMethods publickey,keyboard-interactive in sshd_config — see Duo's documentation for the exact lines.

6Allow Duo Through SELinux

BASH
getsebool -a | grep duo
pam_duo_permit_local_login --> off
pam_duo_permit_sshd --> on

setsebool -P pam_duo_permit_local_login on     # -P keeps it after reboot

pam_duo_permit_sshd is on by default; turn on pam_duo_permit_local_login if you protect local logins and su as well.

7Test

From a new terminal (keep the root session open):

OUTPUT
$ ssh nsunke@o18cdb01
Password:
Autopushing login request to phone...
Success. Logging you in...

The first time, Duo asks the user to enrol — open the link it prints. The same works for su once system-auth has the Duo line:

OUTPUT
[root@o18cdb01 ~]# su - nsunke
[nsunke@o18cdb01 ~]$ su - nsunke
Password:
Autopushing login request to phone...
Pushed a login request to your device...
Success. Logging you in...

Approve the push in Duo Mobile and you're in. Duo's logs in the Admin Panel show every authentication.

Based on Duo's Duo Unix documentation. Test carefully on a non-production server first.
