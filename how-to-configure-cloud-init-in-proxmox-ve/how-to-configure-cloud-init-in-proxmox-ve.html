How to Configure Cloud-Init in Proxmox VE

By Sunke Nithin · April 22, 2025   VirtualizationProxmox

Cloud-Init lets every VM you clone from a template come up with its own hostname, user, SSH key and IP address — no console work after the clone. Proxmox passes these settings to the guest through a small CloudInit drive.

How It Fits Together

VM with cloud-init installed → clean it → add CloudInit drive → convert to template → clone → set user/IP → start

The order matters: install and clean before templating, and add the CloudInit drive to the VM before (or right after) converting it. Settings on the Cloud-Init tab are applied per clone.

1Install Cloud-Init in the VM

Start from a VM with a freshly installed Linux (see Create a Linux VM in Proxmox VE) and install the packages:

BASH
# Ubuntu / Debian
sudo apt update && sudo apt install -y cloud-init qemu-guest-agent

# Oracle Linux / RHEL / Rocky / Alma
sudo dnf install -y cloud-init qemu-guest-agent
sudo systemctl enable cloud-init qemu-guest-agent

2Clean the VM and Shut It Down

Without this, every clone shares the same machine-id (and therefore the same DHCP lease) and SSH host keys, and cloud-init thinks it has already run:

BASH
# inside the VM, last thing before shutdown
sudo cloud-init clean --logs          # forget the previous first boot
sudo truncate -s 0 /etc/machine-id    # each clone gets a new machine-id
sudo rm -f /var/lib/dbus/machine-id
sudo rm -f /etc/ssh/ssh_host_*        # new host keys on each clone
sudo shutdown -h now

3Add a CloudInit Drive

  1. Select the VM → Hardware → Add → CloudInit Drive.
  2. Pick a storage (for example local-lvm or vmdata) and click Add.

4Convert to a Template

Right-click the VM → Convert to template. A template can't be started; it can only be cloned.

5Clone and Set the Cloud-Init Values

  1. Right-click the template → Clone; give a VM ID and name. Full Clone is independent; Linked Clone is faster and smaller but depends on the template's disk.
  2. On the new VM's Cloud-Init tab set User, Password and/or SSH public key, DNS, and IP Config (DHCP or static).
  3. Click Regenerate Image, then start the VM.

The hostname comes from the VM name. The same from the shell:

BASH
qm clone 9000 201 --name web01 --full
qm set 201 --ciuser nithin --sshkeys ~/.ssh/id_ed25519.pub \
   --ipconfig0 ip=192.168.1.51/24,gw=192.168.1.1 --nameserver 192.168.1.10
qm resize 201 scsi0 +20G
qm start 201

6Check the Result Inside the VM

BASH
cloud-init status --long
sudo less /var/log/cloud-init.log
sudo less /var/log/cloud-init-output.log
Better template source: instead of installing an OS from ISO, import a distribution's official cloud image — it already contains cloud-init and is cleaned for templating. Ubuntu, Debian, Oracle Linux, Rocky and Alma all publish them.
BASH · OPTIONAL
# on the Proxmox host: template from an official cloud image
cd /var/lib/vz/template/iso
wget https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img

qm create 9000 --name ubuntu-cloud --memory 2048 --cores 2 \
   --net0 virtio,bridge=vmbr0 --scsihw virtio-scsi-single
qm set 9000 --scsi0 vmdata:0,import-from=/var/lib/vz/template/iso/noble-server-cloudimg-amd64.img
qm set 9000 --ide2 vmdata:cloudinit --boot order=scsi0 \
   --serial0 socket --vga serial0 --agent enabled=1
qm template 9000

Advanced settings that the GUI doesn't offer (packages, run commands) can be passed with a custom snippet: qm set 201 --cicustom "user=local:snippets/user.yaml" (the storage must have the Snippets content type enabled).
