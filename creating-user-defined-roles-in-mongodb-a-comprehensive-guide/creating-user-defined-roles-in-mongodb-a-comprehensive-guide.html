Creating User-Defined Roles in MongoDB: A Comprehensive Guide

By Sunke Nithin · October 14, 2026   DatabaseMongoDB

MongoDB's flexibility as a NoSQL database makes it a popular choice for managing large datasets, but securing access to those datasets is critical. User-defined roles let administrators create custom permissions tailored to specific application or organizational needs, offering granular control beyond built-in roles like read or readWrite. This post explains how to create and manage user-defined roles in MongoDB.

1Why Create User-Defined Roles?

User-defined roles are essential when built-in roles are too broad or too restrictive for your use case. They give precise control over database operations, so users only perform authorized actions.

Granular Access ControlRestrict users to specific actions (e.g. find, insert) on particular collections or databases.
Application-Specific PermissionsTailor roles for applications, such as letting a logging service write to one collection.
Compliance and SecurityMeet regulatory requirements by limiting access to sensitive data.
Team-Based PermissionsGive different teams, such as developers or analysts, their own permissions.

User-defined roles are ideal for scenarios that require collection-level access control.

2Prerequisites

  • MongoDB is running with authentication enabled (--auth flag, or security.authorization: enabled in mongod.conf).
  • You are connected as a user with the userAdminAnyDatabase, userAdmin or root role.
  • You know the target database, collections and actions for the custom role.

3Step-by-Step Guide to Creating User-Defined Roles

Step 1Connect to the MongoDB Shell

Connect to your MongoDB instance and authenticate as an admin user:

BASH
mongosh -u mongoadm -p

Only users with appropriate privileges, such as userAdminAnyDatabase or root, can create roles.

Step 2Switch to the Target Database

Roles are defined in the database where they will be applied. Switch to the desired database:

MONGOSH
use myDatabase

Step 3Create a User-Defined Role

Use db.createRole() to define a custom role. Specify the role name, its privileges and any inherited roles. The syntax is:

SYNTAX
db.createRole({
  role: "<roleName>",
  privileges: [
    {
      resource: { db: "<database>", collection: "<collection>" },
      actions: ["<action1>", "<action2>", ...]
    }
  ],
  roles: [
    { role: "<inheritedRole>", db: "<database>" }
  ]
})

Example: create a role logWriter that can read from dataCollection and insert into logCollection:

MONGOSH
db.createRole({
  role: "logWriter",
  privileges: [
    { resource: { db: "myDatabase", collection: "dataCollection" }, actions: ["find"] },
    { resource: { db: "myDatabase", collection: "logCollection" },  actions: ["insert"] }
  ],
  roles: []
})

You can also inherit existing roles to combine permissions:

MONGOSH
db.createRole({
  role: "logWriterWithRead",
  privileges: [
    { resource: { db: "myDatabase", collection: "logCollection" }, actions: ["insert"] }
  ],
  roles: [{ role: "read", db: "myDatabase" }]
})

This example inherits the built-in read role for read access to the whole database, and adds a specific insert privilege on top.

Step 4Assign the Role to a User

Assign the custom role to a new or an existing user:

MONGOSH
// For a new user
db.createUser({
  user: "logUser",
  pwd: "xxxxxxx",
  roles: [{ role: "logWriter", db: "myDatabase" }]
})

// For an existing user
db.grantRolesToUser("existingUser", [{ role: "logWriter", db: "myDatabase" }])
Note: a user created while you are in myDatabase belongs to myDatabase, so that user must log in with --authenticationDatabase myDatabase.

Step 5Verify the Role

Check the role's details to make sure it was created correctly:

MONGOSH
db.getRole("logWriter", { showPrivileges: true })

Then log in as logUser and check which actions are allowed:

MONGOSH
// mongosh -u logUser -p --authenticationDatabase myDatabase
use myDatabase
db.dataCollection.find()                             // Should succeed
db.logCollection.insertOne({ event: "Log entry" })   // Should succeed
db.dataCollection.insertOne({ name: "Test" })        // Should fail

Step 6Modify or Drop a Role

To update a role's privileges, use db.updateRole():

MONGOSH
db.updateRole("logWriter", {
  privileges: [
    { resource: { db: "myDatabase", collection: "dataCollection" }, actions: ["find", "update"] },
    { resource: { db: "myDatabase", collection: "logCollection" },  actions: ["insert"] }
  ],
  roles: []
})
db.updateRole() replaces the whole privileges array; it does not add to it. List every privilege the role should keep.

To delete a role, use db.dropRole():

MONGOSH
db.dropRole("logWriter")
Be cautious: dropping a role removes it from every user that was assigned it.

4Common Privilege Actions

When defining privileges, you can use actions like:

ActionAllows
findRead data from a collection
insertAdd new documents
updateModify existing documents
removeDelete documents
createIndexCreate indexes
viewRoleView role definitions

See MongoDB Privilege Actions for the complete list.

5Best Practices

  • Minimal privileges: grant only the actions a user needs, to reduce security risk.
  • Descriptive role names: use clear names (e.g. logWriter, dataReader) that reflect the role's purpose.
  • Inherit built-in roles: combine custom privileges with built-in roles for efficiency.
  • Test thoroughly: log in as a test user to confirm the role behaves as expected.
  • Secure admin access: restrict role creation to users with userAdmin or userAdminAnyDatabase.
  • Document roles: keep a record of custom roles for team collaboration and auditing.

6Troubleshooting

ProblemWhat to check
Permission deniedThe admin user has userAdmin or userAdminAnyDatabase privileges.
Role not foundThe role was created in the correct database — check with db.getRole().
User access issuesThe role's privileges — db.getRole("<role>", { showPrivileges: true }).
Authentication errorsThe user authenticates against the correct database using --authenticationDatabase.

Conclusion

Creating user-defined roles in MongoDB with db.createRole() lets administrators enforce precise access control, improving security and compliance. By tailoring permissions to specific collections or actions, you can meet complex application needs while keeping the environment secure.
