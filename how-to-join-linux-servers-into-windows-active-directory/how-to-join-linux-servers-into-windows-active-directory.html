How to Join Linux Servers into Windows Active Directory

By Sunke Nithin · April 8, 2025   LinuxLinuxActive Directory

Joining Linux servers to Active Directory lets people log in with their AD accounts, and lets you control access and sudo rights with AD groups — no local users to keep in sync. With realmd, adcli and SSSD it takes a few commands.

Why Join Linux to AD?

  • One set of accounts and passwords for Windows and Linux
  • Access and sudo controlled by AD group membership
  • Disabling a user in AD locks them out of every server
  • Kerberos single sign-on between joined machines

Prerequisites

  • A working AD domain — mine is scslabs.com
  • A Linux server (RHEL/Oracle Linux/Rocky/Alma 7–9 or Ubuntu)
  • An AD account allowed to join computers to the domain
  • DNS on the Linux server pointing at the domain controllers, and time in sync with them (Kerberos tolerates only 5 minutes of skew)
BASH
# DNS must point at the domain controller(s)
cat /etc/resolv.conf
realm discover scslabs.com

realm discover should show the domain and list the packages it needs.

1Install the Packages

BASH
# RHEL / Oracle Linux 8 / 9, Rocky, Alma
sudo dnf install -y realmd sssd oddjob oddjob-mkhomedir adcli samba-common-tools krb5-workstation

# RHEL / OL 7
sudo yum install -y realmd sssd oddjob oddjob-mkhomedir adcli samba-common-tools krb5-workstation

# Ubuntu / Debian
sudo apt install -y realmd sssd sssd-tools libnss-sss libpam-sss adcli samba-common-bin oddjob oddjob-mkhomedir packagekit

2Join the Domain

BASH
sudo realm join --user=nsunke scslabs.com          # prompts for the AD password
realm list
id nsunke@scslabs.com

realm join creates the computer account in AD, writes /etc/krb5.keytab, configures SSSD and PAM, and enables home-directory creation on first login. Add --computer-ou="OU=Linux,OU=Servers,DC=scslabs,DC=com" to put the computer object in a specific OU.

3Log In Without the Domain Suffix

By default users log in as nsunke@scslabs.com. To allow just nsunke:

BASH
# /etc/sssd/sssd.conf  ([domain/scslabs.com] section)
use_fully_qualified_names = False
fallback_homedir = /home/%u

sudo systemctl restart sssd
sudo sss_cache -E                 # clear cached lookups
id nsunke

4Test

BASH
ssh nsunke@linux-server.scslabs.com

5Restrict Who Can Log In, and Give sudo

After the join, every domain user can log in. Limit it to a group and grant that group sudo:

BASH
# only allow members of an AD group to log in
sudo realm deny --all
sudo realm permit -g linuxadmins

# sudo for that group
echo '%linuxadmins ALL=(ALL) ALL' | sudo tee /etc/sudoers.d/linuxadmins
sudo chmod 440 /etc/sudoers.d/linuxadmins
sudo visudo -cf /etc/sudoers.d/linuxadmins

Tips

  • SSSD caches credentials, so users can still log in if the domain controller is briefly unreachable.
  • Troubleshoot with journalctl -u sssd and by setting debug_level = 6 in sssd.conf.
  • To leave the domain: sudo realm leave scslabs.com.
