Converting a Single-Instance ASM Database to RAC (Manual Method)

By Sunke Nithin · June 24, 2019   DatabaseOracleRac

A single-instance database already on ASM, on a cluster with Grid Infrastructure and a RAC-enabled database home, can be turned into a two-instance RAC database by hand: add a redo thread and undo for the second instance, set the cluster parameters, and register it with the clusterware. This was done on 11.2.0.4 (database asmrac, nodes rac1 and rac2); the steps are the same on 12c–19c with the newer srvctl option names.

Prerequisites

  • Grid Infrastructure on both nodes, the database files in a shared ASM disk group.
  • The same Oracle home path installed on both nodes, linked with the RAC option.
  • A full backup.

1Redo Thread and Undo for Instance 2

SQL
-- redo logs for thread 2 (as many groups and the same size as thread 1)
alter database add logfile thread 2 group 4 ('+DATA') size 200m;
alter database add logfile thread 2 group 5 ('+DATA') size 200m;
alter database add logfile thread 2 group 6 ('+DATA') size 200m;
alter database enable public thread 2;

-- undo for the second instance
create undo tablespace undotbs2 datafile '+DATA' size 500m autoextend on;

select thread#, group#, status from v$log order by 1,2;

2Cluster Parameters

Create a pfile from the current spfile and add:

PFILE
*.cluster_database=true
*.cluster_database_instances=2
asmrac1.instance_number=1
asmrac2.instance_number=2
asmrac1.thread=1
asmrac2.thread=2
asmrac1.undo_tablespace='UNDOTBS1'
asmrac2.undo_tablespace='UNDOTBS2'
*.remote_listener='rac-scan:1521'

The thread settings are essential — without asmrac2.thread=2 the second instance tries to use thread 1 and fails to start. They were missing from my original notes.

SQL
-- on node 1, from the running single instance
create pfile='/tmp/initasmrac.ora' from spfile;
-- edit /tmp/initasmrac.ora: add the lines above, then
shutdown immediate

3Shared spfile, Password File and Directories

BASH
# node 1
export ORACLE_SID=asmrac1
sqlplus / as sysdba
SQL> create spfile='+DATA/ASMRAC/spfileasmrac.ora' from pfile='/tmp/initasmrac.ora';
SQL> exit

# pointer files on BOTH nodes
echo "SPFILE='+DATA/ASMRAC/spfileasmrac.ora'" > $ORACLE_HOME/dbs/initasmrac1.ora           # node 1
ssh rac2 "echo \"SPFILE='+DATA/ASMRAC/spfileasmrac.ora'\" > $ORACLE_HOME/dbs/initasmrac2.ora"  # node 2

# password file and audit directory on node 2
scp $ORACLE_HOME/dbs/orapwasmrac rac2:$ORACLE_HOME/dbs/orapwasmrac2
ssh rac2 mkdir -p /o01/home/oracle/admin/asmrac/adump

4Register with the Clusterware

BASH
# re-register as a RAC database (11.2 syntax)
srvctl remove database -d asmrac
srvctl add database -d asmrac -o /o01/home/oracle/11.2.0.4/db -p '+DATA/ASMRAC/spfileasmrac.ora'
srvctl add instance -d asmrac -i asmrac1 -n rac1
srvctl add instance -d asmrac -i asmrac2 -n rac2
srvctl start database -d asmrac
srvctl status database -d asmrac
Instance asmrac1 is running on node rac1
Instance asmrac2 is running on node rac2

# /etc/oratab on each node: asmrac1 on rac1, asmrac2 on rac2
SQL
select inst_id, instance_name, host_name, thread#, status from gv$instance;
Easier alternatives: rconfig (an XML-driven tool in $ORACLE_HOME/bin) converts a single-instance database to RAC, and DBCA can do it in some versions. The manual way shows what changes underneath. Related: Two-node RAC on VirtualBox · Stop and start a RAC database.
