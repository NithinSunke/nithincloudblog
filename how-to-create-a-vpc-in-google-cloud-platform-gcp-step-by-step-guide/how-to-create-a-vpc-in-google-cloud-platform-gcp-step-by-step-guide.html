How to Create a VPC in Google CLOUD Platform (GCP): Step-by-Step Guide

By Sunke Nithin · August 9, 2025   CLOUDGCP

In GCP every VM, GKE cluster and load balancer lives in a VPC network. A GCP VPC is global, and its subnets are regional. This guide creates a custom-mode VPC — first in the Console, then with gcloud.

Why Custom Mode?

New projects come with a default auto-mode VPC: one subnet per region from 10.128.0.0/9, plus permissive default firewall rules. A custom-mode VPC starts empty: you choose which regions get subnets and which ranges they use, so they won't collide with on-premises or peered networks.

Prerequisites

  • A project with billing enabled and the Compute Engine API turned on
  • A role that can create networks, such as roles/compute.networkAdmin (or Editor/Owner in a LAB)

Method 1: Cloud Console

1. Open VPC networks

Menu → VPC network → VPC networks → Create VPC network.

2. Name and mode

Name gcplab-vpc, subnet creation mode Custom.

3. Add a subnet

Name subnet-us-central1-ext, region us-central1, IPv4 range 10.0.0.0/24. Turn Private Google Access on if VMs without external IPs need Google APIs. Add more subnets in other regions as needed.

4. Firewall rules and routing

The wizard offers ready-made rules (ICMP, RDP, SSH, internal). Note that they allow 0.0.0.0/0 — fine for a short test, but narrow the sources for anything that stays up. Keep dynamic routing Regional unless you use Cloud Router across regions. Click Create.

Method 2: gcloud CLI

0. Open Cloud Shell

Click the terminal icon at the top right of the Console and authorize it — see Mastering Google Cloud Shell.

1. Create the VPC

BASH
gcloud compute networks create my-custom-vpc \
    --subnet-mode=custom

2. Create a subnet

BASH
gcloud compute networks subnets create subnet-us-central1 \
    --network=my-custom-vpc \
    --region=us-central1 \
    --range=10.1.0.0/24 \
    --enable-private-ip-google-access

3. Firewall rules

BASH
# what I ran — no --source-ranges, so it defaults to 0.0.0.0/0 (the whole internet)
gcloud compute firewall-rules create allow-ssh-icmp-rdp \
    --network=my-custom-vpc \
    --allow=tcp:22,tcp:3389,icmp
This rule opens SSH, RDP and ping to the entire internet. Without --source-ranges, an ingress rule applies to 0.0.0.0/0, and exposed SSH/RDP ports are scanned and brute-forced within minutes. Restrict the sources:
BASH
# better: SSH via IAP, RDP and ICMP only from your own IP
gcloud compute firewall-rules create allow-ssh-iap \
    --network=my-custom-vpc --allow=tcp:22 \
    --source-ranges=35.235.240.0/20

gcloud compute firewall-rules create allow-rdp-icmp-admin \
    --network=my-custom-vpc --allow=tcp:3389,icmp \
    --source-ranges=<your-public-ip>/32

35.235.240.0/20 is the range Identity-Aware Proxy uses for TCP forwarding, so gcloud compute ssh --tunnel-through-iap works without VMs needing external IPs.

Best Practices

  • Keep VMs on internal IPs and use Cloud NAT for outbound internet — see Private Google Access and Cloud NAT.
  • Target firewall rules with network tags or service accounts rather than applying them to all instances.
  • Don't use the default VPC for production; delete it in projects that don't need it.
  • Plan ranges up front; a subnet can grow later — see Extend a subnet in GCP.
