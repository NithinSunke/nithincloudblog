Migrating a Database from File System to ASM with a Short Downtime

By Sunke Nithin · August 4, 2022   DatabaseOracleMigration

Moving a database from file-system storage into ASM doesn't need a long outage. RMAN copies the data files into ASM while the database stays open; the downtime is just a restart, a switch to the copies and a quick recovery of the changes made meanwhile. Here the database snd moves from /h01/oracle/oradata into the disk groups +SRD_DATA and +SRD_FRA.

1Record Where Everything Is

SQL
show parameter control_files
select name from v$datafile;
select member from v$logfile;
select name from v$tempfile;
show parameter db_recovery_file_dest
archive log list

Control files, five data files, three redo groups and a temp file are all on the file system; the database is in archive log mode (required for an online copy).

2Check the Disk Groups

SQL
select name, state, type, total_mb, free_mb,
       round((1-free_mb/total_mb)*100,2) pct_used
from   v$asm_diskgroup where total_mb > 0 order by name;

NAME       STATE    TYPE    TOTAL_MB  FREE_MB  PCT_USED
CRS        MOUNTED  EXTERN     30720    24874     19.03
SRD_DATA   MOUNTED  EXTERN     10240     2715     73.49
SRD_FRA    MOUNTED  EXTERN     10240     2904     71.64

Make sure the data disk group has room for all data files, and the FRA disk group for archive logs and backups.

3Copy the Data Files Into ASM — Online

RMAN
RMAN> backup as copy database format '+SRD_DATA';

input datafile file number=00001 name=/h01/oracle/oradata/snd/system01.dbf
output file name=+SRD_DATA/SND/DATAFILE/system.289.1111865763 tag=TAG20220804T193517
...
Finished backup at 04-AUG-22

Image copies of every data file land in +SRD_DATA. Users keep working; this takes as long as the copy does.

4Point New Files at ASM and Move the spfile

SQL
alter system set db_recovery_file_dest='+SRD_FRA';
alter system set db_create_file_dest='+SRD_DATA';
alter system set db_create_online_log_dest_1='+SRD_DATA';
alter system set db_create_online_log_dest_2='+SRD_FRA';
create spfile='+SRD_DATA' from memory;
BASH
# replace the spfile in $ORACLE_HOME/dbs with a pointer (single instance)
cd $ORACLE_HOME/dbs
mv spfilesnd.ora spfilesnd.ora.old
echo "SPFILE='+SRD_DATA/SND/PARAMETERFILE/spfile.xxx.xxxxxxxxx'" > initsnd.ora

# Grid Infrastructure / RAC: register it with the clusterware instead
srvctl modify database -db snd -spfile '+SRD_DATA/SND/PARAMETERFILE/spfile.xxx.xxxxxxxxx'

Find the spfile's generated name with asmcmd ls +SRD_DATA/SND/PARAMETERFILE. (Creating it under an alias like +SRD_DATA/spfilesnd.ora, as I originally did, also works.)

5Downtime Starts: Relocate the Control Files

SQL
shutdown immediate
startup nomount
alter system set control_files='+SRD_DATA','+SRD_FRA' scope=spfile;
shutdown immediate
startup nomount

6Switch to the Copies and Recover

RMAN
rman target /

RMAN> restore controlfile from '/h01/oracle/oradata/snd/control01.ctl';
output file name=+SRD_DATA/SND/CONTROLFILE/current.296.1111868457
output file name=+SRD_FRA/SND/CONTROLFILE/current.476.1111868457

RMAN> alter database mount;
RMAN> switch database to copy;
datafile 1 switched to datafile copy "+SRD_DATA/SND/DATAFILE/system.289.1111865763"
...
RMAN> recover database;
RMAN> alter database open;

Recovery only applies the redo generated since the copy in step 3, so it takes seconds to minutes. As soon as the database is open, the downtime is over.

7Online: Temp Files and Redo Logs

RMAN doesn't copy temp files; create a new one and drop the old:

SQL
alter tablespace temp add tempfile size 50m;               -- created in +SRD_DATA
alter database tempfile '/h01/oracle/oradata/snd/temp01.dbf' drop including datafiles;

Online redo logs can be replaced while the database is open:

SQL
-- new groups go to +SRD_DATA and +SRD_FRA (one member each)
alter database add logfile size 200m;
alter database add logfile size 200m;
alter database add logfile size 200m;

-- cycle until groups 1-3 are INACTIVE
alter system switch logfile;
alter system checkpoint;
select group#, status from v$log;

alter database drop logfile group 1;
alter database drop logfile group 2;
alter database drop logfile group 3;

8Verify and Back Up

SQL
select name from v$datafile union all select name from v$tempfile
union all select member from v$logfile union all select name from v$controlfile;
-- everything should now start with +SRD_DATA or +SRD_FRA

RMAN> backup database plus archivelog;
RMAN> delete copy of database tag 'TAG...';   -- only if old copies are listed

Take a fresh full backup — the old file-system copies are no longer part of the database — and once you're satisfied, remove the old files from /h01/oracle/oradata/snd.

For a RAC or Oracle Restart database, use srvctl stop/start database for the restarts and keep the spfile location in the clusterware configuration (step 4). Related: Converting a non-ASM database to ASM · Moving ASM disk groups to new storage.
