Set Up an SMTP Relay Using Gmail with Postfix

By Sunke Nithin · June 27, 2019   Linux

Servers often need to send email — cron job output, backup reports, database alerts. Rather than run a full mail server, you can have Postfix relay everything through a Gmail account. These steps are for Oracle Linux / RHEL / CentOS.

install Postfix + SASL→Gmail app password→sasl_passwd→main.cf→restart→test

1Install the Packages

BASH · ROOT
yum install -y postfix cyrus-sasl-plain mailx
yum remove -y sendmail
systemctl enable --now postfix
  • cyrus-sasl-plain is required — without it Postfix can't log in to Gmail and logs "SASL authentication failed; no mechanism available".
  • On Oracle Linux 8/9, use dnf; the mail command comes from the s-nail package there.

2Create a Gmail App Password

Gmail no longer accepts your normal account password from other mail programs. Turn on 2-Step Verification for the Google account, then create an app password at myaccount.google.com/apppasswords. It's a 16-character code; use it in the next step instead of your real password. Ideally use a dedicated Gmail account for server mail.

3Store the Credentials

/ETC/POSTFIX/SASL_PASSWD
[smtp.gmail.com]:587 yourname@gmail.com:abcdefghijklmnop
BASH · ROOT
chmod 600 /etc/postfix/sasl_passwd
postmap hash:/etc/postfix/sasl_passwd

The host part must match relayhost exactly, brackets and port included. postmap builds sasl_passwd.db, which Postfix actually reads — re-run it whenever you change the file.

4Configure the Relay

BASH · ROOT
cd /etc/postfix
cp main.cf main.cf.orig
vi main.cf

Add at the end:

/ETC/POSTFIX/MAIN.CF
# --- Gmail relay ---
relayhost = [smtp.gmail.com]:587

smtp_sasl_auth_enable = yes
smtp_sasl_password_maps = hash:/etc/postfix/sasl_passwd
smtp_sasl_security_options = noanonymous

smtp_tls_security_level = encrypt
smtp_tls_mandatory_protocols = !SSLv2, !SSLv3, !TLSv1, !TLSv1.1
smtp_tls_CAfile = /etc/pki/tls/certs/ca-bundle.crt
SettingWhy
relayhost = [smtp.gmail.com]:587Send all mail via Gmail's submission port. The brackets stop Postfix doing an MX lookup.
smtp_sasl_*Log in with the credentials from sasl_passwd
smtp_tls_security_level = encryptAlways use TLS to Gmail
smtp_tls_mandatory_protocolsAllow only TLS 1.2 and newer — Gmail no longer accepts TLS 1.0
My original config pinned smtp_tls_mandatory_protocols = TLSv1. That was fine in 2019, but TLS 1.0 is obsolete and Gmail rejects it, so use the line above.

5Restart Postfix

BASH · ROOT
postfix check
systemctl restart postfix

6Send a Test Email

BASH
echo "Did you get this?" | mail -s "Test email from $(hostname)" someone@example.com

Watch the log while it sends:

BASH · ROOT
tail -f /var/log/maillog

Look for status=sent (250 2.0.0 OK …). Mail sent this way appears to come from the Gmail account.

Troubleshooting

Log messageFix
SASL authentication failed; no mechanism availableInstall cyrus-sasl-plain
535-5.7.8 Username and Password not acceptedUse an app password, check the username, and re-run postmap
Connection timed out to port 587Outbound 587 is blocked by a firewall or your cloud provider
Mail stuck in queuemailq to see it, postqueue -f to retry
