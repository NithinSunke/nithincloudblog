Running Your Own Certificate Authority with XCA

By Sunke Nithin · May 20, 2024   LABSecurityHome LAB

XCA is a free desktop application for creating and managing keys and certificates. In my Home LAB it's the private certificate authority behind every HTTPS service — Nginx Proxy Manager, ESXi, vCenter — so browsers trust them without warnings. The setup: a root CA, an intermediate CA signed by it, and server certificates signed by the intermediate.

Root CA (10 years, kept offline) → Intermediate CA (5 years) → server certificates (1 year)

1Install XCA and Create a Database

  1. Download XCA for Windows, macOS or Linux from hohnstaedt.de/xca (also in the Microsoft Store) and install it.
  2. Start it and choose File → New DataBase. Protect it with a strong password — it will hold all your private keys. Back the file up.

2Create the Root CA

  1. Certificates tab → New Certificate.
  2. Source tab: Create a self-signed certificate; template [default] CA → Apply all.
  3. Subject tab: fill in a name, e.g. Common name SCSLabs Root CA, organization, country; click Generate a new key (RSA 4096).
  4. Extensions tab: Type Certification Authority, validity 10 years.
  5. Key usage tab: Certificate Sign and CRL Sign (the CA template sets these).
  6. Click OK.

3Create the Intermediate CA

  1. New Certificate again. Source: Use this Certificate for signing → select the root CA; template [default] CA.
  2. Subject: e.g. SCSLabs Intermediate CA; generate a new key.
  3. Extensions: Certification Authority, validity about 5 years (shorter than the root).
  4. OK. It appears under the root in the tree.

4Trust the CA on Your Computers

Select the root CA → Export → PEM (.crt). On Windows double-click it → Install Certificate → Local Machine → Trusted Root Certification Authorities (or distribute it by Group Policy). Import the intermediate into Intermediate Certification Authorities the same way. Firefox uses its own store unless security.enterprise_roots.enabled is on.

5Issue a Server Certificate

  1. New Certificate. Source: sign with the intermediate CA; template [default] TLS_server.
  2. Subject: Common name = the host's FQDN, e.g. npm.scslabs.xyz; generate a new key (RSA 2048+).
  3. Extensions: validity 1 year; Subject Alternative Name → DNS:npm.scslabs.xyz (add IP: entries if you browse by IP). Browsers ignore the common name — without a SAN the certificate is rejected.
  4. OK.

6Export for the Server

  • Certificate: select it → Export → PEM chain (.pem) — server certificate followed by the intermediate, which most servers (Nginx Proxy Manager, ESXi) want as the certificate file.
  • Private key: Private Keys tab → select the key → Export → PEM, unencrypted, as <host>.key. Copy it only to the server that uses it.

In Nginx Proxy Manager: SSL Certificates → Add → Custom, upload the key and the chain. For ESXi see Renewing the SSL certificate of an ESXi 8 host.

Set a reminder before certificates expire — XCA's certificate list shows the expiry dates, and Renewal on a certificate re-issues it with a new validity.
