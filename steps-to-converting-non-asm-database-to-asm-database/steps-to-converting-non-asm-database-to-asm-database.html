Steps to Convert a Non-ASM Database to ASM

By Sunke Nithin · June 24, 2019   DatabaseOracleMigration

This post moves a database from file-system storage into Oracle ASM using RMAN: the control file, data files, temp file and online redo logs all end up in ASM disk groups, and the fast recovery area moves to +FRA. The example is an 11.2.0.4 database called ASMRAC; the same RMAN steps work on 12c and 19c.

check space→back up spfile→set parameters→restore control file→backup as copy→switch to copy→open→move redo
WhatBeforeAfter
Control file/o01/home/oracle/oradata/asmrac/control01.ctl+DATA
Data files & temp file/o01/home/oracle/oradata/asmrac/+DATA
Online redo logs/o01/home/oracle/oradata/asmrac/+DATA
Fast recovery area/o01/home/oracle/fra+FRA
Downtime: the database is down from step 7 until it's opened in step 11 — roughly as long as RMAN takes to copy the data files. Take a full backup before you start.

1Set the Environment

BASH · ORACLE
. oraenv
ORACLE_SID = [racdv] ? asmrac

2Check the Size of the Database

SQL
SELECT db.name,
       d.df_gbytes             datafile_gbytes,
       t.tf_gbytes             tempfile_gbytes,
       d.df_gbytes + t.tf_gbytes total_gbytes
  FROM (SELECT SUM(bytes)/1024/1024/1024 df_gbytes FROM v$datafile) d,
       (SELECT SUM(bytes)/1024/1024/1024 tf_gbytes FROM v$tempfile) t,
       v$database db;

5Back Up the spfile and pfile

SQL / BASH
SQL> create pfile from spfile;

cd $ORACLE_HOME/dbs
cp spfileasmrac.ora initasmrac.ora /home/oracle/

6Point the Parameters at ASM

SQL
alter system set control_files='+DATA' scope=spfile;
alter system set db_create_file_dest='+DATA' scope=spfile;
alter system set db_recovery_file_dest='+FRA' scope=spfile;

db_create_file_dest makes new files (data files, redo, temp) Oracle-managed files in +DATA, which is why later commands can just say '+DATA'.

7Restart in NOMOUNT

SQL
shutdown immediate
startup nomount

8Restore the Control File into ASM

RMAN
rman target /
RMAN> restore controlfile from '/o01/home/oracle/oradata/asmrac/control01.ctl';
OUTPUT

output file name=+DATA/asmrac/controlfile/current.269.1011814247
Finished restore at 24-JUN-19

RMAN
RMAN> alter database mount;

11Switch to the Copies and Open

RMAN
RMAN> switch database to copy;

RMAN> run {
  set newname for tempfile 1 to '+DATA';
  switch tempfile all;
}

RMAN> alter database open;
OUTPUT
datafile 1 switched to datafile copy "+DATA/asmrac/datafile/system.270.1011814335"
datafile 2 switched to datafile copy "+DATA/asmrac/datafile/sysaux.271.1011814451"
datafile 3 switched to datafile copy "+DATA/asmrac/datafile/undotbs1.273.1011814531"
datafile 4 switched to datafile copy "+DATA/asmrac/datafile/users.274.1011814547"
datafile 5 switched to datafile copy "+DATA/asmrac/datafile/example.272.1011814497"

renamed tempfile 1 to +DATA in control file

Because the database was shut down cleanly before the copy, no recovery is needed — it opens straight away, and the temp file is created in +DATA on open.

12Move the Online Redo Logs

Add an ASM member to each redo group:

SQL
alter database add logfile member '+DATA' to group 1;
alter database add logfile member '+DATA' to group 2;
alter database add logfile member '+DATA' to group 3;

Then drop the file-system members. A member can only be dropped when its group isn't current or still needed for crash recovery, so switch logs (and checkpoint) between drops:

SQL
alter system switch logfile;
alter system checkpoint;

alter database drop logfile member '/o01/home/oracle/oradata/asmrac/redo01.log';
alter database drop logfile member '/o01/home/oracle/oradata/asmrac/redo02.log';

alter system switch logfile;
alter system checkpoint;
alter database drop logfile member '/o01/home/oracle/oradata/asmrac/redo03.log';
ErrorMeaningFix
ORA-00362 / ORA-01517The new ASM member isn't usable yet — the group hasn't been written since you added itSwitch logs until each group has been current once
ORA-01609The group is the current logalter system switch logfile, then retry

13Check the Fast Recovery Area

SQL
show parameter db_recovery

db_recovery_file_dest       string       +FRA

New archived logs and backups now go to +FRA. Anything already in the old /o01/home/oracle/fra stays there — keep it until it's no longer needed for recovery.

Finishing Touches

  • Multiplex the control file. There's only one control file now. Add a second copy in +FRA: set control_files='+DATA/asmrac/controlfile/current.269.1011814247','+FRA' in the spfile, restart in NOMOUNT, restore controlfile from '+DATA/asmrac/controlfile/current.269.1011814247' in RMAN, then update control_files with the new +FRA file name RMAN reports and open the database.
  • Move the spfile into ASM (optional): create spfile='+DATA/asmrac/spfileasmrac.ora' from pfile; and leave a one-line pfile in $ORACLE_HOME/dbs pointing to it. If the database is registered with Clusterware or Oracle Restart, update it with srvctl modify database -d asmrac -p +DATA/asmrac/spfileasmrac.ora.
  • Take a fresh backup now that the files have moved.
  • Clean up the old data files, temp file and redo logs under /o01/home/oracle/oradata/asmrac/ once you've verified the database — after the switch RMAN catalogues them as data file copies, so RMAN> delete datafilecopy all; removes them cleanly (the temp file and redo logs are removed by hand).
