Active Directory Domain Services (AD DS): The Backbone of Enterprise Identity

By Sunke Nithin · August 16, 2025   WindowsActive Directory

In almost every Windows-based organization, Active Directory Domain Services is where identity lives: one directory of users, groups and computers, central authentication, and Group Policy to configure everything. This post explains the main parts, then builds a new forest on Windows Server.

What AD DS Provides

  • Authentication — Kerberos by default, NTLM as a fallback.
  • Authorization — group memberships used in file, application and system permissions.
  • Policy — Group Policy Objects push settings to users and computers.
  • Availability — multi-master replication between domain controllers.

Core Components

ComponentWhat it is
Domain controller (DC)A server running AD DS that holds the directory and authenticates users. Run at least two.
ForestThe top-level security boundary; one or more domains sharing a schema and global catalog.
DomainA unit of administration and replication inside a forest, e.g. scslabs.com.
Organizational unit (OU)A container to organize objects, link GPOs and delegate administration.
Global catalogA searchable partial copy of every object in the forest, used for logons and searches.
FSMO rolesFive single-master roles: Schema Master and Domain Naming Master (per forest); RID Master, PDC Emulator and Infrastructure Master (per domain).
SitesMap the physical network so clients find nearby DCs and replication is scheduled efficiently.

How a Logon Works (Simplified)

  1. The user signs in; the computer finds a DC through DNS.
  2. The DC's Key Distribution Center verifies the password and issues a ticket-granting ticket (TGT).
  3. For each server or service accessed, the client presents the TGT and receives a service ticket.
  4. The service checks the ticket and the user's group memberships to grant access.

Kerberos depends on DNS and on clocks being within five minutes of each other — the two most common causes of AD trouble.

Install a New Forest

Prepare the server

POWERSHELL
# static IP and DNS first (this server will be the DNS server)
New-NetIPAddress -InterfaceAlias Ethernet0 -IPAddress 192.168.1.10 -PrefixLength 24 -DefaultGateway 192.168.1.1
Set-DnsClientServerAddress -InterfaceAlias Ethernet0 -ServerAddresses 127.0.0.1
Rename-Computer -NewName DC01 -Restart

Server Manager

  1. Manage → Add Roles and Features → Role-based installation → select the server.
  2. Tick Active Directory Domain Services, accept the management tools, Next through Features, Install.
  3. Click the flag notification → Promote this server to a domain controller.
  4. Add a new forest, root domain name scslabs.com.
  5. Keep DNS server and Global Catalog ticked; set the DSRM password (used for directory recovery — store it safely).
  6. Accept the NetBIOS name and paths, run the prerequisite check, Install. The server restarts.

Or with PowerShell

POWERSHELL
Install-WindowsFeature AD-Domain-Services -IncludeManagementTools

Install-ADDSForest `
  -DomainName scslabs.com `
  -DomainNetbiosName SCSLABS `
  -InstallDns `
  -SafeModeAdministratorPassword (Read-Host -AsSecureString 'DSRM password')
# the server restarts as a domain controller

Verify

POWERSHELL
Get-ADDomain | Select-Object DNSRoot, NetBIOSName, DomainMode
Get-ADDomainController -Filter * | Select-Object HostName, IPv4Address, IsGlobalCatalog
netdom query fsmo
dcdiag /q                       # no output = no errors
