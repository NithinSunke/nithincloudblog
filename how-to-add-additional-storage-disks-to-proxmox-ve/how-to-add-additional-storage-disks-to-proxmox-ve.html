How to Add Additional Storage Disks to Proxmox VE

By Sunke Nithin · April 22, 2025   VirtualizationProxmox

Once your Proxmox VE server is running, the next job is usually more disk space for VMs. This guide turns a new, empty disk into an LVM-Thin storage called vmdata — thin-provisioned, snapshot-capable, and ready for VM disks and containers.

Prerequisites

  • A running Proxmox VE host (8.4 in the screenshots)
  • An extra disk attached to it, physical or virtual — here a 1 TB /dev/sdb
  • Root shell access (the web GUI Shell or SSH)
Check the device name twice. pvcreate on the wrong disk destroys whatever is on it. The new disk is the one with no partitions and no mount points.

1Identify the New Disk

sda carries the Proxmox install (pve-root, pve-swap, pve-data); sdb is the new disk.

2Create the Physical Volume, Volume Group and Thin Pool

BASH
# 1. find the new disk (no partitions, not mounted)
lsblk

# 2. make it an LVM physical volume
pvcreate /dev/sdb

# 3. put it in its own volume group
vgcreate vmdata /dev/sdb

# 4. create a thin pool, leaving a little room for pool metadata
lvcreate -L 1023g -T vmdata/vmthinpool
#   or simply:  lvcreate -l 95%FREE -T vmdata/vmthinpool
pvs; lvs

The warning about zeroing and chunk size is informational. The thin pool vmthinpool now shows up in lvs with the twi-a-tz-- attributes.

3Add the Thin Pool to Proxmox

Datacenter → Storage → Add → LVM-Thin, then set:

  • ID: vmdata (the name Proxmox shows)
  • Volume group: vmdata
  • Thin Pool: vmthinpool
  • Content: Disk image, Container

Or do the same from the shell:

BASH
# same result as the GUI step
pvesm add lvmthin vmdata --vgname vmdata --thinpool vmthinpool --content images,rootdir
pvesm status

The new storage appears under the node and is offered as a target when you create VMs.

What LVM-Thin can hold: VM disk images and container volumes only. ISO images, templates and vzdump backups need file-based storage — a Directory, NFS/SMB share, or a Proxmox Backup Server. To use a disk for those, format it (for example mkfs.ext4), mount it via /etc/fstab and add it as Add → Directory.

Adding More Disks

You can repeat steps 1–3 for each disk to get a separate storage per disk, or grow the existing pool:

BASH
# add a second disk to the same pool instead of creating a new storage
pvcreate /dev/sdc
vgextend vmdata /dev/sdc
lvextend -l +100%FREE vmdata/vmthinpool
lvextend --poolmetadatasize +1G vmdata/vmthinpool   # keep metadata in proportion

Spanning one pool across disks has no redundancy: if any of them fails, the whole pool is lost. For redundancy use hardware RAID or a ZFS mirror/RAIDZ (Node → Disks → ZFS).
