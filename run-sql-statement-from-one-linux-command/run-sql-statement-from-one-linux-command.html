Run a SQL Statement from a Single Linux Command

By Sunke Nithin · September 6, 2019   DatabaseLinux

For quick checks and scripts you don't need an interactive SQL*Plus session — you can pipe a statement straight into sqlplus from the shell. Here's the one-liner, the $ trap that catches everyone, and a few better variants for scripts.

1The One-Liner

BASH
echo 'select * from v$version;' | sqlplus -s / as sysdba
OUTPUT
BANNER                                                                           CON_ID
-------------------------------------------------------------------------------- ----------
Oracle Database 12c Enterprise Edition Release 12.2.0.1.0 - 64bit Production              0
PL/SQL Release 12.2.0.1.0 - Production                                                    0
CORE    12.2.0.1.0      Production                                                        0
  • -s (silent) hides the SQL*Plus banner and prompts, so only the result is printed.
  • / as sysdba uses OS authentication — run it as the oracle user with ORACLE_SID set.
Watch the $. Inside double quotes the shell expands $version as a shell variable — usually empty — so SQL*Plus receives select * from v; and fails with ORA-00942. Use single quotes as above, or escape it: "select * from v\$version;".

2Don't Put Passwords on the Command Line

sqlplus -s system/password works, but the password is visible to anyone running ps and ends up in your shell history. Prefer, in order:

  • OS authentication: sqlplus -s / as sysdba
  • A secure external password store (wallet): sqlplus -s /@mydb_alias
  • Connecting inside the input, so it never appears in the process list:
BASH
sqlplus -s /nolog <<EOF
connect system/"$SYSTEM_PWD"@orclpdb
select name, open_mode from v\$database;
EOF

3Several Statements: a Here-Document

For more than one statement, a here-document is cleaner than echo:

BASH
sqlplus -s / as sysdba <<'EOF'
set pagesize 100 linesize 200 feedback off
select instance_name, status from v$instance;
select name, open_mode from v$database;
exit
EOF

Quoting the marker (<<'EOF') stops the shell expanding anything inside, so v$instance needs no escaping. Use an unquoted <<EOF when you want shell variables substituted — and then escape the $ in view names.

4Capture a Value in a Shell Variable

BASH
STATUS=$(sqlplus -s / as sysdba <<'EOF'
set heading off feedback off pagesize 0
select status from v$instance;
exit
EOF
)
echo "Instance status: $STATUS"

heading off feedback off pagesize 0 strips everything except the value, so it's ready to test in an if.

5Fail Properly in Scripts

BASH
sqlplus -s -L / as sysdba <<'EOF'
whenever sqlerror exit sql.sqlcode
whenever oserror exit 9
alter system switch logfile;
exit
EOF
echo "sqlplus exit code: $?"

-L stops SQL*Plus re-prompting for a password if the login fails, and whenever sqlerror makes it exit with a non-zero code on any error — so cron jobs and scripts can tell success from failure.
