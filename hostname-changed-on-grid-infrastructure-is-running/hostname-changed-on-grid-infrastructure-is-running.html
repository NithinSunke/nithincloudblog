Changing the Hostname of an Oracle Restart (Grid Infrastructure) Server

By Sunke Nithin · February 6, 2020   DatabaseOracleRac

Oracle Restart — Grid Infrastructure for a standalone server — records the hostname in its configuration (OLR) when it is set up. Rename the server and the stack stops working. The fix is to deconfigure Oracle Restart, change the name, configure it again and re-register ASM, the listener and the database. Here the server asmdvl01 becomes asmtsl01 (19.3, ASM disk groups CRS, DATA and FRA, database sundev).

This is for a standalone Oracle Restart server. Renaming a node in a RAC cluster is a different procedure: delete the node from the cluster and add it back under the new name.

1Record the Current Configuration

Deconfiguring removes the resource definitions, so write down everything you need to recreate them:

BASH
# as grid / oracle, before anything else
crsctl stat res -t
srvctl config asm
asmcmd spget                                   # ASM spfile location
srvctl config listener
srvctl config database -d sundev              # oracle home, spfile, disk groups
OUTPUT · crsctl stat res -t

2Stop the Database and Listener

BASH
srvctl stop database -d sundev
srvctl stop listener

3Deconfigure Oracle Restart

BASH
# as root
cd /a01/app/grid/product/19.3/grid_home/crs/install
./roothas.sh -deconfig -force
OUTPUT
CLSRSC-332: CRS resources for listeners are still configured
CLSRSC-337: Successfully deconfigured Oracle Restart stack

This only removes the Oracle Restart configuration. The Grid home, the ASM disks and the database files are not touched.

4Change the Hostname

BASH
hostnamectl set-hostname asmtsl01.seo.int
vi /etc/hosts          # replace the old name with the new one

Also update DNS, and any listener.ora / tnsnames.ora entries or local_listener settings that use the old name.

5Configure Oracle Restart Again

BASH
# as root
cd /a01/app/grid/product/19.3/grid_home/crs/install
./roothas.sh
OUTPUT
LOCAL ADD MODE
Creating OCR keys for user 'grid', privgrp 'oinstall'..
Operation successful.
CRS-4664: Node asmtsl01 successfully pinned.
CLSRSC-330: Adding Clusterware entries to file 'oracle-ohasd.service'
CLSRSC-327: Successfully configured Oracle Restart for a standalone server

6Enable CSS and Restart HAS

BASH
# as root: CSS must start automatically, or ASM can't start after a reboot
crsctl modify resource "ora.cssd" -init -attr "AUTO_START=1"
crsctl stop has
crsctl start has
crsctl stat res -t           # ora.cssd and ora.evmd ONLINE

7Add the Listener

BASH
# as grid
srvctl add listener
srvctl start listener

8Add ASM

Register ASM with its disk discovery string and its existing spfile (from asmcmd spget in step 1), then start it:

BASH
# as grid: use the spfile location you saved in step 1
srvctl add asm -d '/dev/oracleasm/disks/*' -p '+CRS/asm/asmparameterfile/registry.253.xxxxxxxxx'
srvctl start asm
asmcmd lsdg                  # all disk groups mounted?

If any disk group isn't mounted, mount it once by hand; ASM remembers it from then on:

SQL
sqlplus / as sysasm
SQL> alter diskgroup data mount;
SQL> alter diskgroup fra mount;
No usable ASM spfile? Start from a pfile
BASH
# only if the old ASM spfile can't be used: start from a pfile ...
cat $ORACLE_HOME/dbs/init+ASM.ora
asm_diskgroups='CRS','DATA','FRA'
asm_diskstring='/dev/oracleasm/disks/*'
asm_power_limit=2
instance_type='asm'

# ... then create a new spfile and register it
sqlplus / as sysasm
SQL> create spfile='+CRS' from pfile;
SQL> exit
asmcmd spget                 # note the new name
srvctl modify asm -p '<spfile path from asmcmd spget>'

9Add and Start the Database

BASH
# as oracle: register the database with its spfile and disk groups
srvctl add database -db sundev \
   -oraclehome /d01/app/oracle/product/19.3/db_home \
   -spfile '+DATA/SUNDEV/PARAMETERFILE/spfile.265.1030560279' \
   -diskgroup DATA,FRA
srvctl start database -db sundev
srvctl status database -db sundev
crsctl stat res -t

With -spfile and -diskgroup set, Oracle Restart starts the database from the right spfile and mounts its disk groups first — no init<SID>.ora pointer file needed. Reboot the server once to confirm that everything comes back on its own.

Steps follow Oracle's procedure for reconfiguring Oracle Restart (My Oracle Support Doc ID 1422517.1). Related: Convert a non-ASM database to ASM.
