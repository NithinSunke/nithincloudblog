Convert a Non-CDB to a PDB in Oracle 19c: A Step-by-Step Guide

By Sunke Nithin · June 9, 2024   DatabaseOracleMigration

Moving a 19c non-container database (non-CDB) into the multitenant architecture means plugging it into a container database (CDB) as a pluggable database (PDB). This post does it manually with the DBMS_PDB package: describe the non-CDB to an XML file, check compatibility, plug it in with NOCOPY, and run noncdb_to_pdb.sql.

read-only→DBMS_PDB.DESCRIBE→shut down→check compatibility→CREATE PLUGGABLE DATABASE→noncdb_to_pdb.sql→open
Test first. Always rehearse this in a non-production environment, and take a full backup of the non-CDB before you start. With NOCOPY, the non-CDB's own data files become the PDB's, so the backup is your way back.

0Prerequisites

  • Version: the non-CDB must be 12.1.0.2 or later — 19c here.
  • Target CDB: an existing CDB on the same version and patch level, the same endianness, a compatible character set, and the same database options installed. Create one with DBCA if you don't have it.
  • Same host / storage: for NOCOPY, the CDB must be able to read the non-CDB's data files where they are. To put the files somewhere else, use COPY or MOVE with FILE_NAME_CONVERT.
  • Privileges: SYSDBA on both databases.
  • Downtime: from the moment the non-CDB goes read-only until the PDB is open — the time to describe, plug in and run noncdb_to_pdb.sql.

1Open the Non-CDB Read-Only

The XML manifest must describe data files that won't change, so restart the non-CDB read-only. Make sure no DDL is running first.

SQL · NON-CDB
sqlplus / as sysdba
SHUTDOWN IMMEDIATE;
STARTUP OPEN READ ONLY;

2Generate the XML Manifest

SQL · NON-CDB
BEGIN
  DBMS_PDB.DESCRIBE(pdb_descr_file => '/home/oracle/noncdb.xml');
END;
/

It takes seconds and records the data files, tablespaces and other metadata the CDB needs.

Shut the non-CDB down

SQL · NON-CDB
SHUTDOWN IMMEDIATE;
Don't open the non-CDB read-write again. The manifest records each data file's checkpoint SCN. If the non-CDB writes to its files after DESCRIBE, the plug-in fails with ORA-65139 — and with NOCOPY, both databases must never have the same files open. Keep it shut down from here on.

3Check Compatibility with the CDB

Connect to the CDB root and run the check:

SQL · CDB
sqlplus / as sysdba
ALTER SESSION SET CONTAINER = CDB$ROOT;
SQL · CDB
SET SERVEROUTPUT ON
DECLARE
  compatible CONSTANT VARCHAR2(3) :=
    CASE DBMS_PDB.CHECK_PLUG_COMPATIBILITY(
      pdb_descr_file => '/home/oracle/noncdb.xml',
      pdb_name       => 'ONCDB')
    WHEN TRUE THEN 'YES'
    ELSE 'NO'
  END;
BEGIN
  DBMS_OUTPUT.PUT_LINE(compatible);
END;
/

If it prints NO, look at the violations:

SQL · CDB
SELECT name, cause, type, message, status
  FROM pdb_plug_in_violations
 WHERE name = 'ONCDB';

Common causes are parameter mismatches or options installed in one database but not the other. Rows of type ERROR must be fixed; WARNING rows usually just need reviewing.

4Plug the Non-CDB In as a PDB

SQL · CDB
ALTER SESSION SET CONTAINER = CDB$ROOT;
CREATE PLUGGABLE DATABASE ONCDB USING '/home/oracle/noncdb.xml' NOCOPY TEMPFILE REUSE;

ONCDB is created and mounted.

ClauseMeaning
NOCOPYUse the data files where they are — fast, no extra space
COPY / MOVECopy or move the files to a new location, with FILE_NAME_CONVERT
TEMPFILE REUSEReuse the existing temp file instead of failing because it exists

5Open the PDB

SQL · CDB
ALTER PLUGGABLE DATABASE ONCDB OPEN;
SHOW PDBS
SELECT name, cause, message FROM pdb_plug_in_violations WHERE con_id = 4;

The PDB opens in restricted mode with a warning. That's expected: its data dictionary is still a non-CDB's, and the violation tells you to run noncdb_to_pdb.sql.

6Run noncdb_to_pdb.sql

Run the script inside the new PDB:

SQL · CDB
ALTER SESSION SET CONTAINER = ONCDB;
@?/rdbms/admin/noncdb_to_pdb.sql

The script can run for a while — it rewrites the dictionary to use the CDB's shared objects.

When it finishes, restart the PDB so it opens unrestricted, and save its state so it opens with the CDB:

SQL · CDB
ALTER SESSION SET CONTAINER = CDB$ROOT;
ALTER PLUGGABLE DATABASE ONCDB CLOSE IMMEDIATE;
ALTER PLUGGABLE DATABASE ONCDB OPEN;
ALTER PLUGGABLE DATABASE ONCDB SAVE STATE;

SHOW PDBS
SELECT name, open_mode FROM v$pdbs;

SHOW PDBS should now show ONCDB as READ WRITE with RESTRICTED = NO, and pdb_plug_in_violations should have no unresolved errors.

7Post-Conversion Tasks

Update TNS

The PDB registers a service with its own name. Add an entry in $ORACLE_HOME/network/admin/tnsnames.ora (add your db_domain to the service name if you use one):

TNSNAMES.ORA
ONCDB =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = <hostname>)(PORT = 1521))
    (CONNECT_DATA =
      (SERVER = DEDICATED)
      (SERVICE_NAME = ONCDB)
    )
  )

Back up the CDB

RMAN
rman target /
BACKUP DATABASE PLUS ARCHIVELOG;

Pre-conversion backups of the non-CDB can't be restored into the PDB, so take a fresh backup straight away.

8Retire the Old Non-CDB

Don't delete the data files. With NOCOPY, the non-CDB's data files are the PDB's now. Retiring the old database only means removing its instance configuration: the /etc/oratab entry, its spfile/pfile and password file, and any listener or service entries. Never use DROP DATABASE on it.

Pros and Cons

ProsCons
Centralised management — many PDBs in one CDBPlanning effort — compatibility checks and testing
Resource efficiency — shared memory and background processesResource contention — PDBs share the CDB's resources unless you use Resource Manager
Simpler patching and upgrades — once per CDBDowntime — the non-CDB is unavailable during the conversion
Mobility — unplug and plug PDBs between CDBs
Multitenant is also the only architecture from 21c onward — non-CDBs are no longer supported — so this conversion is a prerequisite for any future upgrade.

Troubleshooting

ProblemFix
ORA-65139: mismatch between XML metadata file and data fileThe data files changed after DESCRIBE. Compare SELECT file#, name, checkpoint_change# FROM v$datafile_header; with the <fcpsb> values in the XML, then regenerate the XML with the non-CDB read-only and keep it shut down afterwards.
File paths differ on the CDB hostUse COPY or MOVE with FILE_NAME_CONVERT, or SOURCE_FILE_NAME_CONVERT to tell the CDB where the files are.
Permission errors on the XML or data fileschown oracle:oinstall /home/oracle/noncdb.xml and chmod 660 /home/oracle/noncdb.xml
PDB stays RESTRICTEDCheck pdb_plug_in_violations for unresolved errors — often a missing option, or noncdb_to_pdb.sql not run or not finished.
