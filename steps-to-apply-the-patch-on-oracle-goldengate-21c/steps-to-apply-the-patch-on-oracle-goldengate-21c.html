Steps to Apply a Patch on Oracle GoldenGate 21c

By Sunke Nithin · June 25, 2024   ReplicationOracleGoldengate

GoldenGate 21c Microservices is patched with OPatch, like an Oracle Database home. In this post we take a deployment from the base release 21.3 to 21.14 with the GoldenGate Release Update patch 36661469: update OPatch, stop the processes and the Service Manager, check for conflicts, apply, and bring everything back up.

stage patch→update OPatch→stop processes→stop service→conflict check→opatch apply→start & verify
ItemValue in this lab
GoldenGate home/u01/app/ogg/gg_home
Deploymentprodogg (Admin Service on port 7001)
Version before → after21.3.0.0.0 → 21.14.0.0.1
Patchp36661469_21140000GGRU_Linux-x86-64.zip
OPatchp6880880_122010_Linux-x86-64_2.zip (12.2.0.1.42)

1Check the Current Version

The Administration Service banner shows the running version, 21.3.0.0.0:

2Stage the Patch and the Latest OPatch

Download the GoldenGate patch and the latest OPatch (patch 6880880, the 12.2.0.1.x release) from My Oracle Support, read the patch README, and copy both to the server:

BASH · ORACLE
cd /u01/soft
unzip -q p36661469_21140000GGRU_Linux-x86-64.zip
unzip -q p6880880_122010_Linux-x86-64_2.zip

3Update OPatch in the GoldenGate Home

BASH · ORACLE
cd /u01/app/ogg/gg_home
mv OPatch OPatch_bkp
cp -Rv /u01/soft/OPatch .

export ORACLE_HOME=/u01/app/ogg/gg_home
$ORACLE_HOME/OPatch/opatch version

4Stop the Replication Processes

Stop everything running from this home. A sensible order:

  1. Replicats
  2. Distribution / receiver paths (if you use them)
  3. Extracts
ADMIN CLIENT
STOP REPLICAT *
STOP EXTRACT *
INFO ALL
Patching only takes a few minutes, and an Integrated Extract restarts from its checkpoint, so nothing is lost. Make sure the database's redo/archive logs since the Extract stopped are still available when it restarts.

5Stop the Service Manager

As root, stop the systemd service. That stops the Service Manager and every deployment service (Admin, Distribution, Receiver and Performance Metrics):

BASH · ROOT
systemctl stop OracleGoldenGate
systemctl status OracleGoldenGate

Confirm nothing is still running from the home: ps -ef | grep gg_home should return nothing.

6Check for Patch Conflicts

BASH · ORACLE
cd /u01/soft/36661469
export ORACLE_HOME=/u01/app/ogg/gg_home
$ORACLE_HOME/OPatch/opatch prereq CheckConflictAgainstOHWithDetail -ph .

7Apply the Patch

BASH · ORACLE
cd /u01/soft/36661469
$ORACLE_HOME/OPatch/opatch apply
OUTPUT
Oracle Home       : /u01/app/ogg/gg_home
Central Inventory : /u01/app/oraInventory
OPatch version    : 12.2.0.1.42
...
Applying interim patch '36661469' to OH '/u01/app/ogg/gg_home'

Patching component oracle.oggcore.services.ora21c, 21.1.0.0.0...
Patch 36661469 successfully applied.

OPatch succeeded.

Answer y to both prompts. Confirm with $ORACLE_HOME/OPatch/opatch lspatches.

8Start the Service Manager

BASH · ROOT
systemctl start OracleGoldenGate
systemctl status OracleGoldenGate
OUTPUT

9Restart Extract and Replicat

Start them in the reverse order — Extract first, then any paths, then Replicat. The Admin Client now reports 21.14:

The console banner now shows 21.14.0.0.1, and both processes are running.

Rollback: if something goes wrong, stop the service again and run $ORACLE_HOME/OPatch/opatch rollback -id 36661469. Keep the OPatch_bkp directory until you're happy with the patched home.
