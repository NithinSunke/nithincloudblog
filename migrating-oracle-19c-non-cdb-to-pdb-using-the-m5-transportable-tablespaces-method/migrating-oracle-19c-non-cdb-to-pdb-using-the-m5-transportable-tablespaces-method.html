Migrating Oracle 19c Non-CDB to PDB Using the M5 Transportable Tablespaces Method

By Sunke Nithin · August 20, 2025   DatabaseOracleMigration

M5 is Oracle's current cross-platform transportable tablespace procedure (MOS Doc ID 2999157.1). It moves data files with RMAN — a level 0 backup and then incremental level 1 backups while the source stays online — and finishes with a Full Transportable Export/Import of the metadata. Downtime is just the last incremental plus the metadata import, and it works across platforms and endian formats. Here I use it to move a 19c non-CDB into a PDB.

Background: Daniel Overby Hansen's Cross Platform Migration – Transportable Tablespaces to the Extreme.

3List the Tablespaces to Transport

Everything except SYSTEM, SYSAUX, undo and temporary tablespaces:

SQL
SELECT LISTAGG(tablespace_name, ',') WITHIN GROUP (ORDER BY tablespace_name) AS tablespaces
  FROM dba_tablespaces
 WHERE tablespace_name NOT IN ('SYSTEM','SYSAUX')
   AND contents = 'PERMANENT';

Put the list in cmd/dbmig_ts_list.txt:

4Create an Empty Target PDB

SQL
CREATE PLUGGABLE DATABASE ONCDB ADMIN USER pdb_admin IDENTIFIED BY "<password>";
ALTER PLUGGABLE DATABASE ONCDB OPEN;
ALTER PLUGGABLE DATABASE ONCDB SAVE STATE;

5Level 0 Backup and Restore

BASH
cd /mnt/migration/M5
./dbmig_driver_m5.sh L0

This runs an RMAN level 0 backup of the listed tablespaces and generates a restore script for the target:

On the target (NFS mounted), restore into the PDB:

BASH
rman target sys@ONCDB cmdfile=cmd/restore_L0_ONCDB_250820092032.cmd

6Level 1 Incrementals

Repeat as often as you like — each one shrinks the final outage:

BASH
./dbmig_driver_m5.sh L1

# on the target
rman target sys@ONCDB cmdfile=cmd/restore_L1_ONCDB_250820112239.cmd

Check the restore log after each run.

7Outage: Final Incremental and Export

Stop the applications. L1F makes the tablespaces read only, takes the final level 1 backup, and runs the full transportable export (expdp FULL=Y TRANSPORTABLE=ALWAYS):

BASH
./dbmig_driver_m5.sh L1F

Then restore the final incremental on the target:

BASH
rman target sys@ONCDB cmdfile=cmd/restore_L1F_ONCDB_250820113451.cmd

You can shut the source down now, or leave it read only as a fallback.

8Import the Metadata

Edit the variables at the top of impdp.sh; run it without arguments to see the syntax:

Run it in test mode first — it only generates the parameter file, so you can check the data file list:

BASH
./impdp.sh exp_ONCDB_250820202205.dmp log/restore_L1F_ONCDB_250820202205.log test N

Then in run mode. It creates a guaranteed restore point first, then does the full transportable import with TRANSPORT_DATAFILES:

BASH
./impdp.sh exp_ONCDB_250820202205.dmp log/restore_L1F_ONCDB_250820202205.log run N
The import finished "with 12 errors". Read the log: errors like ORA-31684: TEMP / UNDOTBS1 already exists are expected because the PDB already has those. Anything else needs investigating before you go live.

9Validate

SQL
@?/rdbms/admin/utlrp.sql
SELECT tablespace_name, status FROM dba_tablespaces;
SELECT owner, object_type, COUNT(*) FROM dba_objects
 WHERE oracle_maintained = 'N' GROUP BY owner, object_type ORDER BY 1,2;

Compare object and row counts with the source. Then set the tablespaces read write if they aren't already, back up the CDB, drop the restore point, remove the migration backups, and give the applications the PDB's connect string.

Pros and Cons

ProsCons
Short outage — only the final incremental and metadata importMore moving parts: NFS (or file copies), properties, several scripts
Data files are moved, not re-exported — scales to very large databasesNeeds a recent 19c RU and the Data Pump bundle patch on the target; check the MOS note for current requirements
Cross-platform and cross-endian (e.g. SPARC to Exadata)Once the tablespaces are plugged in, fallback is to the source, so keep it
Supports encrypted tablespaces, multisection backups and parallelismTime zone file mismatches (TSTZ data) and evolved types need fixing first

Best Practices and Troubleshooting

  • Test the import with TTS_CLOSURE_CHECK=TEST_MODE / TRANSPORTABLE=KEEP_READ_ONLY on a copy.
  • Watch progress in V$SESSION_LONGOPS and keep AWR snapshots.
  • ORA-39001 / ORA-31640 — check directory object paths and permissions.
  • Missing archived logs during a backup — restore them and rerun.
  • Time zone mismatch — bring the target's time zone file to at least the source's version.
